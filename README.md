# 设计知识库

这里沉淀我们讨论后认为值得长期保留的设计知识：概念、本质、原则、规范、风格、审美和取舍方法。通过可操作的演示观察效果，再用简短文字解释原因和边界。内容覆盖不同产品、平台和使用场景，不以后台界面为默认背景。

文章、链接和本地文件都是讨论的临时输入。长期保留的是我们形成的理解，以及能够用于其他项目的判断方法。

## 放置材料

把需要讨论的本地文件放进 [inbox](inbox/)，也可以直接在聊天里提供链接、文字或图片。文件放入目录不代表已经处理，也不代表其中的观点已被采纳。

`inbox` 可以随时由你手动清空，包括其中已经讨论过的文件。AI 不会默认归档、移动或删除材料。这个目录的内容和 `.tmp` 已配置为不纳入后续 Git 版本管理，`inbox/.gitkeep` 仅用于保留空目录。

## 讨论和沉淀

1. 你提出问题，或指出要读的材料；例如“看看 inbox 里的这篇文章，和我讨论哪些说法值得留下”。
2. AI 提取值得讨论的观点。能直接观察的视觉和交互问题，优先用演示、对照或操作来解释，再区分事实、标准、经验、风格和推论，讨论条件与取舍。
3. 候选观点先留在聊天里。你明确要求沉淀，或讨论中明确达成共识后，AI 将结论及配套演示保存到 [knowledge](knowledge/README.md) 的主题目录，并更新阅读入口；概念和方法类内容可以配图解或案例。
4. 后来有新的理解时，直接修订对应知识条目，让正文表达当前结论。重要的改变可以简短说明原因，不单独维护一套决策档案。

知识条目应当脱离原文也能读懂。理解结论所必需的背景、例子、图示和演示代码应成为长期知识的一部分；删除临时材料后，知识仍然完整可用。

## 阅读和演示

从 [知识目录](knowledge/README.md) 找到主题，先看演示，再读原因与适用条件。一个主题对应一个能独立讨论的问题，可以包含几个紧密相关的知识点，以及一个或多个演示，不要求知识点和 HTML 文件一一对应。

主题目录先平铺。目录页按“概念与判断、视觉与信息组织、操作与反馈、流程与任务、时间与动效、风格与设计系统”提供导航。同一主题可以出现在多个入口，内容只维护一份；组件可以成为补充查找入口。

简单主题由 README.md 和 demo.html 组成，复杂时再拆分演示、样式和脚本。可观察的视觉和交互主题默认配运行演示；概念和方法类主题可以使用图解或案例。文字保留理由与边界，演示帮助观察和比较。

演示默认采用 HTML、CSS 和原生 JavaScript，优先无需构建的本地页面；需要预览服务或额外依赖时，在主题说明中写清运行方式。根据真实维护需求再引入框架和工具。

## 保持轻量

不建立文章档案、来源关系图、来源编号或逐篇阅读记录，也不为每篇输入生成永久摘要。来源仅在帮助理解或核查具体结论时随正文保留，例如标准条款附必要的版本和链接；普通笔记不要求填写来源字段。

每个主题围绕一个值得复用的问题展开，说明结论、理由、适用条件和必要的例子。内容短时用几段话即可，结构不必套满。分类用于找内容，不预建空主题或复杂的分类系统。

## 用于其他项目

在其他项目里，根据实际使用者、任务和约束选取相关知识，形成该项目自己的设计判断。具体页面、组件代码和项目特有的参数留在对应项目中。

当应用知识的流程稳定后，可以把它封装为 skill，并附带需要的知识文档。知识正文始终在这里维护；skill 负责指导如何选取和应用它们。

AI 的具体工作约定见 [协作规则](AGENTS.md)。
