# 批量与模式

批量操作把主语从一个对象换成一堆。界面因此多出两个问题：**选的是哪些**、**这些都能做吗**。

范围怎么写（摘要、按钮自带范围、跨页给哪一批）在[入口与回执](../入口与回执/README.md)；这里谈形态、集合和模式。

## 先看演示

[批量与模式](批量与模式.html)（双击打开，不需要本地服务）

同一批 8 个订单，5 个待发货、3 个待付款。切换四种形态；再试「先筛选、先勾选，然后进入模式」。

观察重点：

1. 「常显·可用」：不勾选点发货，先弹「请先勾选」；勾了含待付款的订单，得到「成功 N 条、跳过 M 条」。
2. 「常显·置灰」：混了待付款，按钮灰掉、旁边写出原因，但没说是哪一条。
3. 「进入模式」：列表只剩可发货的行；筛选还在，但模式内不能改。
4. 先勾两条（其中一条待付款）再进模式：待付款那条被移出选择，横幅写明移出了几条。
5. 把筛选切到「待付款」再进模式：空列表 + 出路，而不是一张「没有数据」的表。
6. 全选范围切到「全部匹配」，再全选：已选 8 条，翻页后数字还在。
7. 退出模式：筛选恢复、选择清空，回到进入前的列表。

## 一、形态：可见性和步数是一根轴的两端

| 形态 | 可见性 | 步数 | 它什么时候回答问题 |
|---|---|---|---|
| 常显·可用 | 全部可见 | 2 | 点了才知道（没选时先弹「请先勾选」，其实什么也没承诺） |
| 常显·置灰 | 全部可见 | 2 + 自己找 | 执行前，但只说「有几条不行」 |
| 多选触发 | 勾选后才出现 | 2 | 执行后 |
| 进入模式 | 进入后全部可见 | 3 | 进入时 |

形态只决定可见性和步数。**防错是另一个维度**，四种形态都能配不同的防错手段——下一节。

## 二、安全性来自集合，不来自按钮

选中里混了不能做的行时，处理手段从差到好：

| 档 | 做法 | 代价 |
|---|---|---|
| 1 | 允许选，执行后**报错** | 事前不可预知，事后不知道哪几条失败 |
| 2 | 允许选，**部分成功 + 报告** | 能推进，但要求用户读结果 |
| 3 | **置灰 + 原因** | 挡住，但只说数量；多个批量操作时按钮会一闪一闪 |
| 4 | **不能选**（勾选框禁用或不出现） | 把问题挪到选择那一刻，但用户仍不知道为什么 |
| 5 | **换集合**（模式里只显示可操作的行，或拆成两张表） | 全选变安全，不需要任何防错 |

第 5 档是模式真正的价值：**不是「多一步换掌控感」，是它能把集合换掉**。列表只剩待发货的 5 条之后，「全选」不再有歧义，置灰和失败提示都可以不存在。

**部分成功的边界。** 第 2 档只在操作可重试、且失败不改变对象其他状态时成立。破坏性操作（删除、清空）不该部分成功——应该先收敛集合，再一次性做。

## 三、全选：列举、谓词、谓词 + 排除

勾一条是**列举**：这个、这个。用户在屏幕上看得见，能核对。
点全选是**规则**：「所有符合当前条件的」。用户没看过全部，无法核对。

所以全选的复杂度不在界面，在「选中」这个状态有三种表示：

| 表示 | 系统存什么 | 用户能核对吗 | 集合会变吗 |
|---|---|---|---|
| 列举 | ID 列表 | 能 | 不会（对象被删会失效） |
| 规则 | 谓词（筛选条件） | 不能，只能核对条件本身 | 会（执行时可能多、可能少） |
| 规则 + 例外 | 谓词 + 排除集 | 部分（例外那几条能核对） | 同规则 |

「跨页勾选」是列举的麻烦版本——要记住几十个 ID，但翻回去还能核对；「全部匹配」是规则；「全选之后取消一条」是第三种，既不是列举也不是规则。

**它逼出第三种表示。** 用户的心理是「全部，除了 A-1042」，只实现其中一种，这一条就会丢：只存条件，取消的那条会回来；只存 ID，新增的那条不会进来。最小可用的模型是**谓词 + 排除集**。

### 三个问题

1. **范围**：哪个「全部」？本页 / 匹配的全部。还有第三个词经常混进来——「已加载」，那是实现泄漏：用户不知道加载了多少，也不知道滚到底还有没有，别用它当范围。
2. **时点**：「全部」是在点下去那一刻定，还是执行那一刻定？中间集合会变：新增的、别人改的、被删的。
3. **表示**：存 ID 还是存谓词。这个决定上面两个问题能不能被回答——存 ID 就答不了「现在多了几条」，存谓词就答不了「我当初选的是哪 128 条」。

### 四个落点

1. **默认可核对**：全选默认选本页，再显式升级成「选择全部 128 条」。这一步不是多此一举，它把「不可核对」变成用户主动接受的承诺。
2. **用条件重述**：数字只回答「多少」，条件才回答「哪些」。「所有待发货的订单」比「128 条」更有意义——条件是他自己下的。
3. **执行前重新报数**：把漂移摆到台面上（「现在有 130 条匹配，其中 2 条是刚刚新增的」）。这是唯一能核对漂移的机会。
4. **结果里带范围**：「处理了 128 条（筛选：待发货）」，不是「操作完成」。

接口形状跟着换：接 `{ query, exclude }`，不是 `{ ids }`；后端在执行时求值，返回实际处理的条数。用 `{ ids }` 接「全部匹配」，前端就得先拉一遍全量。

**不提供「查看这 128 条」。** 它和当前列表并列，是两个同等重要的真相，用户要自己记哪个是哪个；而它换来的核对能力，几乎没人会用。

## 四、模式：替换而非并列

模式里的列表**不是新列表**，是同一个列表换了集合——位置、列、行样式都没变，只是行少了。任何时刻只有一个「当前」。

这和「查看全部」的列表不是一回事：那个是并列的第二个真相，这个是替换。

### 横幅要回答「我原来那些去哪了」

列表变短，用户第一反应不是「这是筛选」，是「我的数据呢」。所以只写「可发货 5 条」不够，它回答了「现在有什么」，没回答「少了什么」。三段式：

> **当前筛选的 8 条中，5 条可发货（3 条不在本模式）** · 筛选：全部（模式内不可改） · 退出模式

一句话同时证明三件事：数据还在（8 条）、只收了 3 条、收的理由是可发货。

### 进入 = 求交集

- **筛选留着，但锁住。** 留着是因为它是用户的意图；锁住是因为模式的价值是集合稳定——模式里还能改筛选，「已选」和「看到的」立刻错位。
- **选择做一次求交集**，把差集说出来（「1 条不可发货，已移出选择」）。不静默保留（看不见的选中就是[假回执](../藏起来的代价/README.md)），也不静默清空（用户白选）。
- **交集为空给一条出路**：「当前筛选（待付款）下没有可发货的订单 · 退出模式或改筛选」，而不是一张空白表。

### 退出

筛选恢复、选择清空。筛选是意图，值得恢复；选择是短命状态，恢复它反而制造「看不见的选中」。

### 能被理解的三个前提

1. **用户主动进入**——他点了一个明确的按钮，集合变小是预期的。这也是「按钮触发」比「自动进入」好的原因。
2. **随时能退出，且回到原样**——这是「没丢」的最终证明。
3. **变的是内容，不是容器**——同一张表、同样的列、同样的位置。一旦模式换了布局、加了新列，它就真成了「另一个列表」。

三条缺哪条，用户都会问「我在哪」。

## 五、什么时候用模式

**判据：换集合的收益要大于「用户重新确认我在哪」的成本。** 收益只有一种——让「全选」变安全。

换集合换不来这个，模式就只剩成本。所以：

- 用户进来时已经知道自己在做批量（通讯录管理、待发货处理）→ 模式成立。
- 只是偶尔顺手删几条 → 多选触发就够。

## 为什么这样判断

- 列举 / 谓词 / 谓词 + 排除是表示问题，可以从「全选后取消一条」推出来：两种纯表示都答不了这一种操作。
- 五档排序是推论加演示观察：前两档的失败在演示里能直接看到（部分成功、0 条成功），后三档是「把问题往前挪」的三种位置。
- 部分成功的边界来自「失败会不会改变对象的其他状态」，这是操作的性质，不是界面的选择。
- 模式的三段式横幅来自一个推理：用户会问「我原来的数据去哪了」，而不是「这是什么筛选」。
- 演示没有做用户测试；8 条订单、2 页分页都是演示值。

## 适用条件和取舍

- **权限**：部分行无权限时，用「不能选」还是「允许选但报错」，取决于能否暴露对象存在（安全要求可能要求统一表现）。
- **移动端**：批量模式少见，多选触发更常见；触摸端的分页和全选范围提示更重要。
- **破坏性操作**：用确认框还是撤销窗口，见[拆组件](../拆组件/README.md)的判据 2；部分成功不适用于删除。
- **范围怎么写**在[入口与回执](../入口与回执/README.md)；结果怎么交代在[受理与交代](../受理与交代/README.md)。本文只谈形态、集合和模式。
- **演示不测人**：没有测完成时间、误操作率、用户对模式的理解程度。

## 例子

- **订单发货**（演示）：四种形态、两种全选范围、模式进出。
- **邮箱**：默认选本页，再升级成「选择全部 N 条匹配」；全选后取消一条就是谓词 + 排除。
- **通讯录管理**：模式成立，因为用户点进来就是为了批量。
- **偶尔删几条**：多选触发，不配模式。

## 还没定

- 全选默认「本页」还是「全部匹配」，在多选场景下的取舍没有数据。
- 「执行前重新报数」是每次都报，还是只在条件型集合时报。
- 部分成功的结果怎么呈现（列表、汇总、可重试入口），没有展开。
- 模式内其他操作要不要禁用，没有讨论。
- 移动端的批量形态（长按进入选择、底部操作条）没有做。
