# 当前位置与返回路径

面包屑展示层级归属，返回操作通常遵循访问历史，菜单高亮标识当前导航位置。它们有时来自不同数据源。用户从工作台或客户详情都能打开同一订单时，可以看到相同的订单归属，而返回不同的入口。

## 归属信息从哪里来

有清楚归属的实体可采用稳定的对象层级，让人始终知道这份订单属于哪一类。纯功能页可以按路由组织。一个对象确有多个父分类时，需要项目选择有意义的展示路径。随入口生成的路径便于和菜单对应，但同一对象可能显示不同归属。稳定的对象路径需要可靠的父级数据，不能从访问历史直接猜出。

菜单只到功能级，而面包屑末级是对象名，这是正常差异。“全部订单”和“我的订单”可以是同一对象列表的两种筛选视图。真正需要改的是可点击的祖先项通向无权限或不存在的页面、同一目标在导航改名后仍显示旧名等问题。仅作分类说明的节点可以是文本，需让人分得清它能否点击。

窄屏可折叠中间层并提供展开入口，或显示明确的横向可滑动线索。换行保留内容但增加高度。静默移除中间层会使剩余路径看起来像完整层级。首页已有稳定入口、当前页已有可见标题时，可以减少重复。路径异常长时也应检查是否把过滤条件当成了分类。

## 顶栏中的对象、位置和操作

移动端常在顶栏提供返回、当前对象名称和页面操作。首页还没有具体对象时，中间位置可用于搜索或分段。已有当前对象时，应能在滚动后仍辨认其名称，例如由面包屑承担，或在大标题滚出时将名称移交给固定顶栏。如果对象信息从视野中消失，又需要据此操作，就应恢复它的位置。仅针对当前列表的搜索宜靠近列表，全局搜索可在顶栏表明较大的搜索范围。

分段控件如果用来定位同一对象的各段，用户滚动后其当前项也应与实际可见内容一致。桌面布局可由侧栏标识模块、面包屑标识路径、标题标识对象，不必为移动端的中间标题保留一个空位置。跨产品引用“导航栏”“标签栏”时，写明它承担版块切换、页内分段还是返回上一级。同名组件的位置和作用可以不同。视口、文案及操作后果决定哪些次要项可收进菜单，保留可到达的退出与必要下一步。

顶栏滚动后出现边线或阴影，可以表达内容从其下方经过。透明顶栏叠在图片上时，检查更换明暗图片后名称、返回和操作能否辨认。可为顶栏提供衬底或滚动后的实色背景。
