# 视觉风格与设计参数

同一个视觉参数可以承担不同作用。字体大小影响能否阅读，也参与层级表达。颜色既可体现品牌，也可能区分操作状态。判断一项规范时，应具体说明更改它会使哪项信息难读、哪个目标难辨，或只是让产品呈现另一种性格。品牌一旦选定，可以在该产品内要求一致。别的产品有权作出另一种选择。

## 选择和延续视觉语言

颜色、圆角、阴影和字重可以分别调整。比较两种形式时尽量保留相同内容和行为，才知道改变的是哪一种关系。一个有规律的图案可以改变配色而保留疏密关系，也可以保留圆点和网格却改变大小的分布规则。在同一规则下换一组输入，还可以产生同系列的另一个结果。放到品牌识别上，颜色本身又可能承担身份含义。是否改变了设计意图，要看这个特征在当前任务中起什么作用。

字阶的层级取决于实际对比。标题只比正文稍大，可能仍像强调过的正文。拉大差距有助于区分，也增加占高。空间紧的列表与展示页不必采用同一组具体字号。某种形式在多处重复并相互呼应，可以形成一致的视觉语言。推广到整个系统前应检查该形式本身是否适合这些场景，否则也会反复放大等待或干扰。日常工具与希望被记住的首次展示，可以为显著的风格投入不同成本。

## 状态色与可验证的规则

悬停提亮或加深属于产品约定。本库采用的可选默认是悬停提亮。白字所在的背景变浅时，对比度会下降，需要检查基准色。已有一致加深约定的项目可以延续自己的方向。一套派生公式能减少逐项维护，但高饱和颜色可能在某个通道到达上限，实际变化方向或文字对比随之改变。应检查正常、悬停、按下等实际背景上的文字及必要的状态线索。用具名的基础值或语义值管理已选方案，如“次要正文色”，方便在同一产品中统一调整。

当背景是开放输入时，给黑、白两张静态样稿不足以决定中间色怎么处理。以不透明纯色背景、纯黑或纯白文字为例，按 WCAG 相对亮度公式分别计算两个对比度，取较高者。在最不利的背景相对亮度约 0.179 处，较高者仍约为 4.58∶1。若文字改为 #333333 和 #F5F5F5，背景相对亮度约在 0.164 至 0.324 之间时，两种文字都可能达不到 4.5∶1。纯红背景上白字约 4.00∶1、黑字约 5.25∶1，只取 RGB 通道算术平均值会在此选错。WCAG 2.2 AA 的普通文本门槛是 4.5∶1，大号文本为 3∶1，另有例外。比较门槛时使用未取整结果。照片、渐变、透明叠加及实际文字区域需要另行核对。[WCAG 文本对比度及其计算方法](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)

输入只有少数已知取值时，逐项给出结果可以完整表达规范。输入开放且规则可推导时，需要传递推导方法及其适用输入，并验证边界。若目标是“像这个品牌”而尚无可检验的规则，可收窄内容范围，或提供代表性选择、反例及项目在意的差异，再用新内容检查近似效果。别人的参数可以作为起点，其适用性仍取决于本项目的输入和产出。

## 字体回退

浏览器按字体族顺序、字符或字符簇的字形覆盖等条件选择字体。同一段中西文可由不同字体绘制。把西文字体置于覆盖拉丁字符的中文字体之前，能改变数字和西文字形。省略字体声明时结果取决于浏览器样式和用户配置。希望采用系统界面字体时，可显式使用 `system-ui`。指定品牌字体及回退列表能提高特定环境的表现一致性，也会增加字体加载与跨平台维护成本。用目标文字和设备核对字形、换行及加载后的变化。[CSS 字体匹配](https://www.w3.org/TR/css-fonts-4/#font-matching-algorithm)
