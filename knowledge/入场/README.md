# 入场

入场不是「我来了」，是「我是什么、你能对我做什么」——它是示能的首次兑现：用户看完之后，应该知道能动手。入场同时也是一条注意力交接链，顺序按用户的疑问排，不按内容的组织顺序排。

本条以判断和验收方法为主，没有独立演示。想对照三版入场的实现，可看[卡片堆叠演示](../卡片堆叠/demo.html)第二部分：同一叠卡的入场三版（v1 封面飘入、v2 封面加生成文字、v3 氛围散开加文字揭开；前两版被否，第三版上线）。

## 我们的理解

### 一、入场要兑换

每一道工序（每个动作、每一拍）都要兑换成下面三类之一，否则就是在主路径上收税：

1. **信息**：真实等待（还要多久）、结构（从哪来、去哪）、示能（能做什么）。
2. **演员与呼应**：之后要响应用户的对象首次亮相，送达反馈连续性。
3. **氛围**：纯体验，仅当对象不需要被学习（低频、一次性活动）。

关键是信息的成色：**须真实，且与当下决策相关。** v2 卡在边界上——它声称有信息（「正在生成」），但信息是假的（没有真在生成），且与决策无关（知道与否不改变你怎么用这叠卡）。所以它不是「没信息」，是用假信息兑换工序。

可操作的判据：**删掉这道工序，用户失去什么？**

- 不知道还要等多久 → 真实等待，保留；
- 不知道这东西能干什么 → 示能，保留；
- 少了「它会回应我」 → 演员线，保留；
- 少了一段好看 → 只在对象不需要被学习时保留。

### 二、承诺要接力：三条线

入场要送达的承诺有两层：**可操作性**（知道能操作）与**反馈连续性**（知道操作后它会回应）。接力线有三条，跨元素时至少接上一条：

| 线 | 接的是 | 送达 |
|---|---|---|
| 演员线 | 入场演员＝之后响应的对象 | 反馈连续性 |
| 空间线 | 入场在目标位置发生或在目标位置交接 | 可操作性 |
| 动作线 | 入场动作预告交互动作 | 可操作性 |

- v3 接的是演员线＋空间线：氛围元素入场从下向上，之后左右滑动时它们左右响应——方向变了，动作线没接，靠演员线完成承诺。
- 12 周年时钟接动作线：入场先演「一圈刻度」，之后左右拨动的就是钟表本身。
- 反例：左上角 logo 闪一下、页面下方卡堆淡入——三线全断，入场是装饰；对象需要被学习时，用户不知道该干什么。
- 反向风险：强行「同一批元素」会逼装饰元素承担它承担不了的示能。v3 的氛围元素只能「响应」、不能「被操作」——同一批元素送达的是反馈连续性，不是可操作性；可操作性仍由对象本身（可滑动、可揭开）承担。

### 三、顺序按疑问排

入场是一条注意力交接链，顺序按用户此刻的疑问排：**这是什么 → 我该看哪里 → 我能做什么**；不按内容的组织顺序排。

材料对照：

- v1 只回答了「这是什么」（一张封面），「看哪里」「能做什么」都没答。
- v2 答错题：补了一个没人问的「它怎么来的」（而且是假答案），「能做什么」仍然空着。它不是多了一拍，是答错了题。
- v3 与 12 周年时钟三拍齐全。
- 2022 年评委卡生成把第二拍换成「它怎么来的」（乐高组装式分步生成：背景→卡片→主要信息→次要信息→创意图片→完成）——因为过程本身有叙事价值：你的投票如何变成你的卡。**疑问链不是死模板，是场景函数**：过程型入场的第二拍就是「怎么来的」。

配套判断：

- **一拍一个焦点**（一组错落算一个焦点）。两个元素同时抢注意力，用户会漏一个。
- **最后一拍＝交互的第一帧**：入场的收尾必须落在可操作状态上，与[接缝](../接缝/README.md)的规则一致。
- **先给最重要的，不等于把内容顺序倒过来**：v3 只是先把注意力交给关键的那张（最后一张卡），之后内容仍按卡堆自己的顺序揭示——注意力顺序与内容顺序解耦。入场是预告片，不是目录。
- **结构先于内容管的是同一拍内部**（容器先到位、信息再落上去，继承自[动效的层级](../动效的层级/README.md)）；跨拍的路线由疑问定。不承载疑问的装饰：并进某一拍（不抢焦点）、放最后、或删。

**代价**：先给重点，失去揭示的快感。当场「揭示」本身是价值（过程型入场）时，按过程走——与第一节的叙事判据是同一条线。

### 四、示能送达的验收

先拆两个验收项：**可操作性**（空间线／动作线）与**反馈连续性**（演员线），别混成「效果好」。四个便宜检查，按成本排：

1. **砍半测试**（作者自查，不用找人）：把入场砍掉一半，从中间直接进可操作状态——承诺还在吗？在，说明被砍的半截是装饰，用第一节的判据处理；不在，说明那半截在承重。
2. **空手接管**（自己＋一个没看过设计的人）：入场结束不给任何提示，看第一下会不会去滑、去翻。犹豫、找按钮、问「怎么翻」＝没送达。自己知道设计，自己只能当最小检查。
3. **去提示测试**：关掉所有常驻提示（「滑动查看」、箭头、文字 hint），只留入场——还能接管吗？不能，说明提示在替入场工作，入场没承担示能。
4. **最后一帧＋三问**：截入场的最后一帧，依次问——这是什么？我该看哪里？我能做什么？第三问答不出来＝示能没送达。这一项与顺序的疑问链同构：顺序按三问排，验收就按三问问。

复述问题：入场后问「接下来你会怎么做？」——回答里出现「滑／翻／点开」＝送达；出现「这是啥／要等吗」＝没送达。

**诚实的不对称**：这些检查的否定结论可靠——发现「没送达」就是发现问题；肯定结论弱——一个人一次通过不等于普遍成立。它们是一人观察／小样检查，不是用户测试；要更强的证据得多人观察，属产品投入决定，不是默认要求。

## 为什么这样判断

- 工序兑换来自 v1／v2 的对照：v2 补了工序、承诺没变，被否——判据不是「多了几步」，是「答没答对题」。
- 三条接力线是从 v3、12 周年时钟与反例里拆出来的；v3 的方向从上下变左右，说明动作线不是唯一依靠——演员线单独也能送达。
- 疑问链顺序是从四次入场（v1／v2／v3／2022）的成败对照里归纳的；v2 用「答错题」解释比「两步多余」更精确。
- 验收检查是低成本自查方法，不是用户研究；其可靠方向是不对称的（否定可靠）。

## 适用条件和取舍

- 工序兑换适用于任何有主路径的入场；纯体验活动（对象不需要被学习）可放宽到氛围兑换。
- 三条接力线跨元素时至少一条；同元素时演员线最省。
- 疑问链的过程型变体（第二拍换「怎么来的」），条件是过程有叙事价值——判据在第一节的「删掉失去什么」。
- 验收成本低、否定可靠；不要用它证明「送达了」。
- 代价：先给重点失去揭示快感；动作线要求的入场动作可能与叙事动作冲突（v3 的方向不一致就是取舍）。

## 稳定性

| 内容 | 稳定性 | 写法 |
|---|---|---|
| 入场是示能的首次兑现 | 定义 | 写死 |
| 工序兑换的三类 | 定义 | 写死 |
| 信息须真实且相关 | 判据 | 写死 |
| 三条接力线 | 判断 | 有对照，可增减 |
| 疑问链三拍 | 默认 | 过程型入场第二拍不同 |
| 一拍一个焦点 | 默认 | 一组错落算一个焦点 |
| 最后一拍＝交互第一帧 | 要求 | 与接缝一致 |
| 验收的四项检查 | 方法 | 否定可靠、肯定弱 |
| 具体时长、拍数 | 不沉淀 | 场景函数 |

## 还没定

- 入场时长与节奏的量化（多长算长、几拍算多），没有讨论。
- 跨页面、跨屏的入场一致性（入场语言在整个产品里要不要统一），没有讨论。
- 空手接管测试的样本量与结论强度，没有验证（一人一次）。
