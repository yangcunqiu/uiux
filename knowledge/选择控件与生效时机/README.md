# 选择控件与生效时机

选择控件的外观、文案、允许的取值和实际操作应表达同一种含义。设计时先明确几个业务问题。选项能否同时成立？“尚未回答”是不是有效状态？选择立即生效，还是先存入草稿？同样的两个选项，答案不同，适合的控件也会不同。

| 需要表达的值 | 常用控件 | 需要留意的边界 |
|---|---|---|
| 一组互斥选项中的一个 | 单选组 | 可以初始未选。若用户选择后还要主动恢复“未设置”，应提供明确入口或有名称的选项。 |
| 集合中相互独立的成员，或对一项声明的确认 | 复选框 | “邮件”和“短信”可同时选。“接收”和“不接收”用两个独立复选框，会允许矛盾组合。 |
| 当前开启或关闭的二元状态 | 开关 | 适合直接改变状态。“跟随系统／开启／关闭”有三个值，需要能表达三个值的控件。 |

单独一个单选按钮一旦选中，通常无法再靠同一动作取消。一个互斥组的成员需要共同的组名和互斥行为。在 Web 上优先使用原生控件。自行实现单选组时，核对组内方向键和焦点进入、离开的行为。圆点、方框和勾形可以帮助预判，最终仍要核对值、角色与操作是否一致。[WAI 单选组交互模式](https://www.w3.org/WAI/ARIA/apg/patterns/radio/) · [WAI 复选框交互模式](https://www.w3.org/WAI/ARIA/apg/patterns/checkbox/)

## 标签、预选与生效时机

复选框的正向标签应能直接回答勾选后会发生什么。把功能名留在开关旁，当前值由控件状态表达，避免切换时连动作的主语也改变。组标题说明维度，选项写出可比较的取值。同组使用一致的语法，区分度比字数更重要。诸如“我已阅读并同意……”的声明应保留完整意思。如果需要填写“其他”，输入框靠近该选项，给它独立标签，并在该选项适用时验证补充内容。选择默认值会消除“尚未回答”的区别。无明显后果的偏好可预选，需要用户主动表示意愿时应保留未选择状态。

开关通常表示当前已生效状态。多个开关作为同一份草稿等待保存时，要让人看出存在未保存更改，以及何时才会生效。设置在另一页才可观察时，错误的状态提示尤其难被及时发现。给立即生效的可逆操作提供适当的改回或撤销方式，用户就能直接操作。

一个多选集合如果需要整体核对、中间组合会产生副作用，或只是更大表单的一部分，可以显式点击“完成”。勾选表示草稿，放弃编辑后外部摘要仍显示之前的值。若每项独立、可逆且立即应用代价低，则每次勾选都可单独生效。单选也可能随整张表保存。移动选择页用勾标识选项时，单选的互斥关系可以由换选后的行为表达。返回后的摘要要准确反映已生效值。
