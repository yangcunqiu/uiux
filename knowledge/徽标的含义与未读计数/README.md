# 徽标的含义与未读计数

同一个小圆点可以表示“有新内容”，也可以表示“在线”。数字既可能表示未读消息，也可能表示购物车里的商品数。先确定徽标回答的问题，再决定颜色、数值和更新规则。购物车数量反映当前内容，访问购物车不会自然使商品数归零。促销文案表达推广信息，也不能直接套用未读机制。

## 依据什么标为已读

- **打开会话即标为已读。** 适合以整段会话为查看单位的产品，代价是只扫一眼也会清除未读提示。
- **逐条标记。** 适合每一条都值得回看、漏读后果可能稍后才出现的内容。到达率高时，未读会持续积累。
- **按看到的位置记录。** 对连续信息流，可以记录阅读位置或自上次查看以来的新增。它能提供新旧分界，不能证明使用者已经处理每一条。

把未读数当作待处理量，需要内容与使用者的目标相关、漏看有后果、数量仍可处理。用户只是想区分新旧时，更合适的机制可能是上次阅读位置。对推广推送，提供不再提醒可能比持续累加未读数量更符合需求。

## 清除什么，界面就写什么

“清除角标”只移除入口处的提醒，可以保留各条消息的未读状态。“全部标为已读”会改变指定范围内消息的单条状态，应反馈实际影响范围。会误清重要未读时可以提供撤销。两种功能都可以成立。标为已读也不自动等于业务事项已经处理完。先执行批量动作，再核对入口数字与具体消息状态，可以发现更新范围不一致。

对人际消息，批量标记一般可放在列表操作区，以免过于容易误触。对时效性通知流，可按内容的新鲜期清除提醒。将私人消息自动标为已读会改变用户用来回看的信息，不应从一般通知的过期策略直接推导。过期天数由内容决定。显示“99+”只降低显示精度，并不改变实际未读状态。

徽标压在照片等复杂背景上，可用与周围背景区分的轮廓维持可辨认性。透明度可以降低次要提醒的视觉强度，前提是内容仍清晰。关键状态还要有颜色之外的区分。大量入口同时突出会削弱优先级差异，是否真的引起忽略则要观察实际使用。
