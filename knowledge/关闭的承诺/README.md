# 关闭的承诺

关掉一个层，用户只在问一件事：我刚才弄的那些，还在吗？

四条通道——取消、×、Esc、点外面——不是四个入口，是四种承诺。前三条说"我要关"，第四条说"我可能只是想看看"。把它们当同一件事，就会做出看起来安全、其实丢数据的关闭。

## 先看演示

[打开「通道与草稿」](通道与草稿.html)（双击即可，不需要本地服务）

一个表单，四条关闭通道，四种草稿策略。按这个顺序走：

1. 草稿设成"不保存"，改一格，点外面关：丢掉计数 +1。
2. 切"同会话快照"，同样点外面关：内容在撤销条里，新建入口仍然是空白。
3. 切"显式草稿"：关掉后列表里多一条"未完成的新建"，点它才恢复；新建入口还是空白。
4. 切"自动填进新建"：再点新建，表里是上次的内容，标题上方出现红条——这就是幽灵草稿。
5. 形态切"非模态"，点背景的"记一笔"：计数先加，面板随之关闭。模态下点同一处只会点到遮罩，按钮不触发。

## 四条通道

| 通道 | 意图 | 误触 | 它承诺的事 |
|---|---|---|---|
| 底部"取消" | 明确 | 低 | 放弃这次编辑 |
| 右上角 × | 明确但泛化 | 中 | 关掉这一层，等同取消 |
| Esc | 明确，键盘 | 中（层内部还有栈） | 取消当前层 |
| 点外面 | **不明确** | 高 | "我什么都没做" |

前三条的差别只在载体，第四条性质不同：它是唯一一个无法确定用户想干什么的通道。

**默认给四条。** 收窄只在两种情况下发生：层很重（有一屏未提交的内容），或者遮罩背后有用户需要读的东西。

## 一、关闭只能表示"放弃"

任何通道都只能表示"放弃这次编辑"，不能表示"保存"。一旦某条通道偷偷保存，用户对"关闭"的全部预期就乱了——他会用 × 去保存，也会在别的弹窗里这么试。

还有一种关闭不由用户发起：会话过期、权限变了、正在编辑的对象被别处删掉。系统发起的关闭也要走同一套承诺。它最容易被忘掉，也最容易让用户一无所有。

## 二、提交中：关闭不再表示"放弃"

| 时刻 | 关闭意味着 | 还能撤销吗 |
|---|---|---|
| 编辑中 | 放弃这次编辑 | 能，内容还在本地 |
| **提交中** | **只收起视图，不能撤销动作** | **不能：请求已经发出去了** |
| 成功后 | 关闭并交代结果 | 不需要 |
| 失败后 | 放弃这次重试，内容还在 | 能，回到可编辑 |

提交那一刻变的是**撤销能力**，不是界面的样子。用户点"创建"之后，内容已经不在界面手里：服务器可能已经建好了。这时候任何一条通道如果还说"我什么都没做"，就是假回执。

所以准确的说法是：**提交中不能"放弃"，但可以"收起"。**

### 三种解法

| 做法 | 适合 | 代价 |
|---|---|---|
| **拦住**：四条通道都不可用 | 短请求（1–2 秒），结果必须在这一层交代 | 请求挂住时用户出不去 |
| **转后台**：允许关，关的是视图 | 长任务（上传、生成、批量） | 必须有层外的结果载体：提示条、列表、进度 |
| **立即关**：提交即关，结果异步回来 | 结果不重要、可异步 | 失败要能回来说 |

分界不是秒数，是**结果要不要在这一层当面交代**：要，就拦住；不要，就把交代搬出去（[受理与交代](../受理与交代/README.md)）。长任务拦住半分钟，用户会去点刷新。

### 如果选拦住，三条硬规则

1. **关闭不撤销请求。** 除非产品明确提供了"取消提交"，而且服务端真的能取消（幂等或可中断），否则任何关闭通道都不能把请求掐掉。掐掉之后服务器照样执行，是最坏的一种假回执。
2. **拦住必须看得见、有界。** 主按钮进入"提交中…"并锁住，其他关闭入口隐藏或明确不可用——不能留一个看起来能点的 ×。按 Esc 给一句轻提示（"正在提交"），不要什么都不发生：无响应的界面读起来就是卡死。超过 N 秒（10 秒是个起点，不是定律）转成"在后台继续"。
3. **失败回来要能恢复。** 请求返回校验错误时，层解锁、错误就近显示、内容还在；关闭重新变回"放弃"，走草稿那套。

### 几个容易漏的

- **提交中整层只读**，不只是关闭。否则界面上显示的内容和已经发出去的 payload 不一致。
- **重复提交要跨关闭拦住。** 允许转后台时，重新打开不能给一张空表，要显示"上一次提交还在进行中"。
- **× 不要灰着留个影子。** 灰按钮仍然是"能点"的形状；隐藏，或换成不可点的静态标记。
- **别把焦点锁死。** 如果服务端支持取消，留一个明确的"取消提交"在层里，Tab 能到。
- **浏览器返回、关标签是另一条通道**，和 Esc 不是一回事；通常只能用 `beforeunload` 提示，不能拦。

## 三、层的轻重决定关闭的轻重

| 层 | 草稿 | 点外面 | Esc | × | 取消 |
|---|---|---|---|---|---|
| 轻（选择、确认、提示） | 无 | 关 | 关 | 有 | 有 |
| 中（改个名字、单个字段） | 小 | 关 | 关 | 有 | 有 |
| 重（一屏配置、选了一半） | 大 | 关，但可恢复 | 同左 | 同左 | 有 |
| 重且不可恢复 | 大 | 拦，或问 | 同左 | 同左 | 有 |

判断不是"点外面关好不好"，而是**这个层有多重，就用多重的方式关**。同一个动作放在重层上就是陷阱：用户心里想的是"我在编辑"，手却做了一个"退出"的动作。不是他大意，是界面把两个重量级的东西画成了同一个。

## 四、「点外面」其实是两个动作

| | 模态 | 非模态 |
|---|---|---|
| 点击落点 | 遮罩 | 背景元素 |
| 背景动作 | 不执行 | 执行 |
| 关闭发生在 | 点遮罩时 | 点层外任何东西时 |
| 名字 | 点遮罩关闭 | 失焦关闭 |

会打架的是把它们混着实现：给非模态层挂一个拦截遮罩，再指望点背景能用——自相矛盾。

**非模态的"点外面"不能靠遮罩实现**，要挂 document 级的 `pointerdown`；用遮罩做点击检测，就必然拦截。

判定要用"按下和抬起都落在遮罩上"，不能只听 `click`：从层里拖选文字、拖到遮罩上松手，`click` 的目标可能是遮罩，只听它就会误关。

## 五、背景什么时候可点

四条都满足才可点：

1. **层里没有提交边界**——没有表单要交、没有不可逆动作。有提交就必须模态。
2. **背景动作不会让层失效**——点了另一行，层要么跟着换，要么不引用那一行。会过期就不能可点。
3. **"对照背景"是开这一层的目的之一**，不是副作用。检查器、目录抽屉、调色板属于这一类。
4. **层是辅助性的**，不是决策。

反面一条（[动效的层级](../动效的层级/README.md)）：**"变暗 + 可点"是最坏的组合**——画法说"别用"，行为说"能用"。选可点就别画遮罩，或者画到不构成"挡住"的程度。

还有一个代价要认：可点的层在"点外面关"时，用户点背景按钮会**先执行按钮动作，顺手把层关掉**。如果那个动作会改变层的内容，层关了不要紧；如果不会，用户只是点了按钮。这是可点的固有代价，不是 bug。

## 六、草稿不是"更安全的确认框"

"点开新建，里面是上次的草稿"——这是**假回执**（[藏起来的代价](../藏起来的代价/README.md)）：用户以为状态是"空表"，系统给的是"上次的残留"。

根因是把草稿当成了"更安全的确认框"。它不是。草稿是一个**新对象**，有归属、有生命周期、有列表。所以要分成两种，不能混：

| | 同会话快照 | 显式草稿 |
|---|---|---|
| 目的 | 防误关、可撤销 | 跨会话继续 |
| 生命周期 | 关掉页面就没了 | 是一个条目 |
| 入口 | 撤销条 | 列表里的"草稿"条目 |
| 会不会污染"新建" | 不会 | 不会（不往新建里塞） |

三条规则：

1. **新建入口永远是空的。** 点"新建"就是要空白。
2. **恢复必须显式且可见。** 要保留未完成的新建，就在列表里给一条"继续上次未完成的新建（3 项已填，10 分钟前）"，用户选它才恢复；恢复后给"清空重来"。
3. **草稿属于对象，不属于入口。** 编辑已有对象时恢复它的草稿是预期的；新建没有对象，也就没有"它"的草稿。

可恢复有三种手段，成本递增：**撤销窗口**（5–10 秒，不产生残留，首选）→ **同会话快照**（防误关，关页即失）→ **显式草稿**（跨会话，最后选）。重层的第一选择是前两个，把第三个当默认，就会生产幽灵草稿。

## 七、× 和"取消"是隐藏的重复

没有草稿时，两个入口指向同一件事，重复是好事——多一个入口，用户不用找。

有草稿时不行。× 在角上，长得像"关窗口"，用户对它的预期是"不会丢东西"；"取消"在底栏，长得像"放弃编辑"。同一个结果、两个心理预期，× 就成了陷阱。修法二选一：让 × 走同一套脏检查，或者有草稿时把 × 变成"收起"。

还有文案：**如果关闭会保存草稿，"取消"这个词就是错的**，应该叫"关闭"。按钮文案是关闭语义的声明，词错了，前面所有判断都白做。

## 八、Esc 是一个栈

Esc 的语义是"取消当前这一层"，但"当前"有三层：

1. **层与层之间**：两层弹窗时关最上面那层，不是全关。
2. **层内部**：弹窗里有展开的下拉/级联，先收起它，再关弹窗。
3. **输入法**：中文输入法在候选状态时，Esc 是"取消候选"，不该关弹窗（监听里避开 `isComposing`）。

原生的 `<dialog>` 和 popover 自带 Esc 关闭，别再自己挂一遍，否则会关两次或者关错层。

## 九、遮罩与回退

遮罩有三根轴：画法（变暗 / 模糊 / 透明 / 无）、拦截（背后能不能点、能不能滚）、点击关闭。画法在[动效的层级](../动效的层级/README.md)里，拦截在[拆组件](../拆组件/README.md)里，这里补第三条和它与前两条的关系。

"点击不穿透"只在拦截时成立：**有拦截层时，点击落在遮罩上；没有拦截层时，穿透本来就是功能**。透明遮罩只在"面板本身已经提示有层"时成立（比如抽屉），否则用户不知道有一层。

回退是**语义回退**，不是外观回退。`backdrop-filter` 不支持、或者低端设备要关模糊时：

- 模糊（"别再看了"）退回**更不透明的纯色**，语义还成立；
- 退回**轻微变暗**，语义变成"可以看"，反了；
- 退回**完全透明**，语义全丢，再叠上"点外面关"，最糟。

性能回退同理：如果设计依赖"透过遮罩还能看见背景"，退回不透明就切断这个依赖，得换布局，不是换颜色。

## 为什么这样判断

- 四条通道的意图差异是定义性的（点击落点、背景动作是否执行），可以直接观察；误触概率是估计，不是测量。
- "点外面是两个动作"来自模态与非模态的实现差别：有没有一个接收指针的遮罩层。这是结构事实，不是偏好。
- "背景可点的四条"整理自[拆组件](../拆组件/README.md)的模态/非模态取舍，那里给了三个信号（会冲突、会过期、需要对照），这里补上"没有提交边界"。
- "草稿是假回执"接的是[藏起来的代价](../藏起来的代价/README.md)里那条：摘要过期、角标没更新——静默恢复草稿是同一类。
- "撤销优于确认"来自[拆组件](../拆组件/README.md)判据 2：只防误触的确认，成本通常高于收益。这里把它落到关闭通道上。
- "提交中关闭不再表示放弃"来自请求发出后界面失去撤销能力这一结构事实；三种解法是按"结果在哪交代"推出来的，没有在长任务产品上验证过；10 秒是经验值，不是测量。
- Esc 的三层作用对象是推理，没有逐一实测；`isComposing` 的行为在不同浏览器和输入法下有差异，没有验证。

## 适用条件和取舍

- **默认给四条通道**是一个偏好加判断：它符合"轻层"的直觉，也符合多数桌面产品。代价在重层上，用"可恢复"抵，不用"确认框"抵。
- 提交中的三种解法依赖 API 能否取消、能否幂等。不能取消时，"转后台"必须配层外的结果载体，否则用户关掉之后什么都不知道。
- 弹窗之上再开弹窗（或抽屉）时，关闭的层级问题会放大；这篇只给了 Esc 那一条，其余在[叠层与返回栈](../叠层与返回栈/README.md)。
- 移动端的手势返回、底部面板的下拉关闭，与"点外面"是另一套习惯，没有讨论。
- 系统发起的关闭（会话过期、权限变化）写了原则，没有给实现方式。
- 演示只展示结构，不测人：没有测误触率，也没有测撤销条会不会被看见。撤销窗口固定 10 秒，是演示值；表单只有三个字段，真实的重层可能更长。

## 稳定性

| 内容 | 稳定性 | 写法 |
|---|---|---|
| 关闭只表示放弃 | 定义 | 写死 |
| 四条通道的意图差异 | 定义 | 写死 |
| 模态/非模态对应两种"点外面" | 定义（由实现决定） | 写死 |
| 默认给四条通道 | 默认 | 可偏离：重层收窄 |
| 轻重一致 | 默认 | 看层的重量 |
| 背景可点的四条判据 | 条件 | 写判据，不写场景清单 |
| 可恢复三档的顺序 | 默认 | 撤销 > 快照 > 显式草稿 |
| 提交中关闭不表示放弃 | 定义 | 写死 |
| 拦住 / 转后台 / 立即关 | 条件 | 按"结果要不要在这一层交代"选 |
| 拦住的时长阈值 | 经验值 | 10 秒是起点，不是定律 |
| 误触概率的具体值 | 经验值 | 没有数据，别当测量 |

## 还没定

- 误触率的真实差异（点外面 / × / Esc）没有数据，都是估计。
- 系统发起的关闭怎么告知、怎么保数据，没有展开。
- 显式草稿的清理策略（多久过期、留几条、谁删）没有定。
- 移动端手势返回、下拉关闭与这四条通道的关系，没有讨论。
- 读屏用户怎么知道"这一层可以点外面关"，没有展开。
