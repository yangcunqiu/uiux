# 卡片堆叠：换位与展开

一叠卡有两个问题：换位时怎么动才像真的；要从里面挑一张时，怎么让每张都能被指认。前者是物理，后者是选择。这一条把两件事分开，用一个演示对照。

## 先看演示

[打开演示](demo.html)（双击即可，不需要本地服务；脚本在同目录 demo.js）

演示三部分，各自只改要研究的一个因素：

1. **换位**：同一叠卡、同一次「下一张」，只换编排——同时换位（反例）对先腾位（正例）。看反例读不读得出「穿模」。
2. **入场**：同一叠卡的入场三版——封面飘入、封面加生成文字、氛围散开加文字揭开。观察每一版落位后，这叠东西有没有宣告「可以被揭开」。
3. **浏览型展开**：hover 展开的三种做法——每张卡自己当目标（A）、扇区当目标（B，扇区随状态变化）、示能加点击展开（C，对照用）。

## 我们的理解

### 一、问题从哪来：选择要求每张卡都能被指认

堆叠把一组卡压成一张（为了省空间或做仪式）；一旦任务是从里面选一张，压掉的信息就必须被还原，否则选不了。还原有两个通道：

- **空间**：把卡展开（扇开程度从 0 到全部）。
- **时间**：把每张卡依次带到最前（逐张翻），卡不需要同时可指认。

没有选择任务，就不需要还原——命中改写、振荡、死区、展开距离这一整类问题都不出现（浏览仍可能要方向感，但那是计数与位置问题）。所以「一叠卡怎么展开」不是孤立的美学题，它是选择任务的衍生问题。

### 二、换位：物理顺序

同一叠卡、同一次换位，只改顺序就能决定它读不读得得出「假」。同时换位时，离场卡和进场卡在中间地带同时在场、深度关系整场冻结——读出来是「穿模」。

失败形态的准确说法不是「两张卡穿过」，而是**卡在自己还压着别人的地方换了账**：滑动的卡半张在别人的区域内时开始翻转深度，被压的那部分瞬间被下面的卡接管。两条规则：

1. **深度改判只能发生在无人区。** z 轴不能过渡（z-index 是离散的），重叠区里换深度必然穿帮。
2. **翻转深度前要让出的范围 = 要跨越的那几张卡的区域。** 插到队尾（跨越全部）就离开整叠的外缘；插到第 n 层就离开前 n 张的区域。

由此有一个推论：**看不见的改判免费**——卡先完全出画、再从别处进场，中间的传送没人看得见。（接缝这条判断见[接缝](../接缝/README.md)。）

滑动方向与露出方向是两个独立选择：露出管「还有卡」的可读性（计数、抓取点），滑动管前进与循环的隐喻。配对决定离场路径的代价——滑动背离足迹（右侧露出的卡向左滑）可以直接进入空场、沉底后穿底插回；跨过足迹（向右滑）就要绕行或用抬起来离开平面。材料里没有「露出侧决定滑动方向」的规则，反例是下侧露出＋向左滑。

边界：这套编排只在用户被邀请把玩的场景成立（低频、一次性、仪式性）。原文自己留了条件——足够简洁明了的轮播避免三维大变形反有优势，用户需不需要「足够自然」定取舍。代价是总时长变长。

### 三、展开：两根轴

把展开拆成两根正交的轴：

| | 打开时机 | 打开形式与程度 |
|---|---|---|
| 取值 | hover／提交（点击）／常开／换位导航 | 换位／部分展开／全铺开 |

「hover × 空间展开」是唯一会长出命中问题的一格：**没交代时，空间就动了**。逐张翻不在表里充当「展开量为零」——它是换了通道（时间），卡不需要同时可指认。

#### hover 位移的病因

位移展开的振荡，病因不是「会闪」，而是 **hover 把选择绑定在屏幕位置上，用户的意图绑在对象上**。卡一动，指针下的人就换了；描边、点中、预期三者对不上——振荡只是可见症状。它需要三个条件同时成立：目标是被位移的卡本身、位移与 hover 互为因果、没有锁存；破坏任意一条即可。

据此的修正版：**扇区为目标，且扇区随状态变化**——收起时只按卡片足迹判悬停，张开后才是整扇区。这样既没有振荡，也没有空白死区（死区是静态区域的实现快捷，不是规律）。B 的顶卡是锚点（动的只有下三层）；展开瞬间指针下的卡可能换人，加上「指针一进入就展开，路过也算数」——这两条是免点击预览的价钱，是代价不是缺陷。

#### 方向与距离

方向不自由：**延续收拢时的露出方向**（peek 在哪边就往哪边展开），并且不出屏。距离有上下限：下限是不点开就认出每一张（识别先于提交），上限是屏幕余量。

#### 形态与判据

选择形态的判据：**选项数 × 空间余量 × 识别要并行还是串行**。

- 卡少、有地方：扇开（并行识别）。
- 卡多、地方小、或翻阅本身有叙事价值：逐张翻（串行识别，N 张要 N 次操作）。
- 要一眼看全：一次铺开（最大的布局事件，要留退出）。

#### C 的定位

示能加点击展开，在拣选主任务里被修正版 B 支配：识别必须靠某种展开，C 把展开挪到点击后，等于在主路径上加一步。但两处场景它成立：

- 叠放不是主任务、周围拥挤、路过多时——「不动，直到你交代」是克制。
- 触摸端没有 hover 状态：任何 hover 展开都必须以点按展开存在，那就是 C。

描边本身的价值是示能（这里能不能动、指对没有），不是识别（哪张是哪张），两者别混。

更上游的判断：如果选择是主任务、空间允许，该质疑的是**堆叠本身**。堆叠为省空间或仪式而压掉选项，选择需要同时看到选项——这时正解是不用堆叠，而不是在堆叠上加展开。

## 为什么这样判断

- 「穿模」读感是观察到的；失败形态的「半张卡换账」是对观察的准确化，不是假设。
- 深度规则来自机制：z-index 不能过渡，任何在被覆盖区域内的深度改判都会在同一批像素上换账。
- 范围通式来自「跨越谁」：要插到哪一层，就先离开那几层的区域；两端分别是「离开整叠外缘」与「离开前 n 张」。
- hover 病因的三个条件是从对照演示里拆出来的：A 模式的目标是被位移的卡本身；B 锚定顶卡后不再振荡。
- 方向与距离的约束可检验：反向展开破坏收起与展开的连续性（可见）；出屏不可见（可见）。
- C 的定位是条件判断，不是偏好：拣选主任务里多一步（可数）；拥挤场景里路过触发（可数）；触摸端没有 hover（平台事实）。

## 适用条件和取舍

- 换位规则适用于「牌堆」隐喻与把玩场景；工具型、高频、赶时间的轮播用简单快滑，代价是穿帮风险——省时长。
- 修正版 B 的代价：路过触发；展开瞬间指针下的卡可能换人。
- 逐张翻的代价：识别串行，N 张要 N 次操作；「只需要扫一眼」时会慢。
- 内容决定距离需要可用宽度：窄屏上可能放不下完整标题，退回固定距离加截断。
- 「别用堆叠」的条件：选择是主任务且空间允许。反之，堆叠有别的理由（空间、仪式）时，展开是合理折中。

## 稳定性

| 内容 | 稳定性 | 写法 |
|---|---|---|
| 选择任务要求每张可指认 | 定义 | 写死 |
| 深度改判只能发生在无人区 | 机制 | 写死（z 不可过渡） |
| 要让出的范围 = 跨越区域 | 定义 | 写死 |
| 滑动与露出方向独立 | 判断 | 材料内无规则，别当定律 |
| hover × 空间展开是病灶 | 判断 | 有对照演示支持 |
| 扇区随状态变化 | 默认 | 可省，代价是死区或振荡 |
| 方向延续露出方向、不出屏 | 默认 | 两条都可检验 |
| 距离上下限 | 经验值 | 下限是识别测试，上限是屏幕 |
| 46/72px、0.5s 等数值 | 演示值 | 不是推荐值 |

## 还没定

- 深堆叠（超过 6 张）扇开后重叠是否导致识别退化，没有验证。
- 「内容决定距离」在不等宽、多行标题上的测量口径，只有演示里的近似实现。
- 逐张翻在「只需要扫一眼」的需求下是否仍成立，没有对照。
- 键盘端「焦点即展开」与指针端 hover 展开是否给出同样的识别效果，没有验证。
