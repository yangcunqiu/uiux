# 设计判断的证据

一个界面可以同时获得良好的第一印象，并在某个具体任务中出错。评审应说明判断的对象及证据能支持多强的结论。能复现“在支持的窗口里，唯一提交按钮被裁掉且没有其他入口”，足以指出这条路径失败。某位评审者第一次没找到按钮，则说明在这次条件下出现了查找困难。两种发现需要不同的后续验证。

## 谁在什么环境中完成什么任务

一条观察至少要能说明是谁在使用、环境与实际使用是否相近，以及使用者是首次接触还是已经熟练。会议室投影与手持设备、设计者自测与新用户初见、改版首日与日常熟练使用，都可能产生不同结果。一次成功只能支持那次操作。范围越广的主张，越需说明任务、样本和环境的代表性。

有条件时先向目标使用者了解实际任务并观察操作。拿不到目标使用者时，可以先了解业务和真实设备，模拟相关环境，明确哪些结果是自己的观察。对一般认知规律的推断也需要核对在当前任务中的前提。能访问真实使用者时，区分他们报告的感受与实际执行的步骤。不能用 AI 对截图的描述冒充使用者的行为。评审现有设计时，先查原方案服务了什么任务，当前提不同时，另一种布局可能更适合。

## 感受、测量与偏好

“感觉太快”可以指出需要检查的地方。查出动画时长，只验证了时长。要说明快到妨碍使用，还要观察是否来得及看清对象、能否继续操作，或在相同任务下比较其他时长。若选择只为品牌性格，可以直接说明项目偏好。对真实使用者而言，“我觉得乱”是一次真实报告，还需观察在哪一步、哪些信息难以区分。

关于 ATM 布局的研究观察到，美观判断与表面上是否容易使用的评分相关。评分不能单独证明任务做得更快或更准，也不足以排除视觉安排对操作的实际影响。对同一个项目，可以先完成任务并记录结果，再询问感受。初次印象和反复使用后的评价应分别记录，二者的权重及变化时点不能从示意曲线读出。[Kurosu 与 Kashimura 的 ATM 布局研究](https://doi.org/10.1145/223355.223680)

借鉴案例时，优先保留能说明取舍的细节。例如一个入场方案被放弃，因为新增的一步仍无法提示怎样开始操作，这比只列出最终效果更能说明适用边界。作者只说“感觉不合适”时，记录为选择理由即可。一个成立的反例可以收窄一条过宽的规则。一个成功案例只能说明在那些条件下可行。
