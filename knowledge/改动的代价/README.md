# 改动的代价

一个界面用久了，它的可用性有一半已经搬进了用户的身体：按钮在哪、这条路怎么走、先点哪个后填哪个。这部分不在界面上，在用户学会的东西里。改版动界面的同时，也在作废用户已经学会的东西。本篇讨论三件事：这份资产怎么计数、改动怎么按它定价、必须改的时候怎么切才不把代价翻倍。

起点是一条流传很广的经验说法——"B/G 端客户欢迎增加、反对修改、抵制删除"。讨论后它被修正成了条件句。

## 先看图解

1. **学习债曲线**：观察谷底深度和恢复时长随习惯资产怎么变；新旧版本的公平对比位置在稳态段，不在谷底。
2. **动刀的深度**：四层代价从浅到深；名字不在轴上，它伤的是口头协作。
3. **在哪切开**：域内一次到位、域间按块；条纹状态（同域改一半）是最差解。

## 我们的理解

### 一、习惯是用户侧的资产，改版作废它

用户学会的东西分两类：

- **绑在产品上的**：位置、路径、顺序、名字。改版作废的是这一类。
- **不绑的**：打字、滚动、双击、"关闭在右上"。这些绑在平台惯例上，跨产品通用。

两类对应心理学的程序性记忆（动身体、不经意识）和陈述性记忆（能说出口）。这个区分本身是常识级结论。

由此把"欢迎增加、反对修改、抵制删除"修成精确版：**你作废多少已学会的东西，就收到多少阻力**。阻力不是保守，是不确定性——用户不知道这次操作会不会变慢、会不会出错，手里的熟练资产突然不能用，新资产成色未知。增加不动存量，所以加法阻力小；但加法有另一种代价（入口变多、找东西变难），那是[入口与回执](../入口与回执/README.md)和[放不下的列](../放不下的列/README.md)的领地，不在这里重开。

习惯资产总量 = **人数 × 每人深度**，不是人数一维。30 个操作员每天 8 小时的系统，人数极少、资产巨大——"没有大量用户"的直觉在这里失效。

### 二、效率测的是"界面 + 用户状态"的联合体

平时说的"这版更快/更慢"，默认带着用户已经预热的状态。老用户测出的是稳态，改版头两周测出的是冷启动——放在一起比是无效对比。有效对比是稳态对稳态：重学完成之后谁快。

学习债怎么量（可检验的操作，尚未实测过）：

- **错按率**：改版头几天用户点向旧位置的比例。错按发生在意识之前——改版后第一次手伸向原来那个位置时"手先动了"，这是程序性记忆最直接的行为证据。
- **核心任务用时曲线**：改版前基线 → 改版后谷底 → 恢复到基线的时长。恢复时长就是这笔债的实际额度。
- B 端的现实困难：客户样本小、单位之间隔离，做不了灰度对照；只能拿工单量和培训提问当代理指标，精度差，如实记。

### 三、改版赢的条件

| 条件 | 说明 |
|---|---|
| 习惯资产总量低 | 投诉多本身就是"没人用惯"的证据；新用户为主的产品改版阻力天然小 |
| 习惯的迁移目标恰好是新版 | 用户平时更多用某个竞品时，抄竞品不是打破习惯，是把用户已经会的接回来 |
| 收益还得起债 | 每次省的时间 × 频率 × 使用寿命 > 重学成本。低频功能两头都小：没多少习惯可伤，也省不了几次，不值得大动 |
| 用户结构摊薄（未定） | 增长期产品，老用户资产被新增用户摊薄；封闭存量里资产全额在场。可能这才是"B 端怕改版"的结构性解释——见「还没定」 |

### 四、动刀的深度：按作废多少分层

| 改什么 | 伤到哪 | 量级 |
|---|---|---|
| 风格：颜色、图标、圆角、字重 | 眼睛重新认一遍 | 小，手不断 |
| 位置挪动、分组重排 | 空间记忆 | 中 |
| 流程：步数、顺序、确认点 | 程序性记忆 | 深 |
| 惯例：Ctrl+C、关闭在右上 | 生态级习惯 | 最深，且冤——撞的不是你的产品 |

**名字单独一列**：改菜单名、改文案伤的不只是肌肉记忆，还有**口头协作**——"你去点设置→高级→导出"这句话失效，培训材料、同事指路、客服话术全部重写。位置挪了用户自己疼，名字改了整个组织跟着付账。这条是讨论中的推论（机制清楚，未单独验证）。

### 五、怎么切：域内一次到位，域间按块

肌肉记忆按任务域组织：不同域互不干扰（学编辑器快捷键不干扰学开车挡位），**同一域内的新旧动作序列才互相干扰**。所以：

- **域内一次到位**：一个任务域改一半是最差状态——旧记忆和新规则在同一块屏幕上互相干扰，两头的账都要付。
- **域间按块上**：按任务边界切，每块独立可活、可回滚；用户每一刻只需要为刚被切的那块重建记忆。
- "习惯资产少就全域一次到位"是这个框架的极端：**整个产品算一个域**。习惯浓度越高，刀要切得越小。

一次到位有两个独立条件，各自成立即可：①习惯资产总量低；②**没有可活的中间态**——有些改动不管习惯多少只能切（全局导航从三级压成两级，改一半意味着一半入口深一半浅，中间态比两头都差）。反过来，能切就尽量切。给后端读者的同构：这就是 expand-contract 迁移和 cutover 的区别——加列、双写、回填、删旧列可渐进；主键改造没有活着的中间态，只能 cutover。

### 六、必须改时，三个手段各有账

- **旧版入口**：好处真实——有退路才敢试（信任效应）；代价是双份维护、迁移被无限推迟、行为数据分叉。它是 expand-contract 只做 expand、不定 contract 日期——两套真相永久并存。所以它是**临时债，立项时就要定 sunset 期限**。
- **新旧映射**：比通用教程有效，因为它承认旧习惯存在，直接回答"原来的 X 现在在哪"。低配版的旧版入口是**保留一条旧通道**。
- **一次到位 vs 渐进**不是一个二选一：真正的问题是在哪切开（见上节）。

## 为什么这样判断

- 两类记忆的区分、同域新旧互扰，是心理学的常识级方向；具体到界面的应用（错按、恢复时长当测量）是本次讨论提出的可检验操作，未实测。
- 起点那条经验说法被修正成条件句，依据是同一份材料里自带的反例：客户投诉多（没养成习惯）、平时用竞品（习惯的迁移目标恰好是新版），所以抄竞品反而成立——"反对修改"在习惯没养成时不成立。
- 文中案例（网银自述、Office 2007、Windows 8、Dvorak 键位、Snapchat 2018）是常识级案例，未做来源核查，各自只支撑就近的那一句话。
- Hyrum 定律（用户量一大，一切可观察行为都会被依赖）说明这份契约存在；热缓存（用户脑子是界面的缓存，条目以界面稳定为前提）说明失效的代价。两个都是类比，帮后端读者接入，不构成证据。

## 适用条件和取舍

- 这套账适用于"用出一身习惯"的高频工具；低频工具习惯资产本来就小，别把这套账套上去吓自己。
- 本篇只管"对的改动怎么付账最省"，不管"改动方向对不对"——方向判断靠业务与证据，不在这篇。
- 一次到位后的**错按向导**具体做成什么样（映射引导的形态），本篇没有展开，Office 案例只证明方向有效。
- 颜值在初见场景的加成与这条的关系（颜值信用 vs 熟练信用），见「还没定」的交接。

## 例子

- **Office 2007**：ribbon 干掉菜单，配"旧菜单位置→新 ribbon 位置"的交互对照引导；键盘 Alt 序列保留旧层次，键盘用户的肌肉记忆基本存活，鼠标专家最痛（代价分层的一个实例）。
- **Windows 8**：动了惯例层（隐藏热角、charms），面对锁定存量，反弹；8.1 交回开始按钮。
- **Dvorak 键位**："更优"赢不了"已会"——即使理论收益全部成立，重学成本也挡在前面，它从未被大规模采纳。
- **Snapchat 2018**（C 端对照）：同样的怨气，C 端用户能走，转化为流失；B 端用户走不了，转化为工单和续约筹码。**被锁定不减轻阻力，只改变阻力的表现形式。**
- **网银自述**：老版本边用边骂，新版本一出来还是切回去了——怕的不是新，是"这次会不会变慢、会不会出错"。样本 1，机制的例子，不是证据。

## 还没定

- **增长摊薄推论**：封闭存量里习惯资产全额在场，可能是"B 端怕改版"的结构性解释——讨论提出，还没找到反例，也没找到支持的研究。
- **体感实验**：换编辑器主题（难受在眼、手不断）vs 重映射一个高频快捷键一天（难受在手、持续错按）——用来体感"皮"和"规则"的代价差，尚未做。
- **改一次 vs 小改多次的怨气对比**：常见说法是小改多次的怨气小于一次大改，未核实；两种做法都真实存在。
- **颜值信用与熟练信用**：初见买账靠颜值、长期买账靠熟练——已分立为[美即好用的边界](../美即好用的边界/README.md)（两本账不同时结算的接缝在那里）；与 N 簇「审美与判断」的关系等那簇谈完再定。
- Office 2007 的引导物料形态（对照引导怎么做的细节）没有核查过，只用了"存在且方向有效"这一层。
