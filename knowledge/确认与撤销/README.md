# 确认与撤销

是否打断操作，需要同时考虑错误能否恢复、通常何时才会发现、操作有多频繁。一次确认可以让人核对对象、了解不可逆后果、明确表示同意，或留下必要的操作记录。只有“确定／取消”而没有新增信息的提示，最多能挡住一部分误触。当用户误认了对象，仍可能按下确定。

高频、低后果且错误通常立即可见的操作，直接执行并允许撤销，往往比每次确认省力。前提是产品确实能在给定时间内恢复对象及其相关状态，使用者也有机会发现并撤销。短时提示消失后才会发现的问题，需要其他恢复方式。实现撤销要负担暂存、恢复和并发一致性的成本。

难以恢复、影响他人或范围可能被误解的动作，值得在执行前明确对象、数量和后果。批量操作最好说明“所选 3 项”或“所有匹配条件的记录”。后果很重时，可以要求核对名称或履行审批。额外步骤是否值得，取决于它能防住哪一种错误。用危险色强调后果时，同时检查默认键盘操作会落到哪里。

对照两个看似相同的删除动作。删除一张自己刚插入、能立即恢复的草稿图片，可以直接撤销。永久删除共享资料时，仅重复“是否确定”不能让人核对资料名或受影响的其他人。若文案写“可恢复”，应验证实际恢复能力和期限。
