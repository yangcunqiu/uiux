# 说服页

功能界面回答「怎么完成任务」，官网这类页面回答「为什么选我」。整页都是说服材料的页面——B 端官网、落地页、活动长页——由此拿到一套功能界面没有的许可，也背上一组功能界面没有的失败方式。本条来自一篇用心流理论包装官网方法的微信文章（Q 簇）：理论是贴皮，剥掉之后剩四块可留的判断。

## 先看演示

[打开「布局与节奏」](布局与节奏.html)（双击即可，不需要本地服务）

一个模拟官网，两个开关：

1. **布局三式**：固定版心 / 宽度自适应 / 单屏切换。同一份内容换三种壳。
2. **节奏**：破域（相邻区块轻重交替）/ 一音到底（全页一个亮度）。

观察重点：

- 单屏切换下在内容区快速甩一次滚轮：过不去几屏；固定版心和自适应下，同样的操作能走多远。这就是「不能快速滚动浏览」的现场。
- 固定版心看两侧的空边——「屏效低」就是那两条空白；自适应下内容铺满。
- 一音到底下快速滚到底，再回想「刚才读到哪了」；破域下同样做一遍——明暗交替给了眼睛锚点。

## 一、说服页不是大号的功能界面

评价功能界面，看任务能不能完成；评价说服页，看访客信没信、试没试。目标不同，带来两条对称的差异：

- **许可**：说服页可以做功能界面不做的事——每一屏都在卖、破格排版、装饰性动效（破静）。
- **失败方式**：同质化（没人记住你）与过度差异化（访客迷路、找不到注册入口）。这对矛盾原文点到了，判据在第五节。

原文还有一句自我定位值得记下：官网迭代慢、改动多来自运营调整，所以它本来就不像组件那样容易提炼通用方法。

## 二、叙事顺序：跟访客的疑问走

行业惯例的官网分层是：导航 → 首焦 → 核心优势 → 产品介绍、业务数据、案例佐证、背书 → 免费试用 → footer。它不是唯一排法，但跟访客的疑问顺序同构：

| 区块 | 回答的疑问 |
|---|---|
| 首焦 | 你是谁 |
| 核心优势 | 有什么用、比别人好在哪 |
| 产品 / 数据 / 案例 / 背书 | 凭什么信你 |
| 免费试用 | 怎么试 |

这个结构可检验、也即可反驳：拿真实访客的疑问顺序对照，发现「凭什么信你」排在「有什么用」之前，就该换位。它是行业惯例，不是定律。

## 三、布局三式的取舍

| 布局 | 得到 | 代价 |
|---|---|---|
| 固定版心 | 开发省、适配广 | 屏效低（大屏两侧留白） |
| 宽度自适应 | 屏效高 | 适配机制复杂 |
| 单屏切换 | 沉浸、聚焦、有仪式感 | 不能快速滚动浏览 |

判据接[尺寸与容器](../尺寸与容器/README.md)那句**内容量定布局**：内容少而重（品牌站、单产品页）才敢单屏切换，内容多就自适应。三行各有明确代价，是取舍表，不是风格偏好——每一条都能在演示里直接感受。

## 四、立与破，归属早就分好了

「立」是规范一致：版心、内容密度、色彩字体体系。**立=约束**，有理由可检验的部分照抄即可。

「破」是差异化节奏，原文给了四个变量——**破形**（打破规矩布局，人物与品牌符号结合）、**破色**（相似模块中用强差异色突出重要信息或按钮）、**破域**（相邻区域界限分明、轻重缓急交替）、**破静**（关键区域用动态元素）。**破=调性**，每家自己拨。归属正好落在[约束与调性](../约束与调性/README.md)的两类参数上。

四破里最值一提的是**破域**：官网页面长，一路同一个亮度滚到底，眼睛没有「读到哪了」的锚；相邻区块轻重交替，变化本身就是信息——和[行的边界](../行的边界/README.md)「亮度表程度、色相表性质」是同一思路。

## 五、判据：差异化花在形式，不花在通道

（推论，讨论中认可）差异化可以随便花在**形式**上——破形、破色、破域、破静；**通道**保持通用——注册入口、导航、滚动方向，这些访客赖以行动的东西。

理由同[改动的代价](../改动的代价/README.md)：通道是习惯资产，而且绑在平台惯例那一层——分层表里最深的。通道一旦不通用，访客得先把「这一站怎么用」学会，才能开始看内容；而官网的停留按秒算，没人打算先学。

## 六、转化收口：两件老结论的复用

1. **CTA 文案要具体**：「注册」「免费试用」优于「提交服务申请」——含义宽泛的动词把「按下去会发生什么」丢回给访客猜。这是[一条主路](../一条主路/README.md)文案分寸的原文场景：写动作、有对象。
2. **注册表单压到最少字段**：原文举的 Teambition 与 Miro 都只外露一个必填项，点 CTA 直接进入转化流程。这是[表单骨架](../表单骨架/README.md)和[提交边界](../提交边界/README.md)的老结论——事务越短越好——在官网收口的复用。

## 七、心流的用法：骨架可以，证据不行

原文用 Csikszentmihalyi 的心流理论当整篇框架：条件因素→信息分层 + CTA，体验因素→立破 + 微交互，结果因素→降低注册门槛。两条判断：

- **模型是借的**：心流为「技能×挑战」的活动设计（攀岩、游戏），浏览官网没有「挑战难度」这根轴；原文引的八区模型（焦虑、厌倦……）没有推出任何一个具体设计决定，是装饰。
- **建议要单独评估**：剥掉心流，上面六节每一条都能独立成立或被反驳。借来的理论当叙事骨架可以、当建议的证据不行——和[感受与论据](../感受与论据/README.md)同构：感受可以是选择的原因，不能冒充论据。

## 为什么这样判断

- 「说服页 vs 功能界面」按回答的问题区分，区分可操作：拿它检查任何一段页面该用哪套许可。
- 叙事顺序的可信度来自「跟疑问同构」这个可反驳的结构，不来自心流；原文自己的分层就是例证。
- 三布局每行有明确代价；「内容量定布局」直接接[尺寸与容器](../尺寸与容器/README.md)，不是新结论。
- 立与破的归属是现成框架（约束与调性）的套用；破域与[行的边界](../行的边界/README.md)同思路。
- 「形式不花在通道」是推论：从「通道是习惯资产」推出的条件句，讨论中认可，没有找过反例（见「还没定」）。
- 心流两条来自原文自身结构：八区图与任何设计决定之间没有推导关系，这是文中可指认的事实。

## 适用条件和取舍

- 适用于 B 端官网、落地页、活动长页；不适用于把这套许可搬进功能界面——后台首屏不该每一屏都在卖。
- 单屏切换的沉浸换不来快速浏览：内容多、需要扫读的页面别用，这条换不来。
- 「形式随便破」的前提是通道通用；如果产品卖点本身就是交互形式（创意工具拿官网当作品集），通道要为它让出多大的口子，没有讨论。
- 原文给 CTA 加「渐变、圆角质感」只有一句，不成判断，见「还没定」。

## 稳定性

| 内容 | 稳定性 | 写法 |
|---|---|---|
| 说服页回答「为什么选我」 | 定义 | 写死 |
| 叙事顺序跟疑问走 | 行业惯例 | 默认起点，可按真实疑问顺序反驳重排 |
| 三布局取舍表 | 定义性取舍 | 写死；选哪个随内容量 |
| 立=约束、破=调性 | 框架套用 | 写死（框架来自约束与调性） |
| 四破的变量清单 | 默认 | 可增减；每破单独评估 |
| 破域给长页面节奏 | 默认 | 官网类长页尤其需要 |
| 形式不花在通道 | 推论 | 条件句；反例未找 |
| 心流当骨架不当证据 | 方法 | 写死 |
| CTA 文案具体、表单压字段 | 默认 | 老结论复用 |

## 还没定

- 「通道不通用却成了」的反例没有找过（强滚动叙事把常规导航改掉的站）；判据目前只有习惯资产这条推理支持。
- 破静的动效什么情况下分心大于加分，没有判据；[一条主路](../一条主路/README.md)留给 Q 簇的渐变、弥散投影这类装饰，本次两篇文章只有 CTA 质感一句，不成结论，交接仍留着。
- 单屏切换在多少内容量以下成立，只有方向（内容少而重），没有可操作的阈值。
- 官网内容与功能内容的过渡（官网里嵌 demo、文档区算哪套许可），没有讨论。
