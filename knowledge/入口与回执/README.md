# 入口与回执

同一个触发器，命令菜单承诺"这里有东西可以做"，值选择器承诺"现在是什么"。前者是入口，后者是回执。入口写什么、回执写什么，规则从这里分开。

## 先看演示

[入口与回执](入口与回执.html)（双击打开，不需要本地服务）

上半：五个动作（导出 CSV、复制链接、打印、归档、删除）藏在一个"更多"后面，切换四种入口写法——只有图标 ⋯ / 写类别 / 类别 + 数量 / 全部摊开。关着时回答两个问题：有几个动作、有哪几个。

下半：三个筛选条件（待审核、已超时、我负责的）藏在"筛选"后面，切换三种写法——只写「筛选」/ 写数量 / 数量 + 条件。

观察重点：

1. "只有图标"那一版，连"有几个动作"都答不了——不是答错，是没有可答的信息。
2. "写类别"进了一步：知道有东西，仍不知道几个、哪些。
3. "类别 + 数量"能答"几个"，仍答不了"哪些"。数量不是内容。
4. 下半同理：只写「筛选」时两问都答不了；写数量能答第一个；只有把条件写出来，第二个才成立。
5. 每组底部"此刻屏幕上能看到几个"是实测：点开浮层会变多，关掉又归零——信息不是不存在，只是要再取一次。

## 我们的理解

**两种职责。** 命令菜单的触发器是**入口**：它宣布"这里有东西可以做"。值选择器（以及开关型命令，比如加粗、显示网格）的触发器是**回执**：它宣布"现在是什么"。

- 入口要认得出来：文字优先于图标，类别名优先于无字。
- 回执要写值：不能只写字段名；没有值时写"请选择"，不能假装有值。
- 例外是开关型命令：它本身有"当前"，触发器是回执，不是入口。

**图标单独用的门槛。** 不是"高频"，是三条同时成立：语义通用（不靠旁边的字能读懂动词）、位置说清范围（行内、工具栏、页头，或者选中数）、安全层兜住后果（撤销、确认）。缺哪条补哪条，而不是一律加字：

| 缺什么 | 补什么 |
|---|---|
| 语义不通用（分享、下载、导出） | 加字 |
| 范围说不清（浮动按钮、表头 vs 行内） | 改位置；加字只是遮住问题 |
| 后果重（删除、清空、停用） | 加安全层；低频再加字，因为没机会学 |

频率只决定值不值得占那块地方，不决定能不能只给图标。

**一个附加的例外：入口图标。** "⋯"不是命令图标，它不回答"做什么"，只承诺"这里有东西"。上面三条对它不适用；它只要"有东西可承诺 + 范围清楚 + 打开可逆"。

**随上游变：命令不变，值要变。**

- 命令的位置一变，肌肉记忆就废；能变的是可用性（禁用），要解释原因。
- 值不变才是 bug：选了省，城市还是全国的。值随上游变要满足两条——变化的原因在屏幕上（上游字段可见），旧值失效有交代（清空并提示，或者保留并标出来）。

**层级不是层数。** 限制菜单深浅的不是"最多两层"，是两个变量：

- **返回路径**：能不能一步退回。级联选择器有三层，但每层都能直接退回，并不难用；Figma 某些菜单有四层，退回去要重走一遍。
- **打开方式**：hover 打开没有状态，手一斜就没了；click 打开有状态，失手再点一下。

所以 hover 只适合"一步、目标宽、不需要在子层里操作"的菜单；带子层的用 click，或者 hover 打开 + 点击锁定。只靠 hover 的入口，触摸端可能打不开；[WCAG 1.4.13](https://www.w3.org/WAI/WCAG22/Understanding/content-on-hover-or-focus.html) 还要求悬停出现的内容可关闭、可悬停、可持久。

**批量命令的范围。** 选中数就是范围：

- 摘要和按钮在同一行：按钮写"删除"，摘要写"已选 3 项"。
- 按钮离开摘要（浮动条、吸底、弹窗）：按钮自带范围，"删除 3 项"。
- 跨页、全选：别只给数字，给"哪一批"（"全部 128 条匹配结果"）。数字只回答"几条"，措辞才回答"哪些"。
- 破坏性操作重复一次数字可以接受，是廉价保险；普通操作重复就是噪音。
- 数字会变时注意按钮宽度抖动；等宽数字，或者把数字放进独立徽标。

**多选下拉的 chips。** 把已选值做成 chip 放回触发器，是多选从"数量"升到"内容"的常见做法（Ant Design 的 multiple select、MUI 的 Autocomplete 都是）。代价是四条：

1. 触发器变成两个目标：点空白处开合，点 × 删除。× 不能顺手开合面板。
2. 语义上不能在 button 里套 button；通常做成 `role="combobox"` 的容器，chip 里的 × 是独立 button。
3. 高度随 chip 换行变化，表单跟着位移；值一多只能折成 +N，又回到"只有数量"。
4. 读屏报"已选 3 项"就够，别把三个 chip 的名字串成一句。

删 chip 等于取消勾选，面板里的勾要跟着变。同一个动作两个入口，两边必须一致，否则就是假回执。

**导航是第三种。** 导航菜单装的是"位置"，它的痕是"我在哪"。位置感和信息架构不在本文展开；本文只处理展开之后的可见性这一层。

## 为什么这样判断

- 触发器的职责不同，它该写的东西就不同。把两者混在一起，就会出现"下拉要不要带当前值""图标能不能单独用"这类没有答案的问题。
- 图标猜错一次，用户就不再点了，正好撞上代价最大的那一级（不知道有）。
- 级联不是"选项随机变"：变的是候选域，功能就是这个；要管的是可解释性和旧值。
- 层级：返回成本和打开方式是变量，层数是影子。Figma 四层菜单的行为是外部观察，级联的例子是推论。
- 批量：用户在工具栏上只能看到摘要和按钮，看不到表格里勾了谁。
- 多选 chips：触发器装不下 N 个值，这是空间事实；不能嵌套 button 是 HTML 的内容模型。

## 适用条件和取舍

- 图标的结论依赖"本产品内用法一致"。跨产品约定不一的图标（分享、下载、导出）要带字。
- "命令不变"有例外：权限导致不可用时保留 + 说明；永远不可用才隐藏。
- 多选 chips 适合值少（3–5 个以内）且需要核对（筛选、收件人）；值多或选完就走，退回"已选 3 项"更省地方；值很长时把 chips 放到触发器外面。
- 触发器里的 chips 和列表里置顶的当前值，是同一个回执的关着/打开两个时刻，可以都留；同一时刻别重复两遍。
- 弹层往哪翻、多宽，在[边界上的弹层](../边界上的弹层/README.md)；选择控件的语义在[承诺与边界](../承诺与边界/README.md)。
- 留痕分级（无痕/数量/内容/全露）在[藏起来的代价](../藏起来的代价/README.md)。

## 例子

- **工具栏**：⋯ / 更多操作 / 更多操作 5 / 五个动作全摊开。前三种是入口的不同程度，最后一种才升到"内容"。
- **省份 → 城市**：上游变，下游清空并提示；旧值不能悄悄留着。
- **批量删除**：摘要"已选 3 项" + 按钮"删除"；跨页时写"删除全部 128 条匹配结果"。
- **收件人选择**：触发器里放 chips，删一个等于取消勾选。

## 还没定

- "通用"图标的判定没有清单，只有"跨产品同一含义"这个方向；本产品内的用法一致性也没有检查方法。
- hover 菜单的延迟和安全路径（避免手斜着走时误关）没有实测参数。
- 多选 chips 的键盘顺序与读屏文案，还没有展开。
- "把最高频的一两个动作摊开"只有经验值，没有阈值。
