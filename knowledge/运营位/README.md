# 运营位

运营内容嵌进功能页，最常被问的是「做成什么样」。更靠前的问题是「占多大、以多大音量出现」。本条来自一篇 banner 四分类的文章（Q 簇）：四类位置并列着摆，拆开看是两个更结构的问题——广告位跟界面框架怎么划界、在内容流里用什么音量说话。

## 先看演示

[打开「划界与音量」](划界与音量.html)（双击即可，不需要本地服务）

一个模拟首页，两组开关：

1. **划界三式**：通栏 / 齐屏 / 卡片——顶部运营位跟状态栏、导航栏（界面固定件，行业俗称 chrome）怎么划界。
2. **画面深浅**：通栏下把画面换浅，看导航内容还读不读得出来。

下半是同一内容流里的两种音量：白底 banner（组件化的安静位）与胶囊 banner（大声的促销位），都带演示标注。

观察重点：

- 通栏 + 浅色画面：顶部「首页」和两个图标是白的、压在浅色画面上——还分得清吗？切回深色画面再对比。
- 卡片式：页面背景被 banner 主色淡淡染色，融合好了——banner 本身还聚焦吗？
- 白底与胶囊都在内容流里：哪种你会当广告扫过，哪种会多看一眼？

## 一、先分广告还是内容

文章把四种 banner 并列（顶部、白底、胶囊、封面），但它们不是一类东西：

- **顶部、白底、胶囊是广告位**：嵌在功能页里的运营内容，为转化服务。
- **封面 banner 是内容自己的脸**：文章封面、课程封面，为表达内容主题服务，不是广告，不适用本条的任何一条判断。

分错这一层，后面全是样式问题；分对了，广告位才谈得上位置和音量。

## 二、顶部三式：跟 chrome 划界

| 式 | 怎么划界 | 得到 | 代价 |
|---|---|---|---|
| 通栏 | 画面吞掉 chrome，一直铺到状态栏底下 | 整体感最强，不用给导航另留空间 | 导航内容压在画面上，画面一浅就没了可读性 |
| 齐屏 | chrome 归 chrome，色块分界 | 上下内容区分清楚 | 中规中矩，做不出新意 |
| 卡片 | 缩进让出框架，页面背景随 banner 主色染色 | 颜色不受限、尺寸小、融合统一 | 背景和 banner 区分不开时，视觉不聚焦 |

三式没有高下，只有「接管多少」的差别：通栏是运营内容接管第一屏的极限，卡片把它降为内容流里的一块。通栏的代价是结构性的——不是「不好看」，是导航可读性押在画面颜色上（演示里换浅色画面可复现）。

## 三、内容流里的音量

中部运营位两档典型：

- **白底 banner**：左文右图，文字为主、图片为辅，做成组件换字换图复用。**安静**，代价是不显眼。
- **胶囊 banner**：节点性促销，颜色鲜艳、元素丰富、造型可以带品牌元素。**大声**，代价是跟整体不融合。

音量跟场合匹配：长期常驻的运营位用白底（大声一次等于吵一年）；节点性活动用胶囊（要的就是这几天的大声）。

## 四、比样式更靠前的两问

原文只教「做成哪种样式」，两件更靠前的事它没问：

1. **该不该占**：运营位占不占、占首屏多大面积，比「通栏还是卡片」先决定。信号：功能内容被挤到首屏之外时，先砍面积，不是先改样式。
2. **能放多久**：更新频率与点击衰减（放久了没人看）没有讨论，见「还没定」。

顺带一个原文自己带过、却最有信息量的信号：淘宝把横版运营位改成竖版、融进产品列表——运营位在往内容流里退、往原生里藏。它是走向信号，不是结论，而且恰好是并列四分类解释不了的：竖版融进列表之后，已经不是「顶部还是白底」这道选择题里的任何一个选项。

## 五、喊与克制

banner 是功能页里的**喊**：大声、主动、目标是转化的那一刻。喊靠克制活着——运营位多了、久了，用户会练出 banner 盲（扫过不看）。和[徽标的账](../徽标的账/README.md)对照着读：徽标是界面里的**碰你一下**，小声、被动、目标是别漏掉该处理的事。两者失效的机制相同——提醒的密度上去，单条提醒的价值就下来。

## 为什么这样判断

- 「广告还是内容」这一刀来自对封面 banner 的语义检查：它回答内容主题，不回答转化，跟另外三类不同类。
- 划界三式和音量两档是对原文位置分类的重新组织（原文并列四类、每类配优缺点），拆法按「跟 chrome 的关系」和「在内容流的音量」两个可检验的问题来。
- 通栏的导航可读性代价是结构事实：演示里换浅色画面可复现，不依赖品味。
- 淘宝竖版一例是原文顺嘴提及的少数案例，只当走向信号用。
- 六种画面类型（人物、场景、元素、文字图形、实物、插画）是素材清单，只回答「有哪几种」、回答不了「什么时候用哪种」，没有纳入。

## 适用条件和取舍

- 适用于功能页里嵌运营位的产品（App 首页、活动页的运营区）；不适用于纯内容产品的分发位（那是推荐系统的问题，不是 banner 的）。
- 白底组件化换的是「运营每期只改文案图片」的低成本，前提是运营节奏稳定；节奏不定的位置，组件化会空转。
- 通栏把导航可读性押在画面颜色上，要么给画面立约束（深色基准、给导航加衬底），要么别用通栏。
- 封面 banner 不适用本条；它是内容，按内容的规则做。

## 稳定性

| 内容 | 稳定性 | 写法 |
|---|---|---|
| 广告位与封面内容的分界 | 定义 | 写死 |
| 划界三式及其代价 | 定义 | 写死；新式样按同一问归位 |
| 音量两档（安静 / 大声） | 默认 | 可加中间档；判据是「吵多久」 |
| 通栏要押画面可读性 | 定义 | 写死；约束方式项目自定 |
| 该不该占、占多大 | 条件 | 写信号，不写面积数值 |
| 竖版融入内容流 | 信号 | 只记录走向，不定论 |
| 六类画面类型 | 不沉淀 | 素材清单 |

## 还没定

- 运营位的更新频率与点击衰减（同一位置放多久开始没人看）没有讨论。
- 六类画面类型不纳入；其中「文字图形」（排版即画面）可能是独立问题的入口，本次决定不展开。
- 白底 banner 的轮播与单张取舍，没有讨论。
- B 端后台顶部的公告条算不算运营位、按哪一档音量，没有展开。
