# 知识目录

这里保存讨论后决定留下的知识。每个主题围绕一个能独立理解的问题展开，可以是概念解释、设计原则、规范辨析、审美判断或取舍方法。先看演示，再读原因和适用条件。

下面的分类是阅读入口，不是必须创建的实体目录。新增主题后，在相应分类下添加主题链接和一句话介绍；主题说明中再链接具体演示。

## 概念与判断

术语、标准与经验的区别、设计评价、研究与验证方法。

- [拆组件](拆组件/README.md)：一组用来拆组件的问题、两条判据、一个动作区分，以及状态、层级和运动的取舍。
- [拟真](拟真/README.md)：一条规律、几条线索；材质是线索的组合，不够像时先数线索再调参数。
- [换皮与换规则](换皮与换规则/README.md)：结果、模式、想法三层；规则管关系；改掉它还是不是同一件，决定它是皮还是魂。

## 视觉与信息组织

视觉分组、信息层级、排版、颜色、布局、信息密度。

- [圆上的首尾](圆上的首尾/README.md)：等分的是什么、缺口由谁认领、渐变端点补在哪；读与看是一道门，不是一条轴。
- [选项行](选项行/README.md)：对齐的是被标记的东西；描述、图标、数量、图像各自的位置；行里的第二个目标与 Tab 成本。
- [拟真](拟真/README.md)：玻璃的三条线索与材质配方表；位移图只服务折射。

## 操作与反馈

选择、输入、状态表达、防错与恢复。

- [拆组件](拆组件/README.md)：字段语义、空状态的原因、动作的放置、禁用与说明文字。
- [承诺与边界](承诺与边界/README.md)：控件只该宣布一件承诺；宣布与解释不一致又看不出来时，用户会按一套行动、系统按另一套记账。含选择控件、半选级联与标签。
- [选项行](选项行/README.md)：整行可点与图标按钮的结构；span 会顺手切换勾选，button 放在 label 外不会；每个按钮多一个 Tab 停留点。
- [点击之后](点击之后/README.md)：一次点击的三个时刻；悬停和按下走不同通道；蓄力属于按下；交接要重合不要藏。
- [边界上的弹层](边界上的弹层/README.md)：三个功能对应三种失败；方向、横向、尺寸是不可替代的自由度；对话框的出现缩放与先缩后滚。

等待、过渡、变化的连续性、运动节奏。

## 主题与演示的组织

主题目录先平铺在 knowledge 下，按问题或主题命名。一个主题可以包含几个紧密相关的知识点，并配一个或多个演示；概念和方法类主题可以使用图解或案例，不强制创建 HTML。

简单主题采用以下结构，其中名称是示意，不代表已经存在的知识条目：

```text
knowledge/
└── 主题名称/
    ├── README.md
    └── demo.html
```

多个演示按各自观察的问题命名，样式、脚本和必要资源按需保存在主题目录内。同一问题的参数、状态和例子可以放在一起；当某部分需要独立解释、经常单独引用，或实际解决了另一个问题时，再拆分主题。

同一主题可以出现在多个分类入口，但内容只维护一份。组件可以作为补充查找入口，链接相关主题；通用知识保留在通用主题中，不向每个组件重复复制。分类可随实际内容调整，拆分或移动后同步修正链接。

可观察的视觉和交互主题默认配可运行演示，让读者通过对照、切换或调整参数理解问题。一次比较尽量只改变要研究的因素；演示使用的数值不自动成为推荐值，展示现象也不等于证明普遍规律。

演示优先采用无需构建的 HTML、CSS 和原生 JavaScript。沉淀的页面应可在本地独立运行，不依赖聊天宿主、临时输入或某次会话；正文写清如何打开或预览，以及哪些参数或动作值得观察。

## 写作参考

主题正文通常需要回答：先看什么，我们形成了什么理解，为什么这样判断，以及在什么条件下适用。短条目用几段话即可；内容较多时可以参考下面的结构，按需要取舍。模板中的链接仅在对应演示已经创建后使用。

```markdown
# 问题或主题

## 先看演示

[打开演示](demo.html)

说明运行方式、观察重点和可以操作的内容。概念类主题可以在这里放图解或案例。

## 我们的理解

用一段话说明结论，并在必要时指出它是经验建议、标准要求或风格偏好。

## 为什么这样判断

解释理由和推导，保留影响结论的条件。

## 适用条件和取舍

说明何时有帮助、付出什么代价，以及已知的例外或反例。

## 例子

补充有助于理解的例子或反例，与上方演示相互参照。
```

只有具体结论需要核查时才在相关段落附必要出处，不要求单独的来源章节。临时材料删掉后，知识说明和演示应当仍然完整可用。AI 的维护约定见 [协作规则](../AGENTS.md)。
