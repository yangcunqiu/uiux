# 按任务查找设计知识

新功能在定方案前使用本页，已有功能按同样的条件审查。先明确目标使用者、任务、支持环境和已经约定的业务结果，再判断哪些条目适用。入口按行为组织，同一问题可以跨越几个主题。

## 共同条件

- **信息可辨认。** 在支持的使用条件下，完成任务所需的信息和状态应能辨认。例如要核对当前对象时，滚动后仍需有可用线索。审查应说明哪一项信息在什么条件下丢失。
- **操作可完成。** 对约定支持的设备和输入方式，必要动作要有可到达的路径。例如窄窗口的菜单裁掉了唯一的确认入口，就应修复可达性。哪一种容器或视觉样式能解决它，可以由项目选择。
- **显示与实际行为一致。** 界面所表达的对象、作用范围、生效时机和结果应与系统行为相符。请求已受理、业务已完成和结果尚未确认，需要按实际状态区分。用户能否恢复或撤销，取决于项目明确提供的能力。

文中的“作用范围”指一次操作会影响哪些对象或字段，“生效时机”指改动何时实际改变业务状态。界面写了什么可以直接观察，用户怎样理解需要证据，系统保证什么要对照真实行为或接口约定。

定义用于辨认概念。适用的标准及可复现的失败可以作为验收依据。条件性建议说明收益和代价，默认做法允许在前提改变时调整。项目约定的风格在该项目内可以成为要求。对使用者行为的预测在获得相应证据前应保留为推测。
