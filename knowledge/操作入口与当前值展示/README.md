# 操作入口与当前值展示

收起一组选项或操作能节省空间，也会改变用户在打开之前能知道什么。需要分别考虑入口是否可辨认、有哪些选择、哪些内容需要并排比较、当前值是什么。只有任务实际需要的信息才值得常驻。判断隐藏的代价时，看用户能否找回、需要反复查看几次，以及据此判断错误会有什么后果。

## 命令与选择器

“更多操作”打开后提供命令，关闭时至少要能认出入口和作用对象。“通知渠道”打开后选择一个值，关闭时应能读出已选择什么。尚未选择可以显示“未选择”。加粗、显示网格等命令兼有开关状态，入口也要显示当前是否启用。导航菜单所显示的当前位置另见[当前位置与返回路径](../当前位置与返回路径/README.md)。

单独使用一个命令图标，取决于使用者是否能辨认动作、位置能否说明作用范围，以及误操作的后果是否得到处理。一个不熟悉的“导出”图标可以补上文字，范围不清的行级操作应放回对应行。悬停提示适合补充全名或快捷键，使用者先要找到图标才会看到它。“更多”图标只负责打开一个可退出的菜单，入口所在位置应说明它属于哪一个对象。

命令的位置尽量稳定。条件暂时不满足时可以保留位置并说明原因。选择值则跟随业务依赖变化，例如省份改变后要更新可选城市，并交代原先选择的城市是否仍有效。

## 关闭面板后还需要核对什么

用户只需知道筛选已经启用时，“已选 5 项”可以满足要求。需要核对哪些条件正在影响结果时，应显示名称或可展开的摘要。只列前三项时附“另有 2 项”，能够避免把部分内容读成完整集合。省略号也能提示截断，但提示效果依赖其位置和可辨认程度。显示全部内容便于比较，会占用更多空间。

当筛选面板有“应用”按钮时，面板外的摘要对应**已生效条件**，面板内的勾选可以是**尚未应用的草稿**。若支持从摘要删除条件，列表、数量以及面板内对应选项要按各自的生效时机更新。用可删除标签显示多个值时，打开面板和删除标签需要两个独立的操作目标。换行会推动下面的内容，收成数量则会减少可核对的信息。

多层菜单的操作成本取决于返回上一级是否方便、指针能否顺利进入子菜单。仅靠悬停的多层入口容易在横移时消失，触摸设备也缺少悬停。需要在子层操作时，可点击打开或点击后保持展开。采用 WCAG 2.2 时，对因悬停或键盘焦点而出现的附加内容，应按条款核对可关闭、可移入和可保持显示的条件及例外。[WCAG 2.2，1.4.13](https://www.w3.org/WAI/WCAG22/Understanding/content-on-hover-or-focus.html)
