# 列表空状态与不可用操作

列表没有显示任何记录，可能是尚未加载、确实没有对象、当前筛选无匹配、没有查看权限或加载失败。它们可以有相似的版面，但使用者接下来能做的事不同。请求尚未返回时显示“暂无记录”，可能使人按“确实没有”采取行动。

| 已知原因 | 能据此提供的说明或动作 |
|---|---|
| 正在读取 | 表明仍在加载，保留必要的上下文。 |
| 确实还没有对象 | 解释这里将显示什么。在角色有权创建时可提供新建、导入、模板等合适的起步方式。 |
| 没有匹配项 | 显示起作用的筛选条件，允许调整或清除。 |
| 没有查看权限 | 在允许披露的范围内说明权限或申请途径。 |
| 加载失败 | 说明本次获取失败，提供重试或可行的恢复路径。 |

同一角色、同一业务上下文中，新建等页面操作应在有数据和无数据时都能找到。行内的“新建版本”则只作用于该行，可以随对象出现。进入窄屏布局后可以变换位置。重试或清除筛选只在其原因存在时出现。空状态里另放“从模板创建”，可能提供了一条不同的起步路径。如果工具栏已经有同样可见的“新建”，再给同等强调的入口只会增加辨别成本。在抽屉或窄窗口里原入口不可达时，可以就近提供入口。

## 不可用的原因与说明

权限不足、填写条件不足、系统正在处理，分别要求申请权限、补充条件或等待。若需要用户修正数据，保留可操作入口并显示错误，往往比一个灰色按钮更能指向问题。必须禁用时，将原因放在仍能看到和到达的位置。不要让可用的次要按钮和不可用的主要按钮只能靠尝试点击来区分。

文字提供业务规则、后果或当前状态时有独立价值。如果一段说明只是反复解释一个图标或按钮是什么意思，优先改善名称、位置和状态表达。一个筛选字段也应表达同一种含义，例如任务处理状态与负责人分别变化，可分别筛选，或用具名视图组合。将“我”写入处理状态，会使权限、归属与进度难以独立解释。来源及变化方式确实相同时，继续拆分只会增加操作。
