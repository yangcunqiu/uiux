# 按下反馈与点击动效

一次离散操作有按下、按住、释放几个时刻。悬停或焦点说明当前目标，按下说明输入已被接收，释放后的变化表明这次操作造成的结果。在有持续按住阶段的按钮上，等到最终点击事件才给出反馈，会使按住期间的状态无法辨认。触摸输入没有可靠的预先悬停，键盘激活的时机也要按实际控件检查。

悬停可以用边框或底色，按下可以用轻微位移或形变。指针按下时两种状态可同时存在，要能分辨。行和行内复选框同时改变按下外观，会使实际操作对象含糊。目标足够清楚或动作极短时，提示可以很轻，甚至让按下与结果共用一次变化。不可把键盘定位和主要结果完全依托于悬停或运动。

## 长按、形变与结果位置

若持续时间是输入的一部分，例如录音时长、持续累积的强度，就在按住期间显示随时间增长的量，松开时使用已经取得的值。普通点赞或一人一票不随按住时间增加结果。增加一段必等的蓄力会拖慢主任务。若仅作低频活动的表现手法，应由该场景承担等待成本。

用动画表现一个物体从按钮飞往计数区时，按下时变形的图形与飞行的图形应在交接处对应。出发位置、初始大小和颜色突然改变，会出现两个不连续的对象。结果就在按钮原位时，原位的状态更新可能已足够。结果在远处且需要说明因果时，移动轨迹可将来源与结果关联起来。动画期间仍应准确反映输入及业务状态。

等待应按用途判断。为了区分路过与停留的短延迟，可在同一组连续浏览中复用。为了讲述先后关系的间隔，移除后可能看不懂发生了什么。为了使远处结果与移动到达同步的时序，也不能随意反转因果。进入减速、退出加速是一种平台动效惯例。连续拖动、返回原处或碰撞等事件各有自己的运动含义。[Material 的时长与曲线指引](https://m1.material.io/motion/duration-easing.html)

操作过程中同步发生的运动、输入结束后的短结果反馈、需要等完才能继续的表演，对任务时间的影响不同。在低频、空间关系清楚的表现性界面里，后一物体的接触可以说明前一物体为什么改变。高频阅读或操作中反复播放同样的过程，则会持续增加等待。
