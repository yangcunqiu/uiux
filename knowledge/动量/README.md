# 动量

动效里的「动量」是个容易被说混的词。这一篇管三件事：**能量从哪来**（用户给的还是作者排的）、**时间记在谁账上**（操作进行中还是等表演结束）、**怎么验收**。机制层面（落后量、弹簧、两个跟随点）在[跟手与平滑](../跟手与平滑/README.md)，不在这里重复。

## 先看演示

[打开「回弹的边界」](回弹边界.html)（双击即可；`回弹边界.js` 放同目录）

十个标签、指示器滑动。四档时长 × 四条回弹规则（从不／总是／距离>350px／速度>1080px/s），每次切换的读数条显示距离、速度和两条规则的判定。观察任务在页面里，核心是分辨格：同一距离不同时长、同一时长不同距离，看你「赚到的回弹」（读成帮落点）的边界跟哪条规则重合。

我们讨论中实测过一次：边界跟**距离**走——低速长距仍要弹。你可以再验，特别是换一块屏幕之后（推导的前提变了，见第六节）。

## 我们的理解

### 一、边界：能量源 × 时间账

先收回一个武断说法：「工具型不要动量」。它和语料直接冲突——AD UI 本身是 B 端设计语言，里面就有物理曲线、错误回弹、350px 阈值；滚动惯性更是所有工具的基础。正确的边界不在产品类型，在两根轴：

| 类型 | 能量源与时间账 | 例子 | 工具能用吗 |
|---|---|---|---|
| 结算型 | 动在输入上，不占任务时间 | 滚动惯性、拖拽跟随、甩卡 | 能，且该有——不改任务时长只改手感 |
| 结果型 | 输入后的短反馈，替操作记账 | 错误回弹、落位确认、拒绝抖动 | 能——作者的动作，但短 |
| 表演型 | 输入后的长演出，额外占时间 | 蓄力后的爆散、生成仪式、入场叙事 | 主要留给体验场景；工具里按频次收税 |

验收三条：

1. **操作停，动量停得住吗**（可打断）——停不住的是表演。
2. **操作变快，响应跟着变吗**（成比例）——不变的是修饰。
3. **这个动量花的时间，记在操作进行中，还是等表演结束？**

「有趣」由此有两个切片：**活动从丰富里拿有趣，工具从精确与比例里拿有趣**——像手的延伸，而不是像一段演出。

### 二、事件结算状态变化

状态变化有两种结算方式：**淡出说「时间过了」，撞击说「它被碰了」**——后者给变化一个看得见的施动者，读的人能归因。

案例：确认页静态版失败（高亮文字抢按钮注意力、气泡误导可点），修法是下一个气泡从下往上撞、前一个被撞「褪色」，有节奏地引出最后的按钮——「弹」有意义。

条件三件：变化需要归因（用户需要知道为什么它变了）、低频一次性、空间可排（相邻才能撞）。**高频状态变化用计时器／淡出是对的**——事件结算贵，每次都付不起。验收：去掉撞击改纯淡出，用户还能不能说出「它为什么变了」；说不出的场合就用便宜的。

### 三、蓄力：时间作为输入

蓄力不是表演型：**它是结算型，输入维度是时间**——积累发生在按住期间，松开只是消费。

由此发现性问题自己解掉：不靠事前提示，靠蓄力自身的反馈——按住时氛围元素加速旋转，按住半秒内屏幕上有随时间增长的量，用户当场学到「按住有东西」。验收一句话：**按住 500ms，屏幕上有没有随时间增长的量？**没有，蓄力就是暗门。

代价：time-to-result 变长（松开前要等），所以只适合低频／游戏式；工具高频里蓄力＝每次操作收时间税。

### 四、在读的时刻，信息优先于风格

文字与气泡的风格尝试（旋转进入、容器变形、扫光、错落进入）在入场里全部被否——**修饰分散了对文字内容的注意力**。有趣的分工是：**风格层管物体长什么样，动量层管对操作的响应**——有趣来自响应，不来自修饰。

与[入场](../入场/README.md)的分工：入场管拍数（工序兑换），这条管**拍内谁让位**。确认页静态失败是双层证据：高亮抢了按钮的注意力（读的时刻信息让位错了对象），气泡误导可点（示能说谎）。

### 五、否定判据：什么时候动量是负的

一个被作者自己标为「不适合上线」的效果给出三条否定判据：

1. **打扰**——拖慢了浏览；
2. **低效**——让用户多付操作；
3. **多余**——效果与任务无关。

三条全过＝装饰动量，再好看也不上。正面对照：近 300 个动效属性的年度活动能立住，靠的是**全部拴在操作上**＋一年一次两分钟的时间账——丰富本身不是问题，没拴住才是。

### 六、审计一个推导出来的值：350px

「长距离切换用回弹曲线」的 350px 阈值，按[约束与调性](../约束与调性/README.md)的参数两类放不进任何一格——它是第三种：**锚定推导的经验值**。推导每步可复算（不是拍脑袋），映射未验（不是定律）。

- **推导链**（原文）：21.5″ 1080p → PPI 102.46 → 50cm 视距 → 中心视野 10° → 8.75cm → ≈350px。复算结果 353px（原文写 354.5，差约 1.5px，取整后无妨）。
- **前提全是约定快照**：21.5″ 1080p（设备快照）、50cm（坐姿典型值）、10°（中心视野定义之一，弱源；定义空间 5°~30° → 阈值软 2–3 倍，数量级稳）。
- **代理**：中心视野＝注意力跨度。**映射**（超出注意力跨度 → 要回弹）经一次演示对照成立——弱肯定：一人一次，定方向、不当定律；机制故事（为什么超出要回弹）未验。
- **换设备重算，不抄 350**：27″ 4K ≈560px、14″ 笔记本 ≈430px。
- **被否的探针**：固定时长下距离是速度的完美代理（350px@250ms=1400px/s），速度假说（平滑追踪 ~30°/s ≈1080px/s）在同一观察里被否——低速长距仍要弹。探针保留在演示里可再验。

这一节的方法价值大于数值：拿到一个推导出来的阈值，审计顺序是**复算算术 → 盘点前提 → 指认代理 → 分辨混淆 → 换设备重算**，五步都便宜。

## 为什么这样判断

- 三类边界是讨论中被用户质疑（「工具型不要动量太武断」）后、由语料冲突（AD UI 自带物理曲线）调解出来的；判据三条都可操作。
- 事件结算、蓄力、信息优先均来自 2025 篇案例；「淡出／撞击」「时间作为输入」是归纳的提法，非原文原话。
- 否定判据来自 11 周年作者对自家效果的自标（「不适合活动」），属案例自评。
- 350px 的算术全部复算过；验收是一次分辨格子演示对照（一人），诚实标注弱肯定。

## 适用条件和取舍

- 三类边界的判据用在「要不要这个动效」的决策时刻；表演型的频次账在活动里宽松、在工具里严。
- 事件结算要求空间可排；布局上不相邻的元素付不起这个成本。
- 蓄力只适合低频；「按住确认」这类安全场景是否算蓄力、和提交中锁定怎么分界，没有讨论（见还没定）。
- 信息优先只管「在读的时刻」；操作后的反馈时刻不受此限（那时响应本身就是信息）。
- 350px 及其推导是桌面端、固定视距语境的值；移动端手持距离、PPI 都不同，重算而不是缩小。

## 稳定性

| 内容 | 稳定性 | 写法 |
|---|---|---|
| 三类边界与三条判据 | 判断 | 语料+调解，可增减 |
| 「有趣」两个切片 | 判断 | 随边界走 |
| 事件结算（淡出/撞击） | 判断 | 一案例+归纳提法；高频例外明确 |
| 蓄力＝时间作为输入 | 判断 | 验收可操作 |
| 信息优先（读的时刻） | 判断 | 案例支持 |
| 三条否定判据 | 默认 | 案例自评，可增 |
| 350px | 锚定推导的经验值 | 前提重算；映射一人验证 |
| 1080px/s 速度探针 | 被否的探针 | 保留可再验，不写为规则 |
| 审计五步 | 方法 | 写死 |
| 演示数值（90px、时长档位） | 演示值 | 不是推荐值 |

## 还没定

- 350px 的机制故事（为什么超出注意力跨度要回弹——注意力重捕获？）未验。
- 换设备的重推测试没做：换屏后感知边界跟不跟重算值走。
- 事件结算与计时器淡出的成本差，没有量化口径。
- 蓄力与「提交中只能收起、不能放弃」（[关闭的承诺](../关闭的承诺/README.md)）在按住类操作上怎么分界，没有讨论。
