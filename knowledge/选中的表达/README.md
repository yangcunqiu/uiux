# 选中的表达

选中态怎么让人看见，有两层：静态的形状和颜色，动态的过渡。这一篇只谈显示——选中意味着什么、什么时候算数，在[承诺与边界](../承诺与边界/README.md)。

## 先看演示

[打开演示](选中的表达.html)（双击即可，不需要本地服务）

上半部分三组胶囊：A 只靠颜色，B 颜色 + 勾，C 描边 + 勾。顶部可以「去掉颜色」。
下半部分是开关和复选：时长滑块（0–800ms）、快速切换 9 次、模拟减少动态效果。

观察重点：

1. 去掉颜色后，A 的两个胶囊一模一样；B、C 还靠勾分得开。
2. 时长 0ms 时状态和视觉同时到位；150ms 左右顺且跟手；600ms 时状态已变，视觉还在路上。
3. 快速切换 9 次：状态每次都变了，视觉一直在后面追。
4. 勾上「模拟减少动态效果」，状态照样清楚。
5. 读数分成「状态」和「视觉」：状态是值，视觉是显示。

「去掉颜色」不是色盲模拟，它只回答一个问题：把颜色这一层拿掉，还剩什么。

## 颜色是加强，不是载体

- 只靠颜色不是一律错：明度差足够时，很多人看得见。但它不稳定——主题、屏幕、色觉差异，都会让那点色差消失或变弱。
- WCAG 1.4.1（A）：颜色不能是唯一手段。WCAG 1.4.11（AA）：控件本身的对比度至少 3:1。
- 静态测试：截图、去掉颜色，还能分出选中吗？能，才算过。

形状层的可靠度：

| 形状层 | 可靠度 | 代价 |
|---|---|---|
| 勾 / 点 | 强：符号，有学过的含义 | 要位置；小尺寸要清晰 |
| 填充 vs 描边 | 中：是形状差，但依赖对比度 | 深浅主题都要调 |
| 边框粗细 | 弱：小尺寸难辨 | 会改变尺寸 |
| 文字加粗 | 弱：改变宽度 | 布局会动 |

状态之间要分得开：hover、focus、selected、disabled。如果 hover 和 selected 用同一个浅色底，勾就是那条分界线。

暗色和高对比模式：勾最好用 `currentColor` 或边框画，别依赖自定义填充色——强制颜色模式会覆盖你的色值。

## 动效是反馈，不是信息

动效在选中态里做三件事：确认输入被收到、表达方向（滑块往哪边滑、点从中心长出来）、让变化连续。

关键是把它和状态分开：**状态在点下时已经成立，动效只是显示在追。** 演示里的读数分成两条：状态是值，视觉是显示。时长 600ms 时，状态已经「开」，视觉还写着「还在动」。

时长是手感问题，不是规则：

| 时长 | 手感 |
|---|---|
| 0ms | 状态和视觉同时到位，干脆，但没有「被收到」的反馈 |
| 150ms 左右 | 顺，仍然跟手 |
| 600ms | 状态早变了，视觉还在路上；连续点会一直追 |

经验判断：控件的最终状态最好在 150ms 内可读。演示里的 600ms 是放大镜，不是推荐值。

快速切换时不要让动画排队：最新的状态赢，动画从当前位置反转。CSS transition 天然是这个行为；JS 动画要自己保证。

不要做的三件事：

- 用动效延迟状态的出现。勾可以有短动画，但状态在第一帧就成立。
- 把动效当唯一线索。截图、减少动态效果、读屏都拿不到它。
- 选中时改变布局。行高、间距一跳，列表会抖。

减少动态效果：勾上之后状态照样清楚。动效可选，状态不可选。

## 为什么这样判断

- 1.4.1 和 1.4.11 是标准。
- 「去掉颜色」的对照是演示里的观察，不是色盲模拟；它只回答「拿掉颜色还剩什么」。
- 150ms 是经验判断，不是测量；0 / 600ms 的对比是演示里的手感。
- 状态与视觉分开读数，是为了让「显示落后」看得见。

## 适用条件和取舍

- 适用于所有有选中态的东西：标签页、chips、列表行、卡片、开关、复选、单选。
- 形状层要占空间：勾需要位置，描边会改变尺寸；空间紧的胶囊可能只能用「描边 + 勾」。
- 动效时长和平台有关：移动端可以稍长，桌面要更快；触摸反馈还可以配 haptic，不在这一篇的范围。
- 高对比模式会覆盖自定义颜色，勾要能活下来。
- 演示里的 0 / 150 / 600ms 是演示值，不是推荐值。

## 还没定

- 选中态的过渡用 ease 还是 spring；过冲在开关上是否合适。
- 多个选中项同时变化（比如「全选」）要不要动效、怎么动。
- 分段控件的指示器滑动算不算同一类动效。
- 颜色对比的具体测量方法和工具链。
