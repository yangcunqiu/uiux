# 树形选择与权限继承

同样一行带勾选框的父节点，可以代表四种不同的操作。设计权限树、分类树或批量选择树时，先确定父节点有没有独立的业务值，再决定父行应放什么控件。

| 父节点的含义 | 点击父行后的结果 | 需要保存或核对的内容 |
|---|---|---|
| 只负责分组 | 选择或取消这一组内可选择的子项 | 明确选中的叶子节点。父行的半选状态由子项计算。 |
| 父节点本身可以独立选择 | 只改变父节点自己的值 | 父子节点各自的选择。另设“全选子项”才能执行批量动作。 |
| 父节点可以显式授权，子项继承 | 父级授权改变子项的有效权限 | 区分显式授权与继承后的有效权限。移除父级授权后，子项恢复各自的授权。 |
| 一个操作将值写入整棵子树 | 父项和子项一起被覆盖 | 取消父项可能抹去之前单独选中的子项，需明确告知影响范围。 |

如果父行同时承担“选择本级”和“选择整组”，一个半选外观无法说明提交的是哪一份数据。可将批量动作放在组标题，为本级值单列一行，或把次要动作放入菜单。放入菜单节省空间，也降低可发现性。继承模式下，子项若不能独立更改，应说明“继承自上级”，并允许区分显式值与有效值。

半选是集合中部分成员被选中的汇总状态。点击它后全选或全清是产品约定。界面如果提供真正的第三种业务值，例如“继承”，应单独表示，避免用计算得出的半选图形兼作这个值。全选保留了已有成员，但失去了它们原先是哪些的历史信息。全清连同已有选择一起移除。默认补为全选，可以把破坏原有选择的动作推迟到下一次点击。支持撤销时才可能完整恢复之前的组合。

“全选”的对象和时间也需要定义。禁用项是否排除、未加载的子项能否计数、今后新增的子项会不会自动获得权限，都会改变结果。未知的子树不能直接当成未选。默认只授权当前明确的对象时，把对未来成员的授权设计成另外一种可辨认的规则。验证时先显式授权一个子项，再开启并取消父级，分别检查最终的显式授权和有效权限。[批量操作的对象范围](../批量操作的对象范围/README.md)
