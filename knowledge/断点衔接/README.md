# 断点衔接

断点是阶跃函数：960px 以下一套值，960px 起另一套值，中间没有过渡。这一篇讲断点之间的地带——错档怎么发生、插值买什么、什么时候不值得。

## 先看演示

[打开「断点衔接」](demo.html)（双击即可；demo.js 放同目录）

iframe 宽度滑块 900–1400（滑块吸附在视口顶部，滚到哪都能拖；点住滑块可用 ←/→ 微调），三个区块：① 步进版（断点外一档到底）、② 插值版（960→1280 之间线性流动）、③ 结构断点（独立区块，两版都保留跳变）。两个版共用同一套校准值，只差区间内行为。

观察重点：

1. **961–977**：步进版两行——一行三张，第四张被拉长。满档校准值在这个区间挤不下四张卡，数值错档把结构挤坏；插值版一行四卡，行数稳定。
2. **跨 960**：两版都跳（手机档→桌面档），幅度不同——步进版跳到满档校准值（顺带换行翻车），插值版只跳到区间起点。
3. **1120**：③ 的列数 3↔4——设计切换，两版都保留。

## 我们的理解

### 一、断点的两个毛病

1. **错档**：桌面档按 1280 校准，却从 961 就开始用——「在 1280px 下合理的字号、间距等排版，在 961px 时会不合适」。区间内完全不响应：961 与 1279 拿到同一套值。
2. **瞬跳**：跨过断点，整套样式瞬间换血。

### 二、修复的形态：按属性逐条仿射线

每个连续属性在两个断点校准值之间线性流动：960 时 24px、1280 时 40px → `clamp(24px, 5vw − 24px, 40px)`。注意它是什么、不是什么：

- **不是等比缩放**：全局一个系数的方案已被[屏宽与缩放](../屏宽与缩放/README.md)否掉（字和点击目标不能缩）。插值是逐属性的，每个属性有自己的两个锚点；布局仍然重排，只是设计值从阶梯变成连续。
- **不是消灭断点**：结构断点照旧跳。
- **关键拆分：结构跳变是设计，数值跳变是缺陷。** 断点处布局可以换（列数、显隐、导航折叠——有意的切换）；同一布局内数值没有跳的理由。断点处的跳变保留，但幅度从「跳到满档校准值」变成「跳到区间起点」。
- 插值连字号在内：每个连续量一条自己的仿射线。与「字不能缩」不冲突——那否的是全局一个系数的**无校准**等比（14px 缩成 7.8px）；插值是在**两个认可校准值**之间的连续路径，不出校准包络。

### 三、数值错档会挤坏离散行为

错档不只是审美问题。满档校准值在窄区间挤不下内容时，**换行、溢出、省略号在断点两侧变成不同一副样子**——demo 里 961–977 的两行布局就是现场：数值换了档，离散行为跟着翻车。这类断点附近的离散故障（wrap 翻、ellipsis 出现又消失）是断点 bug 的标准形态。

所以插值买到的不只是数值连续，还有**离散行为的稳定**——这是它最强的论据。

### 四、px 与线性

- **px＝「谁能写这个值」**：插值合同的两端是设计师能填的表格——「960 时 24px、1280 时 40px」。rem/% 数学等价，但把合同换算成了实现细节。选 px 是协作成本问题，不是技术必要性。
- **线性＝零品位默认**：两点之间用直线，不引入任何可调的品味参数；要非线性（缓动）先拿出理由。

### 五、成本与条件

成本形态：每属性 N−1 段仿射函数；加一个断点＝每属性多一对校准值。工具（SCSS mixin、原子类组件）自动化的是**计算**，校准值的设计判断仍是手工。原文自留注记：「需要非常非常大的设计与开发投入……投入产出比会受到挑战」。

值得的条件：**断点多 × 品牌权重高 × 页面长寿命**。判据不是 C 端/B 端之分，是「**错档看得出来且有人在乎吗**」——原文作者把这套方案也用到了 B 端投放平台（客户掏钱的门面，错档有人在乎）；内部后台没人拿 961px 的截图挑刺。

### 六、验收：拖动测试两查

1. **数值连续**：慢慢拖过整个区间，连续量应连续变化；插值版若仍有「换了一版」的感觉，说明漏了某个属性没插值——插值要覆盖全部连续量。
2. **离散行为一致**：拖过断点，wrap／overflow／ellipsis 在两侧应当是同一副样子。

### 七、缩放屏上的 ±1

系统缩放（125%/150%）的屏上，视口宽度按设备像素取整，同一滑块值可能落在断点两侧——[屏宽与缩放](../屏宽与缩放/README.md)「名义宽度≠实际宽度」的现场版（实测：同一断点，缩放不同的两块屏各偏 1px）。对设计的启示：别把断点切在恰好挤压的临界值上，留出余量。

## 为什么这样判断

- 错档与瞬跳来自原文指认；「区间内完全不响应」在演示里直接可验。
- 判据升级（数值错档→离散行为翻车）由演示实测驱动：步进版 961–977 的换行现场是无意产生的，保留为教学示例——它比原文「不流畅」的审美说法强一档、可验收。
- px/线性的判断是协作与品位口径，非原文原话。
- ±1 取整在两块缩放不同的屏上实测出现，机制（设备像素取整）可复算。
- 演示被单人跨两块屏实测过一次：能定方向，不能当定律；校准值的具体数是演示值。

## 适用条件和取舍

- 插值管的是「同一布局内」的连续量；布局切换本身（结构断点）不插值。
- 高频内容型站点若排版容忍度高，阶梯+少量断点可能就够了——插值的成本账先算再上。
- 工具自动化计算后，维护成本集中在校准值成对标注：设计稿要能表达「960 时的值、1280 时的值」两档，否则插值无从谈起。
- 别为每个属性都插值：只插值会错的那些（断点两侧错档可见的）；纯装饰性的小值跳变无感，阶梯即可。

## 稳定性

| 内容 | 稳定性 | 写法 |
|---|---|---|
| 断点的两个毛病（错档/瞬跳） | 定义 | 写死 |
| 结构跳变是设计、数值跳变是缺陷 | 判断 | 有演示对照 |
| 数值错档会挤坏离散行为 | 判断 | 演示实测一次，断点 bug 标准形态 |
| 按属性逐条仿射线 | 方法 | 写死 |
| 断点处跳到区间起点 | 默认 | 幅度取舍见还没定 |
| px＝谁能写值、线性＝零品位默认 | 默认 | 可偏离，代价见文 |
| 值得的条件与「有人在乎吗」 | 条件 | 作者 B 端反例在案 |
| 拖动测试两查 | 方法 | 写死 |
| ±1 设备像素取整 | 机制 | 写死；具体偏移随缩放设置 |
| 960/1280 与各校准值 | 演示值 | 不是推荐值 |

## 还没定

- 校准值成对维护的设计流程（设计稿怎么标注两档值、谁维护）没有讨论。
- 「跳到区间起点」与「跳到满档」的幅度差没有量化口径。
- 移动端断点之间的插值（触屏、窄区间密集断点）是否同样值得，没有讨论。
