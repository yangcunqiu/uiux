# 数据列表与列宽

表格有两项结构价值。相同字段在各行有共同位置，可以上下比较。一个对象的相关字段也能并排核对。列表适合先认出一个对象，再阅读或进入详情。卡片适合图像或对象整体特征比逐字段比较更重要的任务。数据条数相同，也可能需要不同的排列。

需要跨记录比较金额、找极值或按同一字段排序时，给被比较的字段稳定的列。主要任务是辨认消息、文件或联系人时，每项可以有自己的内容排布。只有一个对象时可用描述列表。需要比较趋势或占比时图表可能更直接。混合形式也成立，例如表格首列组合头像、名称和说明。如果这一列可排序，要说清按哪个值排序。列表尾部只固定一个金额字段时，能比较的是这一项，不能据此认为中间各字段也能对齐。

## 列放不下时

1. **判断哪些值需要成为独立列。** 与对象名紧密相关的说明可并入副文本，会失去独立列的比较空间。罕用细节可进入详情，代价是额外操作。仅用于收窄范围的属性可成为筛选条件。不同角色确实读不同字段时，可以自选列，但初始列仍要能完成主要任务。
2. **按真实内容确定显示和取回方式。** 必须区分的两条记录，在截断后仍应能分辨。任务需要完整值时，提供可发现的展开、详情或可操作的提示，并照顾键盘与触摸。单靠浏览器鼠标悬停的标题，不能覆盖这些输入方式。短符号只适合值少且含义容易识别的场合。
3. **仍需横向滚动时，保留行的身份和必要操作。** 固定列能让用户滚动后仍知道正在处理哪个对象，同时占用剩余窗口宽度。核查真实最小宽度下到底还有多少数据可以并排，不宜仅凭字段“重要”就不断增加固定列。

列已经能完整放下时，可直接处理格式和对齐。为完整导出或机器对账保留字段，与屏幕上优先展示哪些列是两个决定。行列间距、金额精度和分隔方式见[表格对齐与行分隔](../表格对齐与行分隔/README.md)。
