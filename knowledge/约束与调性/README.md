# 约束与调性

规范里的参数不是一类东西。违反字号下限会读不清，违反 4px 圆角不会坏任何功能——它只会让界面不像原来那家。分清这两类，才知道抄组件库时哪些是白拿的，哪些其实是替别人做的决定。末节用字体栈把这套判据走一遍成品案例。

## 先看演示

[打开「约束与调性」](约束与调性.html)（双击即可，不需要本地服务）

四个实验，互相独立：

1. **调性轴**：同一界面只改圆角（0 / 2 / 4 / 8px）和主色（蓝 / 紫 / 橙）。「能不能用」全程不变。
2. **状态色**：悬停/按下色切换来源——一条 HSB 公式自动生成，还是每个颜色手调的样例。公式把高饱和主色的悬停算得比常态还深。
3. **档距**：标题 16px（相邻档）对 24px（跳两档），看哪个像标题。
4. **字体栈**：同一段中西文混排，四行只差 font-family 的写法——西文在前、中文在前、不声明、system-ui。中文字形不动，变的是「谁负责西文」。

观察重点：

- 实验 1 换任何一档，按钮还是按钮、输入框还是输入框——变的是什么？
- 实验 2 的活按钮切两种来源各感受一次，悬停的方向一样吗？
- 实验 3 两张卡只差标题字号，哪边读作「粗一点的正文」？

演示里的具体数值只为制造对照，不是推荐值。

## 我们的理解

### 一、参数分两类

| | 约束 | 调性 |
|---|---|---|
| 例子 | 字号下限、正文对比度、点击热区、焦点可见 | 主色、圆角、阴影、字重分配、字体族 |
| 违反的后果 | 读不清、点不中、键盘找不到位置 | 没有功能后果，只有「像谁」 |
| 抄成熟系统 | 安全，理由可检验 | 抄了不是错，是采纳了那家产品的性格 |

判据一句话：**违反它，坏的是功能还是只是味道。**

这条判据也回答「规范能规定什么」：约束类有对错可检验，规范可以写死它（[尺寸与容器](../尺寸与容器/README.md)里尺寸那套就是这一类）；调性类没有对错，规范只能记录「我们选了哪一档」，不能证明这档是对的。

### 二、调性轴：拨一档，换的是归属

调性类参数各是一根轴（主色、圆角、阴影、字重、字体族），轴上拨一档，界面换一种性格。实验 1 里圆角从 0 拨到 8、从蓝换到橙：「能不能用」没有任何变化，变的是它像哪家、什么性格。0px 冷硬、8px 柔和——这条经观察认同，但它是经验感受，不是定律，对着演示换档可以自己再验。

结论的用处是反向的：**抄 Ant 的 #1890FF 和 4px 圆角，抄到的是阿里云控制台的调性**。约束部分尽管抄（对比度处理、焦点样式），调性部分要么接受「长得像 Ant」，要么自己拨——拨的成本很低，它只是少数几个值。

### 三、派生值：状态色

悬停、按下这类状态色可以从主色**公式化生成**：一条规则管所有颜色，一致、免维护。这是合格的默认值——[受理与交代](../受理与交代/README.md)立过边界：状态色只回答「指到的是它吗」，方向稳定、变化可辨，受理就成立。

两条要分清：

1. **方向是约定，不是定律。** 悬停提亮（Ant、Material）和悬停加深（Bootstrap 系）都有成熟库在用——「都有人用」本身就是约定的证据，没有证据说哪种更快。本库取提亮，和[受理与交代](../受理与交代/README.md)一致；代价它也记了：提亮会掉白字对比度，基准色要够深。
2. **公式保证一致，不保证方向合习惯。** 文中公式（悬停 = H 不变、S+20、B−10）在高饱和主色上顶满饱和度后只剩变深：`#2f6fed` 的悬停算出 `#0047d3`，比常态还深。公式是一条默认生产线；手调只值在少数背景需要微调的边缘场景。

### 四、档距

层级靠**档距**，不靠档数。实验 3 里 16px 标题读作「粗一点的正文」，24px 读作标题——字重、行高、文案全没动。这和[一条主路](../一条主路/README.md)的「级是四根轴，不是五档音量」是同一件事：对比靠差距，不靠档位数量。

配套一条「少即是多」：字阶表里档数多不产生层级，只稀释每两档之间的距离。需要拉开就跳着选（14 → 24），相邻档留给次要层级。

### 五、规范的形态：具名值

对单人 + AI 的开发者，规范不该长成文档，长成**具名的基础值**——设计界叫 Design Token，对后端开发者就是常量/配置项：语义命名（`--color-text-secondary`）而不是值命名（`#666666`），定义一处、处处引用，改一处全站生效。这不是新的设计知识，是确认配置管理的直觉在这里也成立。

### 六、成品案例：字体栈

字体族本在调性轴上，但真写一行 `font-family` 时，约束、调性和机制同时到场。可写死的事实有三条（出处：[一位做 UI 的工程师的字体方案记录](https://wxad.design/abc/font-family)）：

1. **栈的机制：浏览器按字符走栈。** 每个字符用栈里第一个包含它的字体渲染，整段文字因此分开记账：西文字体排前面，拉丁字符与数字由它渲染，不会落到中文字体通常更宽的西文字形上。「西文在前」是机制的结果，不是排列审美。
2. **不声明 ≠ 系统字体。** 不声明时，渲染结果由浏览器的默认字体配置决定，不由你控制。那篇的实测里，macOS 的 Chrome 默认渲华文黑体、Win7 默认渲宋体，都不是系统界面字体（苹方/雅黑）；显式声明的意义首先是安全与可控。
3. **枚举后来被标准收编。** 他们当年维护 14 个具名字体的回退栈，并等着标准化出现；如今 `system-ui` 关键字覆盖了主流平台的系统界面字体（[MDN：font-family](https://developer.mozilla.org/en-US/docs/Web/CSS/font-family)），两行默认值接管了整张清单。这印证了那条代价：**枚举清单是维护负担，机制和目标不是**（枚举完整的账记在[完整化](../完整化/README.md)）。

写不死的条件：

- **短栈与长栈都成立，取决于要不要品牌。** 知乎当年三四个字体照用（长文阅读，安全第一）；微信广告为了品牌形象指定苹方，才值得维护长栈。「写得越多越专业」不成立。
- **对设计者的意义**：设计稿应当用目标平台最终渲染的字体画——设计稿与用户所见一致，走查才有对得上的前提。

## 为什么这样判断

- 两类参数的判据可执行：约束类拿「读不清/点不中/找不到焦点」验收，调性类拿不出这种验收——这是「可检验/不可检验」的差别，不是「重要/不重要」的差别。
- 圆角与主色的调性来自实验 1 的对照：同一个界面换四档圆角、三种主色，功能路径全程可走。这是观察，不是测试。
- 状态色方向：三家成熟库的悬停方向本来就相反（Ant、Material 提亮，Bootstrap 加深），说明方向是约定；本库选提亮记录在案，换约定时全站一起换。
- 公式的高饱和失真是算出来的：`#2f6fed` 的 S≈80、B≈93，S+20 顶到 100 后 B−10 单独生效，悬停深于常态。数字可复算（演示实验 2 的色板上标着实值）。
- 档距来自实验 3 的并排对照，一人验收，未做阅读测试。「相邻档拉不开」在两档字阶表上不成立——那里「相邻档」就是全部，只能跳到底。
- 具名值一节是类比确认；J 簇文章里的团队工作流（Figma 资产、走查还原、多角色协作）对单人协作不成立，没有采纳。

## 适用条件和取舍

- 判据用在「抄」的时刻最值钱：拿一个成熟组件库当底座时，逐个参数问「这是约束还是调性」，得到一张「照抄清单 / 待定清单」。待定清单通常很短——主色、圆角、阴影、字体，四五个值。
- 调性自己拨的代价是要做一次选择并全站一致；收益是界面不再「长得像别人」。两边都合法，这是投入决定。
- 状态色公式化的代价：对每个具体颜色都不是最优；方向必须先定一处，公式只负责一致。
- 档距的代价：大字占空间。窄屏、紧凑列表里跳档用在少数需要被读成层级的文字上，不是全部标题。
- 字号/间距/圆角/网格的具体数值，本库不沉淀为通用知识：它们是各家系统的经验值，抄数值等于采纳别人的调性或安全余量；按两类参数的判据分别处理即可。

## 稳定性

| 内容 | 稳定性 | 写法 |
|---|---|---|
| 两类参数与判据 | 定义 | 写死 |
| 调性轴包含哪些参数 | 默认 | 可增减，判据不变 |
| 状态色方向（提亮） | 约定 | 全站一致即可；换约定连着换 |
| 状态色公式 | 经验值 | 当默认生产线；高饱和主色上失真 |
| 圆角 0→8 的感受 | 经验感受 | 一人观察认同；对着演示可再验 |
| 档距拉开层级 | 默认 | 两档字阶表上不适用 |
| 字体栈机制（按字符走栈） | 定义 | 写死 |
| 不声明 ≠ 系统字体 | 事实 | 原理写死；默认值随平台和版本变 |
| system-ui 两行默认 | 时代注记 | 会再变；机制和目标不变 |
| 短栈/长栈的取舍 | 条件 | 由要不要品牌决定，不给唯一答案 |
| 具体字号/间距/圆角数值 | 不沉淀 | 照抄成熟系统或按项目定 |

## 还没定

- 阴影、字重分配只在文中提到，没逐一做过观察验证。
- 「0px 冷硬 → 8px 柔和」是一人观察，不排除「看惯了」的成分。
- [一条主路](../一条主路/README.md)交给 J 簇的其余项（宽度基准、尺寸档位经验值、24×24 目标尺寸、圆角与命中/接缝的实测）：按本条「数值不沉淀」处理；命中/接缝的实测没做。
- [填错的时机](../填错的时机/README.md)、[顶栏三句话](../顶栏三句话/README.md)、[标签在场](../标签在场/README.md)、[提交边界](../提交边界/README.md)、[表单骨架](../表单骨架/README.md)留给 J 簇的字号/间距/列宽/高度规范值：同上——框架有了，具体值留给具体项目。
- 推导型经验值（前提可复算、映射未验）作为约束/调性之外的第三种参数，审计案例与五步方法见[动量](../动量/README.md)的 350px 一节。
