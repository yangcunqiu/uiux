# 放不下的列

列装不下时，第一反应常常是「横向滚动 + 固定几列」。那是最后一步，不是第一步。顺序是：**先问这一列该不该以「列」存在，再谈列宽与截断，最后才是横向滚动和固定。**

这一条没有配演示：它是一套顺序和判据，不是可切换的现象。相关机制在[行与列](../行与列/README.md)（横向滚动拆掉的是「行并置」）和[对齐的对象](../对齐的对象/README.md)（截断之后对齐失效）。

## 一、先问这一列该不该是列

一列占的是**每一行**的横向空间，而且它一旦成为列，就要接受列的全部约定：同质、可排序、可筛选、宽度要和其他列谈判。所以先问：这个值真的需要「一列」吗？

| 做法 | 什么时候成立 | 代价 |
|---|---|---|
| 并进相邻列的副文本 | 值和主值强相关（邮箱之于用户名、联系人之于客户） | 这一列不再能单独排序、筛选 |
| 换成图标或符号 | 取值少、含义通用（性别、是否、状态点） | 表达能力变弱，需要图例 |
| 搬进详情 | 只在少数情况下才要看（备注、地址） | 每次要看都得点开 |
| 变成筛选条件 | 用户是用它来「缩小范围」而不是「读」（渠道、标签） | 不能横向比较 |
| 交给用户自选列 | 不同角色关心的字段不同 | 默认列要选对，否则用户先看到的是错的 |

这一步的收益是乘算的：少一列，每一行都少一列。

## 二、再谈列宽与截断

- 列宽不是一个数，是「内容的分布 + 这一列要不要读完」。定宽的依据是让用户能区分，不是让内容完整。
- 截断保住高位、丢掉低位；右对齐的列被截断后，右边缘齐的是省略号（见[对齐的对象](../对齐的对象/README.md)）。
- 省略号、渐隐、气泡、可展开，是四种痕迹；`title` 属性不算——它有延迟、不能选中复制、触摸端没有。
- 截断的代价是「以为看全了」。所以截断必须和「能取回完整值」的动作配对：悬停气泡、点击展开、进详情。

## 三、最后才是横向滚动

- 横向滚动拆掉的是表格的第二个承诺：一行看不全，行内就不再并置。所以它必须有补偿——**固定身份列和操作列**。
- 固定的代价是宽度：固定的列越多，完整可见的列越少（演示里 12 列固定两列后只剩 11 列完整可见）。
- 固定的是「身份」和「操作」，不是「重要」。重要是主观的，身份和操作是滚到哪儿都要能回答的两个问题：这是谁、能对它做什么。

## 什么时候这条顺序不成立

- 列本来就不多（5 列以内），横向滚动根本不会发生：直接从第二步开始。
- 表格是给机器读的（导出、对账），列多不是问题：先保证列全，再谈人怎么读。
