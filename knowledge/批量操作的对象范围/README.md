# 批量操作的对象范围

同一操作影响多个对象时，先确定**哪些对象属于这次操作，以及以哪个时点为准**。工具栏出现的早晚、按钮的颜色、当前选中数都不能单独回答这两个问题。全选本页、跨页逐项勾选、选择所有匹配条件的对象，可能得到三个不同集合。

## 对象、时点与排除项

| 用户选择的含义 | 执行时应能保证的结果 | 可选的实现 |
|---|---|---|
| 明确勾选的对象，包括在不同页上勾选的项 | 翻页后选择仍可核对，执行只针对这些对象。 | 保存对象标识集合。 |
| 选择时符合条件的那一批 | 后来新增的匹配对象不自动纳入。 | 明确的标识集合或服务端保存的选定集合。 |
| 执行时所有符合条件的对象 | 执行时重新按条件求值。若允许全选后取消个别项，须保留明确排除项。 | 筛选条件加排除集合，由相应接口求值。 |

对象随后可能被删除、失去权限或不再满足操作条件。项目要另行定义跳过、阻止还是重新核对，并如实报告结果。固定选择范围并不保证每个对象一直可操作。选择时默认本页、再显式扩大到“全部匹配”是一种便于核对的做法。任务本来就面向全部匹配对象时，项目可以采用其他默认，但要让条件、范围和生效时点可辨认。“已加载”依赖滚动或分页，只有当它真是用户选择的范围时才适合用作名称。

操作按钮紧靠“已选 3 项”时，可由摘要提供范围。按钮与摘要分离或操作后果较重时，在入口或确认中重述对象范围。动态集合执行前可以重新报数，完成后报告实际处理、跳过或失败的数量及必要条件。遇到不能披露的对象，按权限规则说明结果。

## 不同对象能否一起操作

混合选择中有部分对象不符合条件时，先决定业务允许的执行方式。逐项相互独立、可重试且某项失败不会改变该对象其他状态时，可以部分成功并提供报告。要求整体生效的操作必须共同成功或共同失败。删除、清空等破坏性批量动作宜先把对象限制在可操作的范围内，核对后整体执行。若实际只完成一部分，结果提示必须区分已生效和未生效的对象。禁用整个按钮可以防止发起，但只说“有几条不能处理”时，用户仍要逐项寻找原因。

常驻按钮可让人先看到可执行的命令，勾选后才出现操作栏可节省常态空间。两种方式都需要处理没有选择或混有不可操作对象的情形。另设专门模式的收益，是只显示当前筛选里可操作的对象，从而可以安全全选。这个收益超过进入模式及重新辨认列表的成本时就值得采用。进入时将已有选择与可处理集合求交集，说明移出了几项。保留并显示原筛选，模式期间固定筛选可以避免看见的集合与已选集合分离。交集为空时给出退出或改筛选的路径。退出后恢复原筛选，清空本次短期选择。保留熟悉的列、位置和列表样式，可以让人认出这是同一列表的一个操作模式。偶尔顺手处理几项时，勾选后显示操作栏往往已足够，专门模式会增加一步及重新辨认列表的成本。

**一个可以直接验证的边界。** 在测试数据中选择全部匹配项，手动排除 A，执行前新增一个匹配的 B。核对实际修改的对象标识。A 应保持排除。B 是否包含由选定时或执行时的约定决定。只对比数量会漏掉数量相同、对象已经替换的错误。
