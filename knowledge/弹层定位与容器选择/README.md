# 弹层定位与容器选择

选择弹层、抽屉或整页，先确定任务是否短到可以当场完成、是否需要同时核对背景、是否连续处理多个对象。增加弹窗宽度可以减少滚动，却不自动降低从许多相似候选中找出正确项的成本。后者要看分组、排序、常用项和搜索，见[选项检索与展开方式](../选项检索与展开方式/README.md)。

固定对话框的宽度上限可从最小支持视口减去两侧所需空间得到。一个产品可以为不同内容设宽度档位，还需定义超出可用空间时的收缩、滚动或换容器行为。能装下多少、确认按钮是否可达可以直接检查。将指针移动距离换算成评分，无法据此证明某个宽度对整个选择任务最优。

## 浮层靠近视口边缘

依附按钮的菜单有三个独立问题。按钮靠近底边时，先选择上方或下方有空间的方向。靠近右边时，需要横向调整以免每项文字被裁切。内容长于选定方向的剩余高度时，还需要限高并允许读到尾部。在下方几乎没有空间时，仅缩小高度无法替代翻转。验证时使用末行、两侧边缘、较长内容、不同缩放和容器滚动等实际条件。

如果浮层绘制在外层，而按钮位于内部滚动区，滚动后两者要保持对应。默认打开时确定方向，在同次操作中跟随锚点平移，避免仅为了更“居中”而反复翻转。应在产品支持的状态中持续保证必要选项可达。固定画幅且内容、位置都可知时，直接在布局中预留位置可能已经足够。通用组件应考虑未知视口、滚动和数据。

## 对话框大小与内容溢出

常用做法是限制框的最大高度，让正文滚动、必要的标题和操作仍可达，内容少时按内容高度收拢。锁定背景滚动时应核对滚动条占位是否改变页面宽度，以及内外滚动区会不会互相干扰。为解决少量溢出而整体缩放，会同时缩小字和按钮。默认优先稳定尺寸与内部滚动。一次性提示、只有很少溢出且缩幅难以察觉时才值得考虑整体缩放。内容异步到达时反复改变整个框的比例，会干扰定位。

出现时的缩放幅度是另一项选择。起点越小越强调出现过程，越接近最终尺寸越克制。应由这个对话框需要获得多少注意力决定。若用户需要边看凭证边选原因，可改用能同时看见凭证的侧面板。每项还要提交证据、或者流程会中断再回来时，独立页面可能更合适。同类任务统一容器能提高可预期性，同时也可能让少数简单任务偏重，这是产品约定。
