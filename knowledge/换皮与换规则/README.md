# 换皮与换规则

评价一件作品时，先分清在评哪一层。生成艺术把这件事摊得很开：一个结果背后有一条规则，规则背后有一个想法。换一层，作品的身份就变；不换层，只是换了件衣服。

这篇从一个对照实验开始，最后落到界面上——我们平常说的"设计"和"实现"，边界其实不在物件上，而在"改掉它，这东西还是不是同一个"。

## 先看演示

[换皮与换规则](换皮与换规则.html)：左边是锁住的一张，右边是当前的一张。先点「锁住当前」，然后每次只改一样。

单文件，双击打开，不需要构建，不联网。

观察重点：

1. 只换配色：每个点的大小和位置一模一样，只有颜色变了。
2. 只换规则：元素还是圆点、还在同一个网格里，但"大小由什么决定"变了——从独立随机，变成横向渐变或同心波。
3. 只换种子：同一个规则，每次都不一样，可"像同一个系列"。
4. 读数会告诉你这一次到底改了什么（规则 / 配色 / 种子），这样比较不会被记忆骗。

## 我们的理解

### 一、三层：结果、模式、想法

| 层 | 生成艺术 | 界面 | 谁在看 |
|---|---|---|---|
| 结果 | 这一张画 | 这一屏长什么样 | 用户第一眼 |
| 模式 | 那条规则 | 组件、规范、行为约定 | 设计师、开发者 |
| 想法 | 创作者想干什么 | 产品意图、用户任务 | 需求方、设计 |

结果由模式渲染出来，模式由想法建立。三层不是并列的，是层层往下。

只看结果评价，就会得出"颜色不好看""动画再慢一点"——这些都在最上面一层打转。**改来改去都在改颜色的讨论，缺的是中间那层。**

### 二、规则管关系，不管元素

演示里三条规则都画圆点，网格也一样，差别只有一句："大小由什么决定"。

- **只换配色**：元素没变，关系也没变 → 同一件作品，换了件衣服。
- **只换规则**：元素没变、网格没变，但疏密关系变了 → 已经是另一件作品。
- **只换种子**：规则没变，关系也就没变，只是参数不同 → 同一个系列里的另一张。

所以判断"作品变了没有"，要看的不是元素换没换，而是**元素之间的关系**换没换。

这条在生成艺术里很好验证，因为元素被固定住了。放到界面上就难一些：按钮换个圆角，是换元素还是换关系？多数时候是换元素——关系（它做什么、能不能点、在什么位置）没变。

### 三、一层里还要分"随机"和"秩序"

演示的三条规则其实是同一根轴上的三个点：

- **独立随机**：每个点自己决定大小 → 噪声。
- **横向渐变**：大小由横坐标决定 → 纯秩序。
- **同心波**：大小由到中心的距离决定 → 秩序，但有一点结构感。

完全随机没有可读的模式，完全秩序就是一张几何图案。有趣的规则通常在两者之间：有一个可被看出来的规律，同时保留足够的差异，让每一张都值得再看一眼。

### 四、皮和魂，取决于承不承载身份

原文里说"评价配色和动画，是在评价实现"。这句话在生成艺术里成立——配色只是规则的一个参数。但推到界面上就不对了：品牌色、警示色、情绪色经常就是想法本身。

更准确的说法是：**判断标准不是"它属于哪一类参数"，而是"改掉它，作品还是不是同一件"。**

- 承载身份的参数是设计，不承载的才是实现。
- 同一个东西在不同层面看，身份也不同：品牌色在品牌层是魂，在某个页面的排版层可能只是皮。
- 所以"配色是皮还是魂"没有固定答案，只有"在这个层里，它承不承载身份"。

### 五、正向与逆向

原文里有一个区分值得留下：

- **逆向**：用代码还原一张已经画好的图——照着设计稿写页面、照着 AE 还原动画。练的是还原精度。
- **正向**：先定规则，再让规则产出画面。练的是"设计规则"。

两者都叫"用代码做图"，但学到的东西不一样。界面里也有正向的东西：设计规范、组件模板、生成式的占位内容、空状态插画——它们不是"这一屏"，是"产出这一屏的规则"。

## 为什么这样判断

- 演示是对照，不是作品评价实验：它只证明"改配色时关系不变、改规则时关系变"，不证明哪种更好。
- "三层"借自原文的框架，不是我们原创；这里补的是把它和界面、和"身份"连起来。
- "皮和魂取决于承不承载身份"是对原文那句话的修正，这次讨论里两个人都认了，但样本只有两个人。
- 演示里的"规则"只是三种分布，不是完整的生成系统；种子用的是确定性伪随机，同一个规则、配色、种子画出来完全一样。

## 适用条件和取舍

- 这套分层适合判断"改了什么"，**不适合判断"好不好"**。好不好还有一层：规则本身有没有意思，那部分没法从代码看出来。
- 不是所有作品都有"想法"层。装饰性图案、纹理、背景，可能只有模式，没有想法——这不丢人，也不影响它有用。
- 生成艺术的"评价"很容易滑到"我觉得好看"，那是在评结果。要看模式，得先读懂规则——这需要时间，也需要作者愿意把规则讲出来。
- 确定性伪随机是可复现的，真随机不是。要做"同一个系列"，必须用可复现的随机源。
- 界面上"关系"比生成艺术里难固定：用户会改变状态、数据会变，同一个按钮在不同场景下的关系是不同的。

## 例子

- 活动页的生成式背景：换配色是换皮，换排布规则是换作品。
- 空状态插画：一套规则生成多个变体，比画十张图更省，也更容易保持风格一致。
- 设计规范：把"关系"写下来（间距关系、层级关系、状态关系），就是模式层的东西。
- 用 AI 生成：提示词是规则，出图是结果。改措辞是改规则，换种子是换一张——只是这层规则通常不由你完全掌握。
