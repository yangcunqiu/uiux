# 动效的层级：空间、顺序、群体

动效常被当成"让画面活起来"的装饰。这一组讨论的是另一件事：**动效在表达关系**——谁在上面、谁导致谁、哪些是一组。这三种关系分别对应后景处理、编排和错落。

## 先看演示

- [后景与可操作性](后景与可操作性.html)：同一个弹层，六种后景处理 × 两种后景行为。可以直接去点后景，看自己会不会犹豫。
- [插入与删除的编排](插入与删除的编排.html)：同一件事，四种先后顺序，外加一个「高亮新增」开关。
- [错落](错落.html)：入场和滚动两个场景分开，各只对比「有错落 / 没错落」。滚动那一档是反例。

三个都是单文件，双击打开。

## 一、后景：画法和行为是两件事

后景的处理方式（变暗、模糊、后退）和它实际能不能点，是两个独立的选择。可以一致，也可以冲突。

**用户信画法，不信行为。** 界面先给出的承诺，比实际行为更有分量。所以：

- 「不动 + 不可点」最糟：承诺可用，然后拒绝。用户会觉得界面卡了，而不是"这里不能点"。
- 「变暗 + 可点」同样糟，但更隐蔽：承诺不可用，用户就不去试，功能永远发现不了。很多抽屉就是这么把功能藏没的。

三种画法不是三个强度档，是三种语义：

| 画法 | 说的是 | 适合 |
|---|---|---|
| 变暗 | 可以看，但现在别用 | 用户需要参考后景才能做决定（确认删除哪几条、核对数字） |
| 模糊 | 别再看了 | 注意力应完全转移；或后景内容不该被旁人看到 |
| 后退 | 层级变了 | 真的进入了另一层（详情、编辑、独立任务） |

后退只表达"位置变了"，不表达"能不能用"，所以很少单独用。它通常要配变暗或模糊，才能同时说清两件事。

选择顺序是先行为、后画法：

1. **后景还能不能用？** 能用就别画成不能用；不能用就必须给可感知的信号。
2. **用户需要读后景吗？** 需要 → 变暗；不需要 → 模糊。
3. **这是叠在当前任务上的一层，还是另一层空间？** 后者 → 加后退。

代价：变暗压得太狠会接近模糊，深色遮罩还会让背景发灰；模糊大面积使用有性能成本，而且彻底切断上下文；后退是像素缩放，背景文字会发虚，进出必须对称，否则来回两次会晕。

## 二、编排：顺序表达因果

同一组元素，同样的终点，顺序不同，用户理解到的因果也不同。

- **插入：空间先于内容。** 先腾出位置，再出现内容。
- **删除：内容先于空间。** 先失去内容，再收掉位置。

可以合成一句：**空间在"出现"时先，在"消失"时后。**

判据不是"哪个更好看"，而是：**用户能不能看出"这块空间是为它准备的"。** 能看出来，就会觉得内容是从这里长出来的；看不出来，就是"凭空冒出来"或者"被挤掉"。

两个边界：

- **编排不是必须的。** 变化不频繁、用户也不关心时，瞬间跳反而最省事——加动画等于给每次操作多加两百毫秒。
- **这条规则只管同一组里的空间与内容。** 两个互不相关的元素同时动，是正确的。

## 三、静态标记和动态过程不能互相替代

同一件事有两条路让人知道"刚才发生了什么"：

- **编排**管发生的那一刻：吸引注意力、让位移可追踪。
- **标记**（比如新增项高亮）管之后的一段时间：让用户回头还能认出来。

它们的有效时间不一样：编排只在变化发生的那一两秒有效，标记只在变化结束之后有效。中间那段，两条都不覆盖。

还有一个不对称：**删除只能靠过程。** 删掉的东西没法标记，所以删除比插入更依赖编排。

## 四、错落：整体与个体之间

错落要同时做到两件事——看起来是一组，但每个个体都还在。完全同步是一块铁板，差异太大会散架。所谓"微小"，就是在两者之间找位置。

"微小"没有固定值。总跨度 = 间隔 × 元素数量，八个元素每个晚 40ms，最后一个就晚了 280ms。元素越多，同样的间隔越不可行。

关键区分：**固定时差和连续参数不是两种实现，是两种语义。**

| | 表达的是 | 属于 |
|---|---|---|
| 固定时差 | 这些元素依次发生，有先后 | 入场：网格加载、图标下落、菜单展开 |
| 连续参数 | 这些元素同时被带动，传递有衰减 | 拖拽：一叠卡、一个面板、转盘 |

它们不该在同一个场景里比较。入场本来就有先后感，所以固定时差是对的；拖拽是同时被一个输入带动，所以用连续参数。

**这条边界是对照过的**：用分场景的演示分别试过，入场用固定时差成立；滚动用连续参数，无论间隔和幅度怎么调，看的人都觉得别扭。原因不在参数。

真正的原因是：

> **错落改变的是元素之间的相对位置。**

- **入场**：每张卡最终都回到原位，错落只改变"到达时间"。运动结束后，相对位置完全正确，所以成立。
- **滚动**：行距本身在运动过程中被改变了。用户读到的不是一个在平移的列表，而是一个被拉长、又被压缩的列表。
- **一叠卡片**：同样不成立。卡片间距是刚体约束，给每张不同硬度，间距就会变。
- **拖动一叠卡**（材料里的场景）：错落改的应该是"整叠的滞后"，不是"卡片之间的间距"。

所以错落只适用于两种场景：**相对位置在运动结束后会恢复**（入场），或者**相对位置本来就不重要**（氛围）。

由此可以判定：**错落属于入场，不属于高频滚动。**

- 滚动是工具动作，用户快速滑动是为了定位。这时把行距拉开，等于在最需要准头的时候增加不确定性。
- 滚动持续、反复，错落会一直存在，不是一次性的表演。

滚动里的错落只在一种情况下成立：**滚动本身是体验的一部分**（展示型页面、活动页），不是工具。材料里那个例子正是活动页的展示列表，用户只滚一两次。

## 五、方向：用运动编码结果

演示见 [空间一致性](空间一致性.html)。同一个弹层，四种关闭方式：无动画、都原路返回、取消回上确认向下、反过来。

这一节要先拆一件事：**「从哪来、回哪去」和「反方向离开」是两种不同性质的手法。**

| | 性质 | 成本 |
|---|---|---|
| 原路返回（取消回上） | 物理直觉：来的路，原路回去 | 几乎零，不需要学 |
| 反方向离开（确认向下） | 人为编码：把「向下」赋成「完成」 | 要学，且只在重复遇到时学得会 |

所以「空间一致性」这个词把两件事混在一起了：**对称是默认该做的，不对称是可选编码。**

一个实际的排序（来自对照演示的体验）：取消回上 > 确认向下 > 取消向下 ＝ 确认回上。中间那个「确认向下」不如「取消回上」顺，因为它需要学习；最后两个同时破坏直觉，最别扭。

不对称编码要成立，四个条件缺一不可：

1. **高频**。低频产品的用户学不会，只会觉得「这次怎么往下走了」。
2. **两种结果都会出现**。只见过「确定」往下、没见过「取消」往上，编码是不完整的。
3. **全产品一致**。这个弹层往下、那个弹层往上，编码立刻失效。
4. **方向差异足够明显**。距离太短、速度太快，用户看不到。

缺任何一条，它就从「表达结果」退化成「没有信息的运动」——还不如两个都原路返回，至少不让人猜。

材料里另外两个判断：用上下不用左右，是因为左右太像导航的前进/后退，会把「关闭弹层」读成「翻页」，上下更像「盖上来、落下去」；不从点击位置放大，是因为距离远时「飞过去」会喧宾夺主。这两条我认同，但它们管的是「从哪来」，和「往哪去」是两件事。

## 适用条件和取舍

- 后景这一节适用于"有前后层"的界面。如果界面上本来就没有可操作的背景（比如独立页面），这套判断没有对象。
- 编排的时长（200ms 左右）是演示值，跨场景要重调。
- 错落的判断适用于"一组相似元素被同一个动作带出来"的情况。元素各自独立出现时，不该错落。
- 减少动态效果：错落不承载必须传达的信息，应该直接关掉。

## 还没定的

- 错落在"展示型滚动"（活动页、画廊）里是否成立，还没有具体项目验证；目前只确定它不适用于工具型滚动。
- **浏览型层叠**（一叠卡片里挑一张）还没想清楚。已知 hover 位移会改变命中区域、形成振荡；hover 只做示能（描边、阴影）更稳，但"展开多少"应该由内容决定而不是固定距离。留到 O 簇《制作有趣的界面：朋友圈广告年度评选 2025》时深入，那里有 iMessage 式的卡片堆案例。
- 「变暗 + 后退」这类组合，具体的适用场景还没有验证。
- 后景处理与「拆组件」里"模态性由行为决定"是同一条原则的两面，但两边还没有互相引用校正。
