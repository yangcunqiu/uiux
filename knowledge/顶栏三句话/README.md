# 顶栏三句话

顶栏是一条句子：**回哪 · 在哪 · 能做什么**。三个位置各管一件事。

中间那格只有一个。借走它，就得有别的地方替它回答"我在看哪个对象"；没有别的地方，用户就只能自己记。

## 先看演示

[中间那格](中间那格.html)：双击打开，不需要本地服务。

五个窗格，内容一字不差——同一张订单详情，只有顶栏不同。前四张是手机的四种塞法，第五张是桌面端的典型解法。

观察重点：

- 点「同时滚到 60%」：②③ 的灯灭，①④⑤ 不灭。
- ② 的分段跟着滚动走（滚到物流就亮物流）。它答得了"哪一段"，答不了"哪一条"。
- ④ 先由内容里的大标题回答；大标题滚出顶栏底部的那一刻，顶栏才把名字接过去。
- ⑤ 的中间那格是空的：B 端把整条路径放在左边，标题在内容区。

灯的含义：灯亮＝屏幕上还能看到订单号。这是"页面有没有在回答"的**代理指标**。灯灭不等于用户一定认不出（商品图、商品名也可能是线索）；灯亮也不等于用户真记得住。

## 一、三格各管一件事

| 位置 | 回答什么 | 放错会怎样 |
|---|---|---|
| 左 | 回哪：上一级，或者关闭 | 回不去了。只剩系统手势或浏览器返回，而它是看不见的 |
| 中 | 在哪：当前对象是谁 | 用户滚两屏之后，不知道自己在看哪一条 |
| 右 | 能做什么：对当前对象的操作 | 操作找不到；或者反过来，什么都往这儿堆 |

两份官方指引画出来的构成几乎一样：左侧一个导航型图标，中间标题，右侧操作。Material 3 把它叫顶部应用栏，主责是页面外壳；iOS 把它叫导航栏，主责是层级（返回）。名字不同，结构相同——这是两套体系独立收敛出来的结果，比任何教程的"构成图"更可靠。

**三格不是三个抽屉。** 这是最常见的误读：既然有三格，每格都能塞东西。实际上每格是一个承诺，塞进去的东西必须回答那个问题。中间那格塞了搜索框，它回答的就不是"我在看哪个对象"，而是"可以去哪找"——换了承诺。

## 二、名字：按问题命名，不按位置命名

同一个位置，两套官方说法正好相反：

| | 底部那条 | 顶部那条 |
|---|---|---|
| Material 3 | 导航栏（navigation bar），切换 3–5 个版块 | 顶部应用栏（top app bar） |
| Apple HIG | 标签栏（tab bar），切换版块 | 导航栏（navigation bar），返回 + 标题 |

不矛盾，只是各自按"这个组件主责回答哪个问题"命名：Material 认为底部那条的活是"去哪个版块"，iOS 认为顶部那条的活是"往回走一级"。

所以团队里能用的问法不是"这个组件叫什么"，而是：**"你说的是切换版块，还是返回上一级？"**

中文还多一层双关：**"标签栏"同时指底部版块切换（tab bar）和页内选项卡（tabs）**。两个都是结构导航，但一个跨版块、一个在本版块内，判据完全不同——前者项数少、永远在；后者可以多、可以滚、可以折。名字一样，规则不一样，这是最容易出事的地方。

## 三、中间那格只有一个

能不能借，不看塞的是什么控件，看**借走之后还有没有别的地方在回答"我在看哪个对象"**。三条：

1. **没有当前对象**（首页、版块首页）——可以借。这页还不欠一个"哪一条"。
2. **有当前对象，但对象名另有稳定位置**——可以借。这个"位置"要能扛住滚动：面包屑末级、不滚走的大标题。
3. **两者都没有**——借走就等于让用户自己记。

三个常见的例子都落在第 1 条上：产品主页那种居中型顶栏、早期网易云音乐首页中间的分段控件、淘宝首页占整行的搜索框——它们都不约而同地发生在"还没有具体对象"的页面上。

### 四种借法，四种代价

| 塞法 | 谁在回答"在哪" | 代价 |
|---|---|---|
| 标题 | 它自己 | 占掉整格，右侧操作只能压到 3 个以内 |
| 分段（同一对象的分段） | 没人，只答"哪一段" | 对象名消失；而且它必须跟着滚动走，否则是假回执 |
| 搜索入口 | 没人 | 借位最彻底；只在这一页的任务是"找"时成立 |
| 大标题（滚动收起） | 内容先答，滚走之后交给顶栏 | 只在滚走之后成立；滚动前顶栏中间是空的 |

第 2 行那条要单说。**分段如果只是"滚到某一段"，它就必须跟随滚动。** 不跟随的后果不是观感问题，是假回执：顶栏说"物流"、眼睛在看"备注"，控件和它控制的东西不同步。演示里 ② 的中间亮哪一项，是按"哪一段落在视口中间"算出来的，不是点击时写死的。

第 3 行那条也常被误解。搜索放在顶栏，说的不只是"这里能搜"，还说了**搜哪个范围**。淘宝首页的搜索跨商品和店铺，占一整行是顺势；一个订单列表页的搜索只搜本表，它属于内容，放在列表上方第一行更诚实。同一个搜索框，两个位置是两种承诺。

## 四、B 端顶栏没有中间那格

手机的三格是"返回 / 标题 / 操作"的结构。B 端桌面是**"路径 / 操作"两段**：左边整条面包屑，右边操作；标题下沉成内容区的大标题。

所以"中间那格能不能借"这个问题在桌面端不成立，它换成了另一个问题：路径占多宽、长到什么时候折。

这样摆之后，"我在哪"由三处分担：

- **侧边高亮**回答"哪个版块"；
- **面包屑**回答"哪条链"，末级就是对象名；
- **内容区大标题**回答"哪个对象"，但它会被滚走。

版块名在侧边和面包屑里各说一遍，是刻意的冗余——版块名短、位置固定，重复一遍的成本比"用户找不到自己在上层哪一支"低得多。而对象名只在一处常驻（面包屑末级），大标题那份是会被滚走的那份。

代价也很实在：侧栏宽度是每个页面都要付的横向空间；面包屑一长就得截断或收进省略号，那时"我在哪"要重新分配。

## 五、滚动的那一刻，边界才出现

演示里五张顶栏在开始滚动后都出现一条阴影。这不是装饰。

顶栏和内容之间是不是有边界，回答的是"这两块是什么关系"：

| 顶栏的样子 | 说的关系 |
|---|---|
| 扁平、和背景同色 | 一体，内容不是从它下面经过 |
| 滚动后出现阴影 | 它浮在内容上面，内容在底下走 |
| 颜色填充 | 它是一块独立的区 |
| 压在图上 | 它临时浮在内容上，要负责自己的可读性 |

最后一行是代价最明确的：透明栏压在一张亮图上的时候，字就没了。这时候要么给一层 scrim（压暗或渐变的底），要么滚动开始后立刻转成有底。**边界也是"下面还能滚"的唯一视觉证据**——页面滚到底、没有边界了，用户才知道到底了。

演示里五张用的都是"滚动后出现阴影"这一种，其余几种没有做成可切换的对照。

## 六、右侧挤不下时收谁

右侧操作的经验上限是 3 个，超过就折进"更多"。这个数字不是规范，它取决于这一屏多宽、图标能不能认出来、动作频率怎么分布。

判据和[一条主路](../一条主路/README.md)里折叠那一节是同一条：**关着的时候，还能不能回答"有几个、哪些"**。只写一个"⋯"，连"有几个"都答不了。

不能收的两类：**退出**（返回、关闭——随时可能要用），**当前任务的唯一下一步**（收了就走不下去）。

## 为什么这样判断

- 三格的分工不是推导，是两份指引的独立收敛：Material 的顶部应用栏和 iOS 的导航栏画出来几乎一样，一个叫应用栏、一个叫导航栏。这个"同名不同物、同物不同名"的现象本身就是证据——名字跟着主责走。
- "中间那格能借"的三条，来自"还有没有别处回答"。它是判据，不是观察：演示里 ①②③④ 用的是同一份内容，唯一变量是顶栏，所以灯灭只能由顶栏引起。
- 分段必须跟随滚动，是从[入口与回执](../入口与回执/README.md)的假回执推的：控件和它控制的对象不同步，就是假回执。这一条不是"体验更好"，是"不一致"。
- 搜索的归属由范围决定：同一个控件在首页和列表页说的是两件事，这属于[承诺与边界](../承诺与边界/README.md)那一类判断——控件只该宣布一件承诺。
- "B 端没有中间那格"是布局事实，不是偏好：路径和操作两段排下来，中间就没有留给标题的位置。
- 阴影那条是观察：五张顶栏的阴影出现时机完全一样，和中间放什么无关。

## 适用条件和取舍

- **① 是最省的默认。** 只要有当前对象，先考虑它；代价是右侧只剩三个位置。
- **② 只在"同一对象的分段"上成立**（概览 / 物流 / 备注）。节点级切换（收件箱 / 已发送）是另一回事：那时选项名本身就是位置，可以占中间——但前提是这一页不再有别的对象名要显示。
- **③ 只能放在"这一页的任务是找"的页面上。** 详情页上用它是借位借错了，演示里保留了这张，就是为了看"借走之后丢什么"。
- **④ 依赖内容区自己滚。** 整页滚动的页面里，大标题会连顶栏一起滚走，交接就失效了。
- **⑤ 是桌面端的形态。** 窄窗口下侧栏收起、面包屑截断，它就退化成普通顶栏；那时"哪条链"要靠标题和返回补。
- 演示里的 172px 侧栏、640px 内容宽、288px 手机宽都是演示参数，不是规范值。
- 这篇只处理顶栏。底部标签栏、平板 rail、抽屉导航属于"同一棵树换壳"，没有展开。

## 例子

- **淘宝首页**：标题和功能图标在上，搜索框单独占第二行。内容太多时，它的做法是**加一行**，不是把标题挤掉。
- **微信首页**：标题占中间，搜索在列表第一行。搜索属于内容，不属于外壳。
- **早期网易云音乐**：分段控件占顶栏中间，切的是首页的几个内容区。那是"还没有具体对象"的页面。
- **订单详情页**：中间放标题、右侧最多三个操作；要显示订单号，就在标题里写短号（演示里是"订单 0032"）。
- **B 端订单管理**：左侧栏高亮"订单管理 / 全部订单"，顶栏面包屑"订单管理 / 订单 / 0032"，内容区大标题"订单 0032"。滚到哪，路径都在。

## 稳定性

| 内容 | 稳定性 | 写法 |
|---|---|---|
| 三格各管一件事 | 定义 | 写死 |
| 中间那格借用的三条判据 | 定义（判据） | 写死 |
| 分段必须跟随滚动 | 定义（回执） | 写死 |
| 搜索的归属由范围决定 | 默认 | 可偏离：整站搜索型产品 |
| B 端"路径 / 操作"两段式 | 观察（布局事实） | 写死，例外是带一级导航的官网顶栏 |
| 滚动时出现边界 | 默认 | 可偏离：始终有底、不需要边界 |
| 右侧 3 个操作图标 | 经验值 | 不是规范；真正的约束是宽度、可辨识度、动作分布 |
| 大标题的交接点 | 经验值 | 演示里取"大标题底部离开内容区顶部 6px"，未测 |
| 侧栏 172px、内容 640px | 演示参数 | 不是规范 |

## 还没定

- 平板 rail、抽屉导航、底部标签栏三者怎么选，没有讨论（留给"同一棵树换壳"那篇）。
- 面包屑在窄屏的三种折法（横向滚动、两行、省略号）没进这篇，留给面包屑。
- ④ 的交接点只试过 6px 这个值，没有测"早一点或晚一点"的差别。
- 返回（历史栈）和面包屑（结构树）不一致时怎么办——从搜索结果进详情，按返回回搜索、点面包屑回分类——只在演示里点了一下，没有展开。
- 顶栏高度、标题字号、图标尺寸的具体数值，属于设计规范，留给 J 簇。
- 演示只做了 288px 和 960px 两档宽度，平板档没做。
