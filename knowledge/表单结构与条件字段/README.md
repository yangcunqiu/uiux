# 表单结构与条件字段

安排表单结构，需要弄清哪些信息要一起看，哪些回答有先后依赖，以及哪些内容要一起生效。页面数量、字段数量和提交次数可以不同。根据这些关系安排字段顺序、列数和分段方式，能够解释具体取舍。单凭字段数不能决定要不要分步。

## 顺序与列数

控制业务类型的字段应放在依赖它的字段之前。例如先选发票类型，再填写该类型要求的附加信息。把省份与城市、金额与币种作为可辨认的一组，避免在换行后把对应关系拆散。字段顺序须能用填写任务解释，数据库列的顺序本身不能提供这种依据。

单列是常用起点，阅读顺序连续，长标签、错误和帮助说明也较容易排布。短字段可在没有顺序冲突时并排，尤其是需要一起核对的成对字段。多列可以节省高度，也会缩小输入宽度，增加换行后的视线转移。一项报错时，同行其他字段下方可能出现空白。以真实内容、窄窗口和错误状态判断是否仍放得下。

## 业务类型改变后，之前填写的值怎么办

**同一表单内，业务条件改变后不再适用于本次业务的字段，不参与本次校验，其旧值不得作为本次业务输入提交。** 这里的前提是字段在业务上不适用。仅切换标签页、折叠段落或暂时滚出视口，仍可能是同一份有效表单的组成部分。

草稿是否保留是另一个决定。假设某种业务类型要求填写企业编号，换到另一类型后本次无须该编号。若仍是同一家企业，切回原类型时原编号仍有效，可以在草稿中保留并恢复，省去重填。如果企业对象或编号的有效条件已改变，应清除失效值，并说明受影响的输入。保留草稿不能导致无关旧值被提交，过期的必填错误也不能阻止新类型提交。接口用字段缺失、空值或明确清除操作表示“不适用”，由前后端根据新建或编辑语义约定。

验证时可以先在类型 A 填值，再切到不适用该字段的类型 B，分别核对 B 的校验、实际提交内容及重新打开的业务结果。再切回 A，检查草稿恢复策略。对另一个标签页中仍适用的字段，应按整表的提交范围验证。这两种操作检验的是不同前提。

## 分组、分步与标签页

| 结构 | 成立条件 | 需要处理的代价 |
|---|---|---|
| 标题分组或卡片分组 | 多段要一起看。普通标题适合同一件事的小节，明显独立、可选或可重复的对象值得更强的视觉边界。 | 卡片增加间距和占高。同一层级用不同的分组方式应有内容上的原因。 |
| 分步 | 任务有真实先后，或必须先完成当前段才能继续。 | 其他步骤不可见。下一步负责当前步校验，最终提交才使整项操作生效，除非产品另有明确的保存动作。 |
| 标签页 | 各段并列，可任意顺序完成，仍可能共同提交。 | 其他标签中的错误需要位置提示，提交后应能到达出错段。 |
| 页内锚点 | 用户需要跳到较远位置，同时保留同一页中所有内容。 | 导航占宽，窄屏要另行安排。锚点本身不改变提交范围。 |

错误可能出现在当前面板以外时，段落标记、错误汇总和可跳转位置比只改变某个标签的颜色更有用。每段是否独立保存由实际生效关系决定。[保存范围与提交时机](../保存范围与提交时机/README.md)
