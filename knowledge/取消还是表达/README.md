# 取消还是表达

界面里一个状态改变，会牵动可见的变化；最贵的一类是**布局变化**——它把别的东西推走。处理它的顺序不是「给不给加动画」，而是先问更前面的事：**这个变化在表达什么。** 不表达什么的，要么取消，要么拿到裸跳的执照；表达什么的，只留一个来源、对齐接缝，最后才轮到时长和曲线。

判据一句话：**变化要么被取消，要么必须被看见；中间那种「发生了、但没人知道为什么」最贵。**

## 先看演示

[打开演示](demo.html)（单文件，双击即可，不需要本地服务）

三段，每段只研究一个因素：

1. **归因**：同一个面板长高一条消息、推走页脚。触发（我点的／后台静默／后台同刻横幅）× 策略（预留／裸跳／高度过渡／定框）两个旋钮。观察页脚位移和「你知不知道为什么」——同样的 +54px，归因在不在，读起来是两件事。
2. **圈**：切页签整块替换面板（一次重置）。只改两版内容的高度差。小差（24px）页脚没人计较；大差（280px）页脚飞出去——归因没问题，追视丢了。
3. **夹带**：先把筛选点成「未读」再切页签。整块替换把几何变化盖住的同时，也把状态变化一起盖住。试试不看读数能不能发现筛选被重置。

键盘：全部控件是按钮，Tab 可达；系统开了「减少动态效果」时，③退化为②，页面会显示提示。

## 我们的理解

### 一、四级阶梯，按谁付账排

| 级 | 做法 | 谁付什么 | 边界 |
|---|---|---|---|
| ① 取消 | 变化不发生 | 付结构工作，可能付内容或耦合损失 | 总是最好，不总是可达 |
| ② 裸跳 | 发生、不表达 | 无人付账 | **仅限归因免费域**（见二） |
| ③ 最小表达 | 动画把因果接上 | 所有人付一点时长 | 域外必用；域内大位移可自愿用 |
| ④ 围堵 | 定框、钉锚、限幅，把跳变圈住 | 用户付一瞬重定位，可压到近零 | 兜底，但常是正当设计而非妥协 |

②不是垃圾档，是**有执照的便宜档**。梯子管下限（归因必须被接住），不管上限（大位移可以自愿买③换可读性）。

①的具体机制和成本：

| 机制 | 做法 | 付什么 |
|---|---|---|
| 上收 | 共有部分提到变化区外（两个 Tab 共有的 Switch 放共享底栏） | 结构工作；前提是共有的真是同一件东西——只是相似时，你造了一个以后会被拆穿的壳 |
| 预留 | 先付空间（空位、min-height），到达时无变化 | 空闲期空地；估错回到原点。**取消可以按概率摊销**：预留一条的量，第一条免费 |
| 定框 | 外框几何固定，变化吸进内部滚动 | 内容被裁或出滚动条——「装不下」本身是个新信号 |
| 限幅 | 只取消常见幅度 | 罕见 case 仍需③④ |

③④的材料成本是独立的账：位移便宜（transform 走合成器）；尺寸贵（height 每帧 reflow，scale 伪造会扭曲内容）；**正在输入的区域禁表达**——动画等于在动作和反馈之间插延迟。

### 二、裸跳的执照：圈＋窗＋认领

多数布局变化是**副产品**，不是消息——「这个 Tab 更高」没人当信息读，但下面所有东西都被它推走。副产品分支的判据不是「必须表达」，是**归因**：用户能不能不费力地说出「它为什么动了」。

归因免费有三个来源：

| 来源 | 机制 | 例子 |
|---|---|---|
| 自己实时造成 | 用户就是原因 | 打字时长高、拖动 |
| 响亮共现信号 | 同刻有更大的信号把原因说完了 | 点 Tab 后整块内容换掉 |
| 幅度低于察觉 | 跳变没过察觉门槛 | 几 px 的行高微调 |

「响亮共现」不是一个音量，是三件可以分开失败的事：

| 条件 | 检查问题 | 失败例 |
|---|---|---|
| 同刻 | 变化和原因落在同一个注意瞬间 | 异步数据 1 秒后孤身到场 |
| 罩住 | 跳变区域 ⊆ 重置区域 | 点 Tab 只换面板，页脚在圈外被推走 |
| 认领 | 用户触发，或同刻有告示 | 后台自动应用筛选，无人认领 |

机制：用户引发的整块置换是一次**局部重置**。变化盲（change blindness，Rensink 等人 1997 年起的系列研究）表明同一刻有更大瞬态时，人对大幅改动的察觉率很低——不是看见了没在意，是真的没看见。反过来用：**重置之后用户重新扫视，得到的是「一个新场景」而不是「一个动过的旧场景」，跳变不作为变化存在，自然不需要归因。** 圈内连搬移都免费（点排序后行瞬移，常见界面就这么做）；执照与幅度无关。

### 三、两笔账，别混

| 账 | 用户在心里问 | 由谁管 | 失败的样子 |
|---|---|---|---|
| 归因 | 为什么动了 | 执照（圈＋窗＋认领） | 停下来找原因 |
| 追视 | 我刚才看到哪了 | 幅度 | 原因清楚，但眼睛丢位，重扫一遍 |

Dialog 内容大范围变高：归因有照（内容同刻置换）、追视贵——买③买的是**眼睛跟得上**，不是知道为什么。还有第三种付款理由：**运动里有对应关系要读**（排序后 FLIP 读出哪行去了哪、飞行把动作和结果连起来）——这种运动本身是信息，永远不在免费域里。

### 四、一个反转

连续输入区里判据倒过来：不是变化要表达，是**表达被禁止**。打字时容器长高不取消也不加过渡是对的——用户自己实时造成的，加动画反而在动作和反馈之间插延迟。

### 五、黑暗面

执照是合法化的变化盲，而变化盲对几何是福、对状态是祸。**圈只覆盖位置和尺寸；值与状态的变化即使在圈内也必须另行交代。** 切 Tab 顺手重置了筛选条件：用户看不见，事后靠后果才发现。这不是「跳变没动画所以没关系」的问题，是「跳变里有没有夹带状态」。

## 为什么这样判断

- 四个原文案例是骨架的锚：Dialog 高度大范围变化加过渡（追视账）、输入中的高度变化不加过渡（反转）、两个 Tab 共享 Switch 而取消高度变化（上收）、Card 变 Dialog 用同一容器（表达分支）。它们是案例加立场，不是实验。
- 阶梯、执照、两笔账是机制推论加本工作区讨论结论；「归因在不在，同一跳读起来不同」在演示第 1 段可复现，但演示不测人。
- 变化盲是可复现的实证现象（[Rensink 等，To see or not to see](https://scholar.google.com.mx/citations?view_op=view_citation&hl=zh-CN&user=s_5xXxQXpU0C&citation_for_view=s_5xXxQXpU0C:gsN89kCJA0AC)）；「重置把运动变成新场景」是它引出的机制推论，没有在界面场景做过实验。
- 工业界有一份同型对照：Chrome 把累积布局偏移（CLS）当伤害计分，但用户输入后 500ms 内的位移排除在计分外——「用户自己造成的位移不算伤害」被写成了机器可执行指标（[web.dev/articles/cls](https://web.dev/articles/cls)；⚠️ 500ms 是工程政策值，不是感知阈值，本会话未能重新打开原文核对，引用前应复核）。
- 「圈内位移免费」是对常见界面做法的观察，不是测量。

## 适用条件和取舍

- **结构不在你手里时，①整级不可达**：第三方组件、平台限制——Props 是墙上的门，没预留这个口子就进不去（见[黑盒与源码](../黑盒与源码/README.md)）。这时参数（③）是止损：一行 CSS 能盖住「闪一下」，盖不住「跟不上」。
- **④的执照比看起来窄**：定框内滚把布局变化换成滚动，前提是这块区域的职责容得下「装不下」——Dialog 正文、聊天记录内滚很正常；卡片网格定高裁剪，剪的就是内容本身。
- **「减少动态效果」开启时③退化为②**，执照和①④变得更重要——这也是把②写成有执照的正当档位、而不是垃圾档的原因之一。
- 本篇只管「变化怎么处理」；变化的编排（先后、方向、曲线、时长）见[动效的层级](../动效的层级/README.md)和[点击之后](../点击之后/README.md)；两段状态交界的一致性见[接缝](../接缝/README.md)。
- 演示里的 24px／280px／900ms／260ms 都是演示值，不是推荐值。

## 稳定性

| 内容 | 稳定性 | 写法 |
|---|---|---|
| 判据：要么取消、要么被看见 | 模型 | 写死，标注为讨论结论 |
| 四级阶梯与各自的账 | 模型 | 写死 |
| 裸跳执照（圈＋窗＋认领） | 模型 | 写死；成色是机制推论，非实验 |
| 两笔账（归因／追视） | 模型 | 写死 |
| 变化盲→重置→免费 | 实证现象＋机制推论 | 现象写死，推论标注 |
| CLS 500ms 排除窗 | 工程政策 | 引用，标注未复核 |
| 圈大小、幅度阈值 | 待校准 | 留空（见「还没定」） |
| 演示数值 | 演示值 | 不是推荐值 |

## 还没定

- 圈的大小怎么估：占视口的比例？结构变化的数量？目前只有两个锚点——整块面板置换算、工具栏变色不算（圈罩不住跳变区）。
- 幅度阈值：多大算「追视贵」。信号是「读位置会不会丢」，没有数，也不确定该不该有数。
- 变化盲在界面场景（短时、局部、有任务在身）的察觉率没有实验数据；「圈内位移免费」尤其缺反例核对——刻意设计的 FLIP 排序动画说明有人认为对应关系值得读，与「免费」的主张张力未解。
- CLS 输入排除窗（500ms）与感知绑定的关系未核对，引用前应打开原文核实。
- ④「职责容得下装不下」的判据没有展开，只有正反例各一。
