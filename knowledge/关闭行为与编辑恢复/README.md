# 关闭行为与编辑恢复

关闭编辑界面时，需要分别处理当前视图的去留，以及这次编辑或已经发出的操作所处的状态。对使用显式保存的编辑器，“取消”应放弃尚未提交的修改。已自动保存、已显式保存或已提交的内容，不能因一个关闭图标而被含糊地描述成“已取消”。

## 编辑中关闭

桌面对话框常提供取消按钮、关闭图标、Esc 和点击遮罩。前三者是明确的关闭或取消入口，点击面板外面也可能只是想查看或操作背景。对轻量选择，多个关闭入口方便退出。对已填写很久的内容，意外关闭代价大，可检查未保存的修改、允许恢复，或收窄点击遮罩关闭的范围。若“取消”和“关闭”处理草稿的方式不同，要在名称及反馈中体现。

模态界面要求用户先处理当前层，遮罩接收点击，背景操作不执行。非模态辅助面板允许点击背景，点外部可能既关闭面板又执行了背景动作。不要用拦截背景的遮罩实现本来要求可操作的背景。按下始于面板内、拖选文字后在遮罩松开时，应避免被当成一次有意的遮罩点击。Esc 的作用对象还要考虑输入法候选、层内展开的菜单和最上层面板，避免一次操作连续关闭两层。浏览器返回和系统发起的关闭也有各自的触发条件。

## 草稿的归属与恢复

短时撤销适合立即发现误关的情形。同一会话内保留输入可避免重填，跨会话续填则要有明确的草稿对象、生命周期和恢复入口。新建应从可辨认的初始状态开始。若要恢复之前未完成的新建，可提供“继续草稿”和“重新开始”。编辑已有对象时，恢复的是该对象的草稿。将旧值无提示地填进下一次新建，可能把一个对象的信息提交到另一个对象。也要考虑会话到期、权限改变或对象已被其他人移除时，现有输入和恢复能力如何说明。

## 已发出请求时关闭

此时关闭本地视图不能证明服务端撤销。短请求且结果必须在此处处理时，可以暂时拦住关闭，显示处理状态，并避免等待无限延长。此时固定本次已提交内容，避免用户继续编辑后误认正在处理的新值。支持后台继续时，允许收起，并让用户重新进入后能看见同一任务的进度与结果。提交后立即关闭也可用于结果能够在别处核对的任务，失败必须仍有反馈路径。

只有业务接口支持真正取消时，才提供明确的“取消任务”。接口的重复执行保证和撤销能力需要分别验证。服务端明确校验失败时，恢复编辑、保留可修正内容。对结果尚未知的请求，按[操作受理与结果反馈](../操作受理与结果反馈/README.md)核对。
