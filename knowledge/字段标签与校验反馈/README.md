# 字段标签与校验反馈

字段标签应在填写前说明要回答的问题，在输入和复查时仍能识别这个值的含义。只用占位文字兼作标签，输入后问题便消失。浮动标签可以在窄屏保留名称，需要核对缩小后的文字是否清晰。简短、极熟悉的登录字段有时能靠上下文辨认，将同样做法扩展到长表单容易失去对应关系。

## 标签和说明放在哪里

顶部标签能把长名称和多语言文本换成额外高度。侧排节省高度。右对齐的标签末端靠近输入框，左对齐让各标签的起点整齐，便于在字段列表中扫描。标签长度、可用宽度、是否逐项填写都会改变取舍。例如在短表单上观察到眼睛从标签移到输入框的时间较短，只能说明那次注视转移。整表还包含辨认、思考、输入和修改，这个时间不能直接代替跨场景的完成时间。[Penzo 的表单标签观察](https://www.uxmatters.com/mt/archives/2006/07/label-placement-in-forms.php)

会改变填写方式或决定提交结果的规则应在输入前可见，例如金额是否含税、何时需要附件。短格式例子可放在占位提示中。只有少数人需要的补充说明可以收进帮助按钮，并提供键盘和触摸入口。只在报错时给格式要求适合可以低成本修正的输入。如果用户会因此白填一整段，宜提前说明。标签采用简短名称或完整问句时，可按语言和句意使用标点，标签与值的关系应能从位置和语义中辨认。

必填标记、校验、错误说明和最终提交拦截应针对同一条件。重要但允许留空的字段不宜标作必填。标记必填或标记选填均需说明约定，同一个产品应避免让未标记字段在不同表单中代表相反含义。“本页均为必填”可用于确实全部必填的短表单。星号简短但需理解约定，文字清楚但占宽。标签后标记可保留标签起点整齐，框边标记在宽度不一时较难对应。允许保存不完整草稿时，正式提交的必填规则不应阻断草稿保存。

## 何时报告错误

输入中可以说明字数、要求、强度或异步检查进度。用户尚在输入时，过早把半个值判错会打断填写。失去焦点后可检查已经修改过的字段格式。仅用 Tab 经过空字段时，通常将必填错误留到提交。提交时验证整份业务输入，将服务端发现的问题定位到能修正的位置，并把焦点带到第一个出错字段。短表单可以只在提交时集中检查。长表单若将所有错误都留到最后，会增加返工。

用户开始修正时可以撤下过时的错误，仍需按新值判断有效性。异步检查应避免将旧值的结果显示在新值下。报错后保留用户输入。说明可放在框上，错误靠近框下，代价是占用高度。共用一处展示时，替换后的错误必须包含改法，如“请输入 11 位数字”。长表单的汇总指出剩余项和位置，能把焦点带到出错字段。字段旁负责解释怎样修改。

表单未完成时，默认可保留提交操作，点击后说明缺项并定位。短表单、全部前提都在眼前且缺少的那一步单一明显时，暂时禁用可表达尚未就绪。原因要在可见位置，原生禁用按钮本身收不到键盘焦点。可点击的“还差 2 项”能补充数量，仍需能定位具体字段。业务条件改变后的校验范围见[表单结构与条件字段](../表单结构与条件字段/README.md)。
