# 选项检索与展开方式

决定怎样呈现一组选项，先看用户掌握什么信息。知道名称时可以搜索，知道类别时按组浏览，熟悉位置或顺序时按字母、时间等稳定顺序查找。用户连可选项是什么都不知道时，单加搜索框帮助有限。是否值得搜索取决于输入成本、可见范围和名称是否为人所知。固定的选项数量难以替代这些条件。

## 排序、置顶与可用性

置顶当前值只改变位置，预选默认值则改变“是否已经作出选择”。为便于寻找，可在单独且有名称的区域复制当前值，保留原列表顺序，两处同步选中。最近使用区适合经常重复选择且主要靠输入查找的任务。对靠类别位置浏览的人，顶部高度反复变化会移动熟悉的分组，可将最近使用放到搜索建议中。筛选器默认收窄结果时，人可能误判数据范围。

短列表保留暂时不可用项及原因，有助于理解有哪些可能。长列表中一直无权使用的选项可以省略，前提是符合产品的信息可见性约定。行尾数量为零时，隐藏和禁用对选项位置及能力说明各有代价。

## 展开结构与容器

需要同时比较多组内容时，可使用支持多组同时展开的折叠区。单开模式节省高度，展开会推动后续内容，靠近窗口边缘时要让标题仍可定位。单行分段选择适合短、互斥、能同时显示的值。若裁掉尾部选项而没有可发现的入口，就失去了同时展示的优势。分段选择改变取值，标签页切换的是内容面板。已选标签和可选项的点击含义也要能区分。允许输入任意标签能省去寻找选项的步骤，但会引入重复和拼写变体。需要干净的值集合时应提供建议或校验。[操作入口与当前值展示](../操作入口与当前值展示/README.md)

依附按钮的浮层保留来源和较短的返回路径，代价是显示空间和键盘空间有限。需要同时参考父页面时可选浮层或半高面板。选择本身有名称、需要再次进入或分享时，独立页面或可定位的地址更有价值。全屏或底部面板需要重新交代正在改哪个条件、怎样完成。触摸设备还要考虑可触达区域和软键盘。

## 筛选什么时候应用

面板与结果同时可见、更新代价低时，调整后实时更新能直接显示影响。面板遮住结果且应用会重置分页、清空选中或重排列表时，可以先编辑后显式应用。关闭尚未应用的面板应按草稿约定处理。实时生效的筛选在关闭面板后仍保留，恢复原状需要明确的重置操作。

给出“预计匹配数量”需要相应的数据能力。用相同筛选条件、权限范围和相容的取数时点计算。数据会变化时应区分预估与实际处理数。结果本来可见时可复用列表已有的数量。单独计数可能另有查询成本。不能合理提供计数时，可在应用后显示实际结果。构建条件很费时才值得另存未应用草稿，展示时应与已生效条件区分。
