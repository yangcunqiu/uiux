# 表单骨架

表单不是一堆字段的列表，而是一组需要一起回答的问题，外加一个提交边界。骨架就是：先问什么、后问什么，一列还是多列，分成几段，分段用标题、卡片、步骤、标签页还是锚点；以及条件字段什么时候出现、值怎么办。

字段多不多、7 个还是 15 个，只是症状。真正要回答的是那三句：**这些字段是不是要一起看、一起答、一起交。** 提交边界在[提交边界](../提交边界/README.md)；标签、必填、说明在[标签在场](../标签在场/README.md)；校验和错误在[填错的时机](../填错的时机/README.md)。

## 先看演示

三个页面都双击打开，不需要本地服务。

1. [列数与字段顺序](列数与字段顺序.html)：同一个 11 字段表单，切 1 / 2 / 3 列；开关帮助、让「详细地址」报错；切「任务顺序 / 条件倒置」。读数：高、列宽、实际列数、折返、单行最多、省/市是否同一行。

   - 1 列 876px、折返 0；2 列 502px、折返 5、省/市同一行；3 列 352px、折返 3、省/市被拆开。
   - 3 列的折返反而比 2 列少（行少了），但单行更宽、字段更窄——不是「列多更差」，是多列各有代价。
   - 条件倒置：税号跑到发票类型前面；先填税号，再把类型改成普通发票，字段消失、值也不保留。

2. [分组、分步、标签页、锚点](分组分步标签锚点.html)：6 个字段分 3 段；切平铺 / 标题 / 卡片 / 标题 + 1 卡 / 分步 / 标签页 / 锚点；点提交留空，看「错误可见」和提交边界。

   - 分组 / 锚点：6/6 字段、错误 3/3；分步 / 标签页：2/6 字段、错误 1/3。
   - 分步第 1/2 步只有「上一步 / 下一步」，最后一步才有「提交」；标签页只有一个提交，在面板下方。

3. [隐藏的值](隐藏的值.html)：发票类型切普通，税号字段消失；三种处理：清掉 / 保留切回恢复 / 保留并提交（错误）。看输入值、草稿和提交内容三层。

## 一、顺序与列

### 顺序：条件先于被它控制的字段

字段顺序不是数据库字段顺序，是用户回答的顺序。**条件必须先于被它控制的字段**；一个字段如果会因前面的答案消失，它就不该出现在那个答案之前。

- 发票类型 → 税号：类型在前；切普通发票时税号消失；先填税号再改类型，字段没了，值也不该留着。
- 省 → 市：省在前；两个字段是一个单元，不要被列数拆开（3 列就会拆）。
- 数据库顺序把税号排在发票类型前面，用户会先填一个可能马上消失的字段；这不是字段多，是顺序错了。

「条件倒置」是反例，演示里可以切。

### 条件字段消失时，值怎么办

三个层次别混：

1. **输入值**：看不看得见；
2. **草稿状态**：要不要留着，切回来能不能恢复；
3. **提交内容**：这次回答成不成立。

「清掉还是保留」是前两层的选择；**隐藏的字段不能作为这次回答提交**，是第三层的契约。

- 旧值在新条件下**不成立** → 清掉，并告诉用户（国家从中国改成美国，省/市不适用）。
- 旧值**仍成立**，只是暂时不问 → 可以保留在草稿里、切回恢复；隐藏期间不提交（同一家公司的税号）。
- 无论哪种：隐藏字段不参与必填/校验，错误不能指向它；后端收到 `null` 或字段缺失，表示「不适用」。
- 只清值不提示、保留值却提交、字段消失但校验还拦着——三种都是 bug。

演示里三种处理都做了；「保留并提交」能看到 payload 里带着用户看不见的税号。

### 列数：你付的是高度，还是折返

多列省高度，付出的是折返和成对字段被拆。演示里的数（11 个字段、短标签、同宽输入框）：

| 列数 | 高 | 折返 | 省/市同一行 | 列宽 |
|---:|---:|---:|---|---:|
| 1 | 876px | 0 | 否 | 840px |
| 2 | 502px | 5 | 是 | 409px |
| 3 | 352px | 3 | 否 | 265px |

- 折返 = 换一行时从行尾回到下一行行首的次数；演示里用箭头标出。列多、行少，折返次数不一定更多（3 列比 2 列少），但单行更宽、字段更窄——代价不是一条线性的数。
- 省/市是成对字段：2 列时同一行，3 列时被拆开。成对字段要包成一个单元（跨列或子网格），不能靠列数碰运气；拆开就是顺序错了。
- 帮助/错误多时，某个字段多一行，整行被撑高，旁边的字段下方留洞；一个字段的问题变成整行的节奏问题。
- 窄屏（720px 以下）多列降回 1 列，省下的高度还回去；多列不是响应式的免费午餐。
- 多列是排版工具，不是分组工具；它不制造「一组」，只改摆法。

**单列是默认。** 多列只给短、独立、成对的字段：省/市、开始/结束、金额/币种；长标签、依赖、帮助多、错误多，回单列。标签本身的左右对齐（顶标签、左标签右对齐/左对齐）在[标签在场](../标签在场/README.md)，不要和多列混成一个变量。

## 二、分组、分步、标签页、锚点

四种结构，四种「藏法」：

| 结构 | 藏什么 | 错误可见 | 适合 |
|---|---|---|---|
| 平铺 / 标题 / 卡片 | 不藏 | 3/3 | 字段不多、要一起看 |
| 分步 | 别的步骤 | 1/3 | 有真实先后、任务长 |
| 标签页 | 别的标签 | 1/3 | 并列、可任意顺序 |
| 锚点 | 不藏，只加导航 | 3/3 | 长页面、都要看 |

### 分组：标题 vs 卡片

- **标题**：给一段起个名字，轻，不藏内容；同一页可以有几段。
- **卡片**：更重的边界（边框、底色、内边距），也更占高度；卡片一多，页面就像一摞盒子——这就是冗杂。
- 卡片给「这一块是独立/可选/可重复的对象」或页面级的大块；不是每两个字段就包一张卡。标题给同一件事里的小节。
- 同一张表可以「其余段用标题，只有发票信息这种独立块用卡片」（演示里的「标题 + 1 卡」）；也可以卡片里再用标题分小节。**一套层级只用一个视觉边界**，不要同一层这张卡、那张标题，用户找不出理由。
- 分组不改变提交边界：整张表还是一个提交；分组只是阅读边界。

### 分步：只有真实先后才用

- 一次只显示一段；第 1/2 步只有「上一步 / 下一步」，最后一步才有「提交」。下一步只校验当前步，不提交；提交才校验整张表。
- 步骤项上是编号 + 连接线；红点是错误地图；提交跳到第一个出错的步骤，其余错误要自己切过去看。
- 每步校验、上一步/下一步、最终复核都是真实分步的一部分；不要因为「有三组」就分步。
- 分步的代价是看不见别的步骤、上下文丢失、来回切换；只有真实线性顺序、任务长时才值。

### 标签页：并列，不是顺序

- 标签条 + 面板；切换标签只换面板，不提交；整张表只有一个提交，在面板下方。
- 标签是并列的段，用户可以任意顺序完成；不适合「下一步依赖上一步」的任务。
- 隐藏错误：标签上的红点 + 汇总；提交跳到第一个出错的标签。每个标签都有自己的提交 = 多个表单并排，提交边界跟着标签走，不是「一个表单分了几段」。
- 标签页和分步的外观、语义都不同：标签条 + 下划线 + 面板；分步是编号 + 连接线 + 上一步/下一步。不要用同一种胶囊按钮做两种结构。

### 锚点：不藏，只加导航

- 所有段都在一页，错误仍然全在眼前；侧边导航只是位置感；导航上有错误点。
- 适合长页面、各段独立、用户要跳；代价是导航占宽、长页面滚动、移动端要换形态。
- 锚点是导航，不是分组；它不改变内容可见性和提交边界。

### 隐藏的错误是主要代价

- 分步/标签页把错误藏到别的屏幕；标签/步骤上的红点和汇总就是地图；没有地图，用户提交后只看到一个错误，不知道还有几个。
- 提交跳到第一个出错段是缓解，不是治愈：用户仍然要一段一段切过去改。
- 分步可以每步校验，减少隐藏错误；标签页通常要等到提交，除非每个标签单独校验/保存。

### 阈值是经验值，不是理由

7 个字段分组、7–15 卡片、6–8 折叠、2–5 可编辑表格、>8 抽屉——这些数字服务不同形态，但没说代理的是什么；7±2 是短时记忆的块，不是屏幕上的字段数（前面在[承诺与边界](../承诺与边界/README.md)里纠过）。

真正的信号还是那三句：这些字段是不是必须一起看、一起答、一起交。字段数只是症状。

## 三、怎么选

| 要一起… | 结构 |
|---|---|
| 看（对照、比较、都要在眼前） | 标题分组 / 卡片 / 锚点（不藏） |
| 答，有真实先后 | 分步 |
| 答，彼此独立、可任意顺序 | 标签页 |
| 交 | 一个提交边界（见[提交边界](../提交边界/README.md)） |

再加两条：

- 一列还是多列：短、独立、成对 → 多列；长标签、依赖、帮助/错误多、窄屏 → 单列。
- 条件字段：条件在受控字段之前；成对字段包成一个单元；隐藏的值按「旧值是否仍成立」清掉或保留，但都不提交。

容器（弹窗/抽屉/页面）在[尺寸与容器](../尺寸与容器/README.md)，按钮级在[一条主路](../一条主路/README.md)；这里只讲结构。

## 为什么这样判断

- 列数的数（876/502/352、折返 0/5/3、列宽 840/409/265）是本页实测的几何；折返是示意，不是眼动测量。3 列折返比 2 列少，说明代价不是线性的；这一点是读数直接看的。
- 省/市在 3 列被拆、帮助/错误把整行撑高，是演示里直接看到的；不是「多列一定不好」。
- 条件顺序、清掉/保留/保留并提交，是演示里可操作的状态；「隐藏的字段不能提交」是从 payload 看出来的契约，不是文案建议。
- 分步/标签页的 2/6、1/3，是演示里的可见字段/错误计数；提交边界在第 3 步、面板下方，是读数和按钮位置直接看的。
- 阈值是经验值；7±2 的误用已有结论。字段数不是原因，三句信号才是。
- 没有做用户测试；演示里的 11 个字段、列宽和折返都是演示值。

## 适用条件和取舍

- 单列默认；多列只给短、独立、成对字段；成对字段包成单元；帮助/错误多、长标签、窄屏回单列。
- 分组：标题轻、卡片重；卡片少用；混合只在层级真实时成立；分组不改变提交边界。
- 分步：真实线性顺序、任务长；下一步只校验当前步；提交在最后；有错误地图；不要为分组而分步。
- 标签页：并列、可任意顺序；一个提交在面板下方；有标签错误点；每标签独立提交 = 多个表单。
- 锚点：长页面、都要看；导航不藏内容；移动端换形态。
- 条件字段：条件在前；成对字段不拆；隐藏值按有效性清掉/保留；隐藏字段不提交、不校验。
- 演示不测人：没有测完成时间、误填率、用户偏好；阈值和数都是演示/经验值。

## 还没定

- 字段顺序对完成时间/出错率的影响，没有做测试；条件倒置是反例推理。
- 多列的极限：几个字段、多宽的列、多长的标签开始坏；没有系统比较。
- 长标签/多语言下，列宽和换行的具体处理。
- 条件字段清掉还是保留，在草稿/断点续填里的具体规则；「保留并恢复」的提示怎么写。
- 跨字段校验在分段/分步里的位置；标签页的每标签校验要不要做。
- 分步的最终复核页、每步保存草稿；标签页的每标签独立提交（多个表单）的边界。
- 锚点的当前段高亮、移动端形态；错误点与导航的联动。
- 标题 + 卡片混合的层级规则，除了「一套层级一个边界」还没有更细的判据。
- 7/7–15/6–8 这些经验值到底代理什么，没有数据；7±2 的误用已纠正，但没有替代阈值。
