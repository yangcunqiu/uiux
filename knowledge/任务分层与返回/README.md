# 任务分层与返回

是否打开第二层，先看用户正在补充一个字段，还是开始一项有独立结果的任务。每增加一层，就增加一个“取消”的作用对象，还需要处理焦点、滚动位置、父子状态和遮罩。能在原位置完成的字段选择可以就地展开，不必为简单内容建立独立导航。

在同一个面板里选择已有部门，可以换成选择内容，并用“返回”回到编辑。若要先新建部门，新部门有自己的创建、权限和失败结果，应为这项有独立提交的子任务提供独立的操作层级和结果位置，不能让“取消创建”同时放弃父表单。常用的安排从就地展开、同容器的一步、依附入口的小浮层，到隐藏父层或叠加子层。越靠后需要维护的状态越多。

## 父层是否仍需可见

- 需要读父层信息才能作决定时，叠加子层可以保留参照。子层应足够具体，避免一个更大的新容器把必要参照完全盖住。若子任务本来需要整页，重选入口或第一层容器通常更合适。容器随层级减小是组织上的经验建议。
- 不必观察父层、但父层有未提交输入时，可隐藏并保留父层状态，关闭子层后恢复。只读详情或可以放弃的视图，直接替换的维护成本更低。
- 子层完成后，父层需要更新受影响的那一项，并保留其他编辑和滚动位置。两层都加遮罩会重复压暗背景，可保留单一清楚的前后关系，或一次只显示一层。

模态与非模态由背景能否操作、焦点与滚动如何限制来决定，抽屉和对话框的外形不能代替这些行为。必须先做决定、存在不可逆操作或背景变化会使当前编辑失效时，宜隔离前后层。本节讨论的非模态辅助面板适合参考、预览和目录等任务。允许与背景交互的前提是面板没有独立的提交或不可逆决定、确实需要对照背景，而且操作背景不会使面板所引用的对象或状态失效。视觉上让背景显得不可用时，实际行为也应相符。

## 返回到哪里

一般约定是取消最近进入的子任务，回到原触发位置，恢复父层焦点、草稿和滚动。任务整体完成后，可以一次退出多个层级并显示最终结果。产品若让面板进入浏览历史，应使浏览器返回与其表示的层级一致。不能把关闭子菜单直接实现成退出整个页面。层内从父内容转到子内容时，标题、返回入口及适度的空间变化能说明父内容仍可恢复。只有透明度变化，无法单独说明数据会不会保留。[关闭行为与编辑恢复](../关闭行为与编辑恢复/README.md)
